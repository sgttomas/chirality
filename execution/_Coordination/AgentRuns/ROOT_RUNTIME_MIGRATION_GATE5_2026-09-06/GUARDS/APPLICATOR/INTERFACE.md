# Applicator interface

CLI: `python3 tools/scaffolding/apply_root_retirement.py --subject-manifest SUBJECT.json --effect-record EFFECT.json --evidence-dir NEW_DIRECTORY (--dry-run | --apply)`.

SUBJECT JSON schema `root-retirement-application/v1` requires `governance_state: {path,sha256}`, `tested_files: [{path,sha256}]`, `fixture_suites: [{path,sha256}]`. Root is the actual script checkout. Tested files must include the applicator, own test, shared state module, all five guard implementations, four _harness YAMLs and governance state. Suites must include all five `tools/validation/test_validate_*.py` guard suites plus `test_root_governance_state.py` and `test_apply_root_retirement.py`; all suites must appear identically in tested_files. Extra pinned test suites can be supplied. Every suite executes freshly, then actual G0-G4 check(scratch_root) runs on full prospective postimages.

EFFECT JSON schema `root-retirement-execution/v1` requires `subject_sha256` of the exact SUBJECT bytes and `owner_act` equal to state.gate4. The published owner act binds Gate4 plan digest, not a future generated JSON digest. Shared loader independently derives approved statuses/successors from accepted Gate3/Gate4 records. No Gate5 acceptance input is required for execution.

Prepared governance state declares transaction `{path: <NEW_DIRECTORY>/journal.json, sha256: null}`. This fixed path serializes application via exclusive directory creation. Read-only dry-run uses a different new evidence directory. Apply writes the declared journal; live config is not changed by this tool. Journal states are PREPARED/APPLYING/APPLIED/ROLLING_BACK/ROLLED_BACK/BLOCKED_PARTIAL. G3 must refuse dispatch for pending/blocked/missing journal (and independently require effective owner state). Structural guards inspect without demanding completed transaction. Final immutable applied state may pin a completed journal separately.

An exact already-applied rerun must have all53 approved postimages and an APPLIED journal for the same subject digest, and reruns all checks without rewriting statuses. Any mixed state refuses. Python exceptions and KeyboardInterrupt trigger guarded rollback, restoring only still-matching own postimages; concurrent edits survive and are identified in BLOCKED_PARTIAL. Hard process termination/power loss leaves a durable incomplete journal and preserved preimages for explicit recovery; the CLI deliberately refuses automatic mixed-state completion. No force, pointer or Git mutation exists.

Snapshot copies only tracked files, exact Gate4 pending write targets/guard inventory, and explicit subject/state path references. It does not scan/copy arbitrary untracked or ignored runtime/account state. Read-only Git metadata reference permits verifying published owner evidence inside scratch.

Boundary tightening: subject/effect top-level keys are exact; reference objects only path/sha256. Extra pins are limited to guard implementation source paths. Evidence directories are canonically contained in approved application/current migration run roots; symlink ancestors refuse. Prospective config governance_state references are discovered only from the four reviewed YAMLs. No recursive arbitrary dict-path gathering is performed.
