## 2. Independent orientation

The three products form a defensible but incompletely closed authority stack:

1. Chirality Root owns normative doctrine, the generic agent runtime and shared provider-neutral contracts, the agent/tool method, and cross-project governance constraints.
2. Chirality App is a product-specific client and work surface. It owns presentation, App integration, compatibility behavior, and App acceptance evidence; it does not own generic runtime semantics.
3. PEC is an optional projection and ephemeral-presence product over file-native governed truth. It does not become the system of record and its absence must not block governed work.
4. Domain engines retain situated professional truth, protected paths, deterministic acts, and human gates. Root runtime transport, App presentation, and PEC projection do not inherit that authority.
5. Git and governed files preserve identity and evidence. They do not perform human acceptance, reliance, issuance, or release judgment.

That orientation emerged from the accepted product instruments before the charter’s architectural propositions were used as challenge questions. It is broadly coherent in the accepted PRDs and later rulings. The largest vertical defect is implementation ownership: D-GOV-20 assigns a substantial shared-runtime surface to Root, but the accepted Root decomposition does not assign that surface to a concrete deliverable. The largest downstream conflict is App’s amended decomposition statement that App retains “semantic ownership” after the Root rehome. The ruling chain instead leaves App with client/integration semantics and Root with generic runtime semantics.
