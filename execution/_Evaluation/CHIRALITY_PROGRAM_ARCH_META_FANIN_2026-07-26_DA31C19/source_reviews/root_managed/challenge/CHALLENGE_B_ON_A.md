## Part 4 — Genuine disagreements (stated without softening)

**D-1 — Duplicate semantic ownership of the shared runtime. (B-001 vs A §4 "Duplicate-ownership check")**
Report A states: "**No shared function has two claimed semantic owners at the freeze.**" I assert the opposite and evidence it: the accepted App decomposition, §13 Downstream Execution Notes, **line 611**, reads *"Root `runtime/` ownership is an implementation-location change; app-dev deliverables retain semantic ownership and acceptance evidence through the SCA-APP-003 impact map."* That is an accepted instrument claiming semantic ownership of the shared runtime, against D-GOV-20 item 1 ("root-owned"), D-T0-23 item 2 ("shared infrastructure"), `AGENTS.md` §Shared Runtime Doctrine, and the App PRD's own second §17 ("root-owned product subsystem rather than a frontend-owned singleton"). The string does not appear anywhere in Report A; A's boundary matrix assigns the runtime's semantic owner to Root without registering the counter-claim. This is my only BLOCK, and it is a factual disagreement about what the corpus contains, not a difference of emphasis. **It should not be fanned in as agreement.**

**D-2 — Whether the absence of a Root runtime-conformance owner is a finding. (B-002 vs A-026 / A §7.4)**
A explicitly declines to make it a finding: O-2 is a boundary commitment the forward register covers via DEL-02-02, so A records "an observation about coverage granularity, **not** a conformance finding", reasoning that the charter's stronger reading would create scope. I filed B-002 as a REVIEW-severity ownership gap. The underlying facts are not in dispute — we independently reached the same measurement, and I likewise routed the remedy as a **PRD amendment, not decomposition repair**, on the same "a review may not create scope" ground. The disagreement is therefore narrow but real: whether an accepted ruling (D-GOV-20) with ten architectural items and named implementation gates, having no owning deliverable anywhere in the accepted decomposition, is a *finding* or an *observation*. I hold that D-GOV-20's substance makes it a finding; A holds that O-2's coverage makes it an observation.

**D-3 — Severity of App's inability to detect Root doctrine drift. (B-006 REVIEW vs A-020 WARN)**
Same verified fact, reached independently: App's `AUTHORITY_CORPUS.json` resolves `docs/SPEC.md` / `docs/CONTRACT.md` to App-local copies, so its corpus-drift check structurally cannot detect changes to Root's same-named documents. I rate it REVIEW and locate the finding in the *missing detection channel*: the `AGENTS.md` rule presents notices as redundancy over each loop's own deterministic checks, and for this class that redundancy does not exist, leaving a single channel that B-007/A-027 both show is used inconsistently. Not a factual conflict; a genuine difference in consequence assessment.

**D-4 — Reach of the ResponsibleParty contradiction. (B-014 vs A-006)**
No conflict in direction, but our numbers differ and both are checkable: A asserts 91 contradicting surfaces; A's own itemisation and my recount both sum to **82** (45 `_CONTEXT` footers + 34 SOWs + 3 decomposition passages).
