## Findings

### 1. Architecture ownership is coherent

The current accepted instruments support one clear division:

- Root owns generic runtime semantics and stewardship.
- App is a current client with accepted client/conformance work and concrete
  static composition against Root runtime packages.
- PEC v2 has accepted prospective client capabilities but no implementation or
  activated client work; the v0.4 tree is frozen reference.
- Piping is positively a non-client. Its App-era mechanism is historical,
  current reliance is retired, and its unresolved successor remains held
  without creating a runtime-client obligation.

That is stronger than an absence-based architecture claim, but it remains a
paper-and-static-composition conclusion—not proof of running behavior.

### 2. The D-8 assessment is provisional

Current D-8 still requires CHANGE-managed, human-gated PRs and says never
self-merge. Valid owner delegation is accepted as a premise, but it does not
collapse semantic approval, approved source SHA, merge authorization, and
effective merge identity.

The future candidate should:

- define `authoring actor`, `merge executor`, and `self-merge`;
- distinguish delegated execution by a separate CHANGE actor from same-actor
  author-and-merge;
- state Root-only versus shared scope, duration, and expiry;
- preserve K-AUTH-2/K-MERGE-1 checks;
- inventory the closed July 28 acts it addresses;
- use disclosed exception or exact-state ratification language without
  claiming retroactive procedural cure;
- propagate through the PRD/decomposition/ScopeOfWork/procedure chain selected
  by the adopted candidate.

These are candidate feedback requirements. They are not adopted amendments.

### 3. Named next-work boundaries matter

- DEL-02-06's activation-time affected-client census remains necessary before
  a consequential Root runtime change. This horizon scan cannot replace it.
- The comparison HTML revision must preserve the exact App/PEC/Piping lifecycle

The older App PRD product-owned runtime wording should also be reconciled before
a future App runtime tranche relies on it, but no presently authorized tranche

  a runtime-client hold;
