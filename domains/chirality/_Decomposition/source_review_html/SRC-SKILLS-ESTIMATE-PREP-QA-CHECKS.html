SEC-SK082-0006 CSV schema integrity (SCAFFOLD only)

| # | Check | Requirement | |---|---|---| | S5a | Column names + order | Every generated CSV matches the canonical schema family (or the canonical file discovered via `AUTO_FROM_CANONICAL`) exactly — no invented columns | | S5b | Key fields non-empty | No empty `ItemID`, `ParameterID`, `RoleID`, `TradeID`, or `DeliverableID` values | | S5c | Recommended within range | For files with min/max/recommended columns, `RecommendedRate` (or `RecommendedPrice` / `RecommendedPercent`) MUST fall within `[Min, Max]` unless `Notes` provides explicit justification | | S5d | No column additions | No columns may be added beyond what the canonical schema specifies |

SEC-SK082-0007 Provenance tracking (SCAFFOLD only; schema-family-aware)

| # | Check | Requirement | |---|---|---| | S6a | Rate/pricing files (Families 1-7) | Every row has non-empty `Basis` (canonical enum or ENRICH addition) and non-empty `Confidence` (`HIGH`, `MEDIUM`, `LOW`, `N/A`) | | S6b | Project parameters (Family 8) | Every row has non-empty `Source` (canonical enum) and non-empty `Confidence` | | S6c | Level of effort (Family 9) | Every row has non-empty `Basis`. **No `Confidence` column exists; do not require or generate one** | | S6d | Parametric defaults | Parametric values carry `Confidence=MEDIUM` or `LOW` with `Basis=PARAMETRIC`, never `HIGH` | | S6e | `HIGH` confidence discipline | `HIGH` confidence values are traceable to a vendor quote, human confirmation, or source document — not to parametric defaults |

SEC-SK082-0012 Conflict surfacing (both phases)

- Conflicts MUST be surfaced in `Conflicts.csv`, not silently resolved. - Conflict triggers: - Two or more human sources disagree for the same key - Canonical schema discovery fails / mismatches - Required inputs imply contradictory interpretations - Dependency cycles (BOE only) - `Conflicts.csv` columns: `ConflictID`, `Key`, `Description`, `Contenders`, `ProposedAuthority` (optional PROPOSAL), `HumanRuling` (TBD until decided), `Notes`. - `HumanRuling` remains `TBD` in every generated row — the skill does not fill this field.

SEC-SK082-0013 Human decision rights (both phases)

The skill MUST NOT unilaterally decide any of the following. If any arise, flag them and halt the relevant step:

- Accept or issue the BOE strategy / publish to canonical locations - Resolve conflicts between disagreeing sources - Approve overrides that would change a `HIGH`-confidence value - Make scope boundary decisions (in/out; base vs option vs alternate) - Execute any irreversible publication action (git commit/push; copy into `_PriceSources/`)

Any such decisions surfaced during a run are recorded as proposals in the relevant log (`Decision_Log.md`, `Conflicts.csv`) with `HumanRuling=TBD`.

SEC-SK082-0014 Failure reporting

| Status | Condition | |---|---| | `FAILED_INPUTS` | `PHASE` missing/invalid, required inputs missing, required inputs malformed, or single-run-spans-both-phases detected | | `WARNINGS` | Run completed with surfaced conflicts, low-confidence items requiring attention, partial coverage, or schema discovery warnings | | `OK` | Run completed with no warnings, no conflicts, and all required artifacts present |

`QA_Report.md` MUST declare exactly one `RUN_STATUS` value.

SEC-SK082-0015 Success case — SCAFFOLD

A clean SCAFFOLD run reports:

- `RUN_STATUS=OK` - Snapshot folder path - Pricing files generated (file count + row counts) - Confidence distribution summary - BOE scaffold file path - `Publish_Manifest.md` present - No conflicts, no overrides requiring human ruling (or explicit statement of none)

SEC-SK082-0016 Success case — BOE

A clean BOE run reports:

- `RUN_STATUS=OK` - Snapshot folder path - Deliverable count + tier distribution - Cycle detection result (none, or listed) - `BASIS_OF_ESTIMATE.md` path - `Publish_Manifest.md` present - Human modifications between scaffold snapshots logged in `Decision_Log.md`
