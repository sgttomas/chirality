Root's prospective App profile now limits ordinary skill context to the
reviewed bundled skill library. Project and user skill origins remain available
only for standalone compatibility and read-only historical replay; their files
never make them eligible for a new ordinary App turn. Continuation requires an
explicit drop or change and never silently rebinds the old selection. Project,
user, and bundled workflow discovery remains. Users
create, save, or revise canonical `WORKFLOW.md` packages through chat,
authorized file tools, validation, and catalog refresh. No separate workflow
editor is part of the MVP. Codex is the sole App MVP engine qualification and
release target.

The affected App surfaces are the project instruction overlay, Runtime method
catalog/context/replay behavior, the packaged instruction-root mirror produced
by `frontend/scripts/prepare-packaged-instruction-root.mjs`, and its integrity
fixtures. The current App authority corpus v21 does not include Root `AGENTS.md`
or `docs/AGENT_WORKFLOW_RUNTIME.md` as hashed members, so this notice does not
create corpus drift or authorize a v22 bump. The v21 preparation packet did cite
the Runtime contract as a source identity; that citation is derivative evidence
and must not be treated as an accepted pin.

This notice communicates an authorized Root candidate. It does not amend the
App decomposition or product documents, adopt or repin an App corpus, qualify
Runtime behavior, modify packaged bytes, or release the App. The App owning loop
must reconcile its older multi-engine and project/user-skill requirements under
its own instruments, implement and verify the policy, then record any adoption.

Source CI follow-on: the same Codex-only tranche updates
`.github/workflows/harness-premerge.yml` to use an isolated controlled Runtime
entry for real Next/daemon/CLI integration checks. Obsolete Pi production-policy
and Claude package-fixture assumptions are removed. Controlled outputs remain
outside the shipping graph; this preserves source integration coverage without
representing stub execution as Codex account, native Plan, or package
qualification. Existing accepted supplier and release obligations remain.
