# Existing controller evidence limit — additive proposal clarification

Status: PROPOSAL_ONLY, HELD. This addendum narrows the interpretation of PROPOSAL.md's existing-controller clause without changing the candidate _STATUS.md postimage or introducing new scope.

`RuntimeSettings` currently invokes `bridge.daemon.status/start/stop` for the Chirality runtime daemon and `bridge.models.status` for residency. These facts do not by themselves prove the external oMLX server is running, and daemon start/stop must not be presented as direct oMLX server start/stop. The implementation must use the existing observations at their actual strength. If the existing bridge lacks a local-model-server observation, the Local model row says unknown/unavailable with an accurate explanation; it must not infer a green server dot from `daemon.running`, cached loaded-model data, API reachability, or a fake account fixture. Any existing runtime action shown must retain its actual daemon target in accessible text/help and preserve its existing confirmation/busy behavior.

The reference's local-server switch is an imperfect map where existing actions cannot supply its literal semantics. V3-05 still owes useful truthful presentation within its unchanged boundary. Missing service-specific observation/control, if confirmed during implementation, is an explicitly recorded product gap for its actual owner; neither this amendment nor the mock permits adding a bridge method, server-control endpoint or runtime process authority. Existing native runtime controls remain usable and correctly named. This clarification applies the accepted no-invention/port-unchanged rules, changes no product acceptance criterion, and does not waive Q7 or mark the local-model-server experience complete.
