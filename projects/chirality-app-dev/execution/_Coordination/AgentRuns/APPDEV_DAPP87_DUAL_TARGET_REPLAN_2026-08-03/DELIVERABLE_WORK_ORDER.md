## Domain-first governed work order

1. **Owner architecture gate (this proposal).** Select A/B/C, authorize a
   bounded comparison proof, or defer.
2. **First-domain requirements packet.** App translates accepted Piping inputs
   into exact typed-agent, information, workflow, decision-gate, identity, and
   unavailable/stale state requirements; Piping reciprocally confirms source
   ownership through coordination.
3. **App PRD gate.** Adopt exact two-target product requirements and
   standalone/domain acceptance boundaries.
4. **SCOPE_CHANGE gates.** Exhaustively classify the deliverables above and
   apply only owner-approved amendments; prefer no topology addition unless
   coverage proves otherwise.
5. **Packaging-identity gate.** Rule bundle/product/executable names, target
   profiles/resources, data/session coexistence, and unsigned local outputs.
6. **Root contract gate.** Wait for named Root/Piping triggers, then adopt only
   the ruled generic contract/version/identity/resume/sandbox/Bash semantics
   needed by App clients.
7. **WORKING_ITEMS activation.** Execute the smallest domain-first vertical
   slice under the selected deliverables and a sealed two-target matrix.
8. **Two-target evidence and owner acceptance.** Common evidence plus separate
   standalone/domain UI, package, and runtime-client proof; no release effect.
9. **Release posture.** Signing, notarization, publication, distribution,
   update channel, and professional reliance remain later decisions.
