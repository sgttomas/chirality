## Contained directory and file read strategy

GET-only route accepts current `projectRoot` and optional one-basename `.md` filename. Reject empty/absolute/traversal/separator/control-character targets, duplicate conflicting parameters and extra nesting. Call existing `assertProjectRootAccessible` and instruction-root resolution; current root is canonicalized before store entry. Return canonical root in every success payload; renderer request generation plus root key prevents stale completion from rendering after root change.

Store boundary is exactly canonical root + `/.chirality/workflows`. Require `.chirality` and `workflows` to be real directories, not symlinks, and verify canonical identity/containment. Missing directory is a truthful empty state; permission errors and non-directory components are distinct failures, not empty results. Do not recurse or create any directory.

Enumeration is candidate discovery only. Node path-based `readdir` plus later path identity checks is NOT descriptor binding. Never expose raw enumerated names, ignored filenames, per-entry exceptions, raw filesystem error paths, or raw counts from candidates. For each candidate independently open the exact `.chirality/workflows/<basename>` with unchanged `openDocument`, verify its canonical path is the exact allowed directory plus basename, verify no symlink components, and verify parent/root identity around open and content read. Only successful contained regular descriptors may produce a named list entry. If any candidate fails containment/race validation, fail the whole scan with a generic retry message rather than a filename/error row. This prevents a transient escaped enumeration from leaking outside filenames. Cap scan candidates (proposed 500) and do not expose unvalidated overflow names/counts; a generic bounded-scan warning is sufficient. The scan is a point-in-time set of independently validated files, not an atomic directory snapshot. Do not claim stronger atomic/no-race guarantees than existing portable descriptor policy supports.

Use `openDocument` unchanged (`file-policy.ts:59`) for all content reads, preserving its before/after inode checks and O_NOFOLLOW/O_NONBLOCK open. Require regular file; reuse TEXT_LIMIT; bounded descriptor read catches growth/truncation and compare dev/inode/size/mtime/ctime after read. Close handles in finally including parse/limit/UTF-8 failures. Decode UTF-8 strictly and refuse NUL/binary. List should read metadata only for the raw subset, with content SHA computed on opened detail bytes; no unbounded read per list item. No entry may be cached across a folder change. Root mismatch in the bound chat disables this view just as Files does.
