# Candidate trusted response finalizer and proof contract

Status: HELD candidate design, not implemented or native-proven. Basis: INPUT_IDENTITIES.json and D-APP-121 revision 2. This chooses a concrete implementation direction for review; technical feasibility of Chromium's built-in viewer under the closed policy remains unproven. No endpoint policy exemption is recommended.

## Mechanism

1. `renderer-window-policy.ts` owns policy bytes and the finalizer. Packaged HTML retains one fresh nonce, generated before Next handling and inserted byte-identically in Next's request and final HTML response. The actual server-bound origin, never request Host, supplies the narrowly scoped frame source on the four known shell HTML routes only: `<renderer-origin>/api/working-root/file`. Other resources retain closed frame/ancestry policy.
2. Packaged `main.ts` overwrites/removes any incoming private eligibility-challenge header, creates a random per-request 256-bit challenge for exact eligible-shape GET requests, and retains it in the response closure. It installs the central finalizer around the response's actual `writeHead` boundary before calling Next. Every explicit/implicit header commit, including `write`, `end` and `flushHeaders`, must go through the finalizer. Merge any `writeHead` header arguments first, then remove all case variants of private attestation/CSP headers and set one authoritative policy. Unit tests must cover Node overloads, array headers, implicit writes, errors and repeat commits; failure denies or aborts before headers. Do not buffer PDF bodies to finalize headers.
3. The file endpoint revalidates exact GET/path/selectors, Working Root and descriptor identity. For `content=pdf`, permit exactly `projectRoot`, `content`, and either `path` or `target`, each once; reject both target aliases even when equal, all duplicates and unknown keys. Require `.pdf`, a non-empty file and descriptor-read initial `%PDF-` bytes (five-byte eligibility screen only). Perform descriptor checks before creating the successful stream. It emits a private response attestation equal to the internal challenge ONLY after validation; it never emits CSP. Untrusted query/header values do not directly select a policy. No challenge yields no framing attestation. The challenge is not a user credential and is not persisted or logged.
4. The central finalizer requires closure-held challenge equality, exact request shape/origin/path, successful status 200, no Location, MIME application/pdf, inline disposition, nosniff and no-store. Only then replace the ordinary deny policy with the exact D121 closed PDF policy (`default-src 'none'; script-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'`). The private attestation is stripped before transmission. Metadata/errors/redirects/mismatches stay unframeable. Signature/validation results travel as a server-owned route attestation, not a caller-supplied assertion. The trust boundary includes the application's own route implementation; arbitrary compromised server code is not mitigated by this attestation.
5. Development Electron uses the same classifier/finalizer at its session request/response boundary: overwrite private challenge headers in `onBeforeSendHeaders`, retain challenge by request ID plus origin/path/method, consume once in `onHeadersReceived`, and clear on completion/error/redirect. Apply canonical development CSP to own-origin responses even if a CSP already exists; never infer authorization from a preexisting CSP. Strip private response fields. Ordinary standalone Next/browser access stays unproven and cannot authorize the desktop capability. Reuse the single session hook ownership; do not install competing hooks per window or replace the existing egress handler. Extending the policy's local type interfaces is within its exact file boundary.
6. Add actual subframe navigation/request guards: initial destination and every redirect must retain exact permitted origin/path and valid PDF selector shape; reject all redirects for this endpoint. Existing top-level `will-navigate` / `will-redirect` handlers alone are not evidence of subframe containment. Integrate with existing `onBeforeRequest` egress ownership, not a second listener that replaces it. Electron built-in internal viewer resource needs must be observed in native proof. Do not permit chrome-extension, blob, data, file, object, additional network destinations or arbitrary frames to rescue a failed render.
7. Keep existing chunked descriptor reads and no PDF size cap. Initial implementation deliberately ignores Range and answers 200 with the full bounded-memory stream; it does not advertise byte-range support. Prove the native viewer accepts that behavior using a multi-page large PDF, memory/chunk observations and actual page navigation. Re-stat before/after chunks and at completion; abort on detected size/mtime/ctime/identity change or truncation, close on cancellation and failure. Descriptor binding prevents path substitution but does not make in-place writes atomic: mutation can occur after a check or after bytes have been delivered. Record the detailed atomicity limitation in evidence; the UI shows an actionable changed/unavailable-document error and reload/default-app controls when a failure is detected, without internal-control jargon. Do not claim coherent immutable snapshots or retroactive status changes after streaming starts. If accepted controls require immutable delivery, return a new storage/snapshot candidate rather than silently buffering the entire file or adding a cap.
8. Only enable `inlinePdfPreview` after a frozen candidate achieves actual packaged native proof. Proof may use a test-only launch mode on candidate bytes, but final published bytes must be retested with capability enabled. Error/default-app handoff remains reachable; PDF embed failure cannot be inferred reliably from iframe load alone, so evidence must exercise actual native failure and explicit fallback controls.

## Scope fit and feasibility limits

The design can be expressed inside the 12 D121 files: policy/main own injection/finalization/native instrumentation; route/file-policy own eligibility; existing tests/pins/proof own validation; viewer/preload own truthful capability. No new shared module, dependency, HMAC secret, environment credential, IPC or Root interface is required. The internal header protocol literals must be pinned across separately bundled Electron and Next modules; do not assume a shared JS singleton or AsyncLocalStorage crosses Next's module boundary.

This is static design feasibility, not validated implementation feasibility. Native closed-policy support, supported Electron subframe interception, Node finalization coverage and Next forwarding of private headers remain mandatory experimental findings before a product completion claim. If any requires another path/control exception, return its exact amendment. Signature-prefixed malformed/polyglot content may pass the eligibility screen; browser sandbox/network denial and truthful errors remain essential. Same-origin ancestor trust is intentionally coarser than a particular parent route and must be accepted explicitly under D121.

## Required proof matrix

| Surface | Required evidence / fail condition |
|---|---|
| Native positive | Unsigned packaged Electron (actual `app.isPackaged=true`), known local multi-page PDF visibly readable in right panel, next/previous page navigation, exact package/source/fixture hashes and versions. Browser display, HTTP 200 or iframe load alone fail. |
| Framing negative | Foreign origin, wrong port/scheme, arbitrary same-origin path, encoded path, redirect, ordinary HTML on all four operator routes, JSON/metadata/error/image/Office/mislabeled data remain unframeable. |
| Eligibility negative | Duplicate content/root/path, both aliases, unknown key, non-GET, absent/wrong signature, zero bytes, traversal/encoded traversal, instruction/.git access, symlink escape, nonregular/unreadable input, stale descriptor all rejected. |
| Attestation negative | Caller-spoofed request/response fields, missing/mismatched/replayed token, wrong request ID, wrong status/MIME, Location, duplicate/mixed-case CSP, preexisting permissive CSP and redirect reuse fail closed. Tokens removed from responses/logs. |
| Existing controls | Four-route nonce uniqueness and request/response equality; no packaged unsafe script allowance; contextIsolation/sandbox/no Node, child-window denial, sender authorization, navigation/egress and secret-free output retained. |
| PDF behavior | Large uncapped file with bounded chunks, Range request answered truthfully 200/full data, cancellation, truncation, in-place mutation, corrupt/polyglot content and internal-resource attempts observed. No silent successful truncation or unsupported promise of atomicity. |
| Proof fail-closed | Missing native/page/negative/policy evidence, synthetic spoof records, malformed payload, overbroad frame-src/ancestry or skipped required controls make summarizer fail. |

Reuse the registered frontend/typecheck/build/premerge, D-APP-36 and security command surfaces after fresh whole-diff review. Pin changes must positively assert the exact exception AND retained denial cases; deleting blanket frame assertions is insufficient. Retain commands/cwd/effective non-secret environment, tool versions, exits/stdout/stderr, actual images/process observations, cleanup and sorted recomputable manifests. The new frontend mutation prospectively triggers A1; prior proof stays historical.
