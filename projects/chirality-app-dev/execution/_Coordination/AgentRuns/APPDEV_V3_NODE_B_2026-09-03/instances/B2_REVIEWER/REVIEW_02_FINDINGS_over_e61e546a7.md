### MINOR-1 — `$DMG` names two different artifacts, and step 3.F.4 overwrites the G6a-ruled unsigned candidate DMG in place
- **Where:** `DEL/Release_Runbook_CANDIDATE_2026-09-03.md:61` (`$DMG` = `frontend/dist/Chirality-3.0.0-rc.1-arm64.dmg`), `:75` (§3.B evidence `shasum -a 256 $DMG …` on the **unsigned** candidate), `:138` (guard (iii): 3.F.4 must produce `Chirality-3.0.0-rc.1-arm64.dmg`, which electron-builder writes to `dist/` — the same path), `:139-140,:157-161` (`$DMG` = the **signed** DMG); checklist `DEL/Exact_Candidate_Identity_and_Custody_Checklist_CANDIDATE.md:31` (A13 unsigned DMG SHA-256, named by the G6a ruling per P1 `:33`) vs `:36` (A17 signed DMG).
- **What/why:** `desktop:dist` (§3.B) and the `--prepackaged` step (§3.F.4) both emit `dist/Chirality-3.0.0-rc.1-arm64.dmg` (`dmg.js:23-24`; `build.directories.output` = `dist`). Executing 3.F.4 as written therefore replaces the bytes whose digest the G6a ruling names (A13) with the new unsigned-container-around-stapled-app DMG, before that DMG is signed. The ruling artifact is then gone from disk and can only be re-derived by a rebuild, which §2 forbids. The single `$DMG` variable also makes §3.B and §3.G refer to different bytes under the same name. Not a shipping defect (A13 is recorded by digest and the signed lane does not depend on the unsigned DMG bytes after G6a), but an evidence-preservation gap in a procedure whose purpose is exact-byte custody.
- **Fix:** Introduce `$DMG_UNSIGNED` (= the §3.B/A13 artifact) in the conventions line `:61` and use it in `:75`; add to §3.F.4, before the command: "Archive the ruled unsigned candidate first: `mkdir -p "$EVID/unsigned" && cp "$DMG_UNSIGNED" "$EVID/unsigned/" && shasum -a 256 "$EVID/unsigned/$(basename "$DMG_UNSIGNED")"` must equal A13; the `--prepackaged` step writes to the same `dist/` path and would otherwise overwrite it." Keep `$DMG` for the signed artifact only. Mirror the two-name distinction in checklist rows A13/A17 ("`$DMG_UNSIGNED` … archived under `$EVID/unsigned/`" / "`$DMG`").
