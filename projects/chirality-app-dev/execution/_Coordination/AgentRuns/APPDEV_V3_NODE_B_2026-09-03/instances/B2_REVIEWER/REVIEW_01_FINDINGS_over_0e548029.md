## Findings (most severe first)

### MAJOR-1 — Runbook §3.K download backcheck is self-contradictory: `curl` does not quarantine, but step 3 requires the quarantine attribute
- **Where:** `DEL/Release_Runbook_CANDIDATE_2026-09-03.md:199` (step 3.K.1 `curl -L -o ~/Downloads/... "<browser-download URL ...>"`) and `:201` (step 3.K.3 "Gatekeeper assessment on the quarantined download is the real test: `xattr -p com.apple.quarantine` present").
- **What/why:** `curl` writes the file without the `com.apple.quarantine` extended attribute (only LaunchServices-aware downloaders — Safari/Chrome/Finder/Mail — set it). Following the runbook as written, step 3 either fails on a correct artifact (a false stop) or is skipped, in which case `spctl --assess` on an unquarantined file does not exercise the Gatekeeper first-launch path that AT-042 ("downloaded GitHub asset ... launches") is meant to prove. The plan's G8 row requires the public-path download to be reverified for Gatekeeper; the procedure must actually produce a quarantined file.
- **Fix:** Replace step 3.K.1 with a browser download through the release page (the "user-visible path" the plan §12.2 names), *or* keep `curl` and add an explicit quarantine step before 3.K.3 (`xattr -w com.apple.quarantine "0083;$(printf '%x' $(date +%s));Safari;" <dmg>` recorded verbatim as a simulated quarantine, with the source noted as simulated). In both cases record `xattr -p com.apple.quarantine` output before `spctl` and state which route was used.

### MAJOR-2 — Runbook §3.F.4 "build the DMG around the stapled app" names no byte-preserving command; the only packaging command in the runbook (`desktop:dist`, §3.B) rebuilds from source and violates the G6a no-rebuild rule
- **Where:** `DEL/Release_Runbook_CANDIDATE_2026-09-03.md:134` ("Build the DMG around the stapled app (the same electron-builder DMG target, from the same frozen configuration, with the stapled `$APP` as input — no source rebuild)") vs `:75` (`CSC_IDENTITY_AUTO_DISCOVERY=false npm run desktop:dist`) and `:111` (layer 4 "after ... the DMG was rebuilt around the stapled app").
- **What/why:** `FE/package.json` `desktop:dist` = `npm run build && ... electron-builder --mac dmg --arm64 --publish never ...` — it runs `next build` + the Electron bundle and re-packages a *new* unsigned `Chirality.app`, discarding the signed/stapled app. That is exactly the "rebuild after final acceptance" the plan §12.2 bullet 4 and the runbook's own §2 bullet 3 forbid, and it would make §3.G's mounted-vs-staged digest comparison fail (or, worse, ship an unsigned app inside a signed DMG if the comparison were skipped). The runbook's intent is right; the executable step is missing, and the one named command does the wrong thing.
- **Fix:** Name the exact command and its guard: e.g. `CSC_IDENTITY_AUTO_DISCOVERY=false npx electron-builder --mac dmg --arm64 --publish never --prepackaged dist/mac-arm64 -c.mac.identity=null` (the `prepackaged` option exists in app-builder-lib 26.15.3, `node_modules/app-builder-lib/out/index.js:40`), state that this step must not re-sign or touch `$APP`, and require in §3.F.4 itself (not only §3.G) that `shasum -a 256` of the mounted `Chirality.app/Contents/MacOS/Chirality` equals A18 before layer-4 DMG signing. Alternatively adopt Apple's simpler flow (sign app → create DMG → sign DMG → notarize DMG → staple DMG; app inside covered by the DMG ticket) and drop the app-zip submission — either is acceptable, but the chosen one must be executable from the text.
