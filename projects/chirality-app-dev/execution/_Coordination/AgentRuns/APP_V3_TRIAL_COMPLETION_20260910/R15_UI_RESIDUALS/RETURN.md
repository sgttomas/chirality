## 1. Joined commentary/final text — confirmed source projection defect

`projects/chirality-runtime/packages/daemon/src/codex-session.ts:581` builds terminal output from distinct native message items with `.join("")`. Lines585–591 and618–627 track native item IDs internally but emit text events without the ID. `CodexSessionEvent` line50 has no text item identity. `codex-supervisor.ts:471`, `core/src/delegated-engine-adapter.ts:184`, and `core/src/turn-coordinator.ts:260` forward/persist only text. Live `chat-panel.tsx:888` appends chunks directly; replay `contracts/src/harness/transcript-replay.ts:298–301` groups all assistant deltas by turn and concatenates them. Thus distinct commentary/final items predictably become `itself.I’ve...`; CSS/Markdown cannot recover the lost boundary. Ordinary deltas within a single item must still concatenate without separators.

Recommendation: preserve native item identity in a typed progress projection, introduce a paragraph boundary only between distinct nonempty assistant items, and use identical ordered assembly for streamed text, terminal output and replay. Minimum bounded repair may emit an explicit separator on the first text of a new nonempty item and join terminal items with the same separator, but must handle completed-only messages, empty started items, duplicate completions, interleaved items, interruption and bounded buffers; preserving identity is safer. Do not insert spaces on every chunk or guess boundaries from punctuation. No need to invent commentary/final attribution when the transport does not expose it.

Checks for repair tranche: two items with split deltas plus terminal completion; completed-only items; one word split across deltas; empty items; interrupted partial turn; identical live/completed/replay text. Existing codex-session / codex-primary-chat-integration and transcript tests are the appropriate seams.

## 2. Sidebar title remains bootstrap — confirmed classification plus sticky-cache defect

`core/src/runtime-service.ts:318` records a boot accepted turn with `{ message: input.message, boot: true }`, where input.message is the reserved bootstrap string (line298). `contracts/src/harness/transcript-replay.ts:251` projects every accepted turn with text as a user message without checking `boot`. `frontend/src/lib/woven-dialogue/chat-organization.ts:277–282` selects the first nonempty projected user message. `woven-dialogue-shell.tsx:261–267` saves that derived title into `chatTitles` once and refuses to update any existing key. Therefore a boot record becomes the first operator prompt and the stored title stays bootstrap after real turns. Data is present but misclassified; no generated title service is needed.

Recommendation: exclude explicitly marked boot events from ordinary user-message/title projection, retaining raw events for inspection. Derive fresh titles from the first actual accepted user prompt. Preserve legitimate user messages whose text happens to be bootstrap—use `boot: true`, not a string blacklist. Separate explicit rename overrides from derived-title cache (or avoid persisting derived titles). Existing `chatTitles` mixes automatic and manual values, including Navigator rename at line208, so do not blindly overwrite old entries equal to bootstrap: a historical manual rename is indistinguishable without provenance. New behavior can be fixed immediately; existing ambiguous saved titles should remain manually renameable or receive a deliberate migration with an explicit provenance rule.

Checks: boot then real user prompt; actual user text bootstrap without boot marker; manual title unchanged; first substantive prompt discovered after initial empty/boot-only load; late/stale replay loads cannot override another folder.
