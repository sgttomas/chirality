## Explicit nonblocking design observations

- Raw endpoint path identity is underspecified relative to the inherited encoded-path negative matrix. State comparisons before/after URL normalization and expected outcomes for encoded dot segments, slashes, backslashes, duplicate separators, query key aliases and fragments. A normalized same endpoint is not evidence of a containment escape, but must not be presented as rejected raw syntax if normalization erases it. Both modes need the same effective eligibility result.
- Installed Electron declarations support will-frame-navigate with event details and will-redirect with details plus deprecated arguments. They expose main-frame distinctions; the current structural adapter omits those details. Candidate correctly permits adapting the same policy locus, but implementation should pin exact event fields and preserve existing main-frame navigation while constraining subframes. This static finding does not prove event coverage or built-in viewer compatibility.
- Postcommit mutation cannot produce a new typed HTTP error; the candidate correctly says abort and close. Live iframe has no dependable PDF failure signal. Retained default-app action is already present, so the candidate's alternative of retaining that fallback is achievable without promising automatic error detection. Require actual malformed/aborted native proof, and do not label an iframe load as decoded success. Same-size restored-mtime writes are expressly outside the detection guarantee; no atomicity claim is made.
- The response marker is acceptable only as the stated trusted-App-server classification, not authentication against a compromised server. Sole-emitter, reflection, duplicate-header, status/MIME/length and selector tests remain mandatory.
- The candidate accurately retains full-T3/T4 consequences, positive native proof, restrictive policies, 12-file boundary, and separate owner release authority. No additional source locus or security relaxation is recommended by this review.
