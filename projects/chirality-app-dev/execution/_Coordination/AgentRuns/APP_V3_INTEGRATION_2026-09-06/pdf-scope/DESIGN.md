## Minimal trust boundary

Use the existing renderer-window-policy.ts as the sole policy-byte owner, imported only by server route and Electron main, never renderer client components. It currently depends only on node:crypto; adding pure server-response constructors there needs no new dependency or file. The file route calls a central helper ONLY after exact request selectors and opened-descriptor PDF eligibility pass. The helper adds a reserved internal response classification, `X-Chirality-Response-Class: eligible-pdf-v1`, and the fixed PDF header tuple. The marker is server-generated classification, not a credential, public request assertion, cryptographic signature, or guarantee of benign PDF parsing.

This explicitly trusts the frozen App server implementation at the exact endpoint; it does not trust arbitrary same-origin endpoints, arbitrary CSP, URL selectors alone, or client metadata. No route may reflect the marker from request headers, and no other production emitter is allowed. Prove sole emitter through source review/pins and spoof/reflection negative tests. If the owner requires authentication against a compromised trusted App server, this design does not meet that different threat model and needs a separate contract; do not silently add a secret protocol.

The central classifier requires exact origin/path `/api/working-root/file`, GET, valid nonduplicate selectors, status 200, exactly one marker, application/pdf, inline disposition, nosniff, no-store, positive Content-Length, and absence of Location/Content-Range. Case-normalize names; reject duplicates/conflicting values and any unexpected CSP for eligible PDF. In packaged mode the expected preinstalled request-nonce CSP is required as the baseline (Next will not copy a route CSP over it); the trusted marker and non-CSP tuple determine PDF eligibility, and the finalizer replaces that known baseline with the central PDF policy. Any route attempt to replace the known baseline before finalization fails closed. In development the central route helper supplies the exact fixed PDF CSP, which the hook validates and replaces with identical central bytes. No equality between nonce HTML CSP and PDF CSP is required or asserted. Any malformed or incomplete tuple receives the closed policy, never an embedding grant. Strip all reserved classification headers before renderer delivery. Request-supplied marker headers are ignored/stripped, never forwarded into a response classification.

## Header-commit order

Packaged: main installs the existing fresh request nonce and HTML CSP before invoking Next. Extend central request-policy installation to interpose once on the response's writeHead commit boundary, including explicit header arguments and implicit flush/write/end calls. Merge pending headers with explicit arguments using Node precedence, inspect final status and trusted tuple, delete every case variant of reserved marker and CSP, then write exactly one centrally generated policy. Non-PDF response keeps the original nonce policy byte-for-byte. It is not possible for route code to replace it by setting CSP. Next errors/redirects/default responses remain closed. Finalization is one-shot; restore original writer during the call, and never rewrite after headersSent.

Installed Next send-response.js copies status and Response headers onto the Node response before pipeToNodeResponse. pipe-readable.js calls flushHeaders before the first body chunk, and bodyless responses use end. Thus the marker can reach the single Node commit boundary without buffering the PDF or patching Next. Unit tests must exercise writeHead headers overloads, flushHeaders, write, end, errors, and late header writes. This is a design supported by inspected code, not an executed integration result.

Development: Next is a separate server process (package scripts); no process-global registry, inherited secret, or request-local storage bridge is assumed. The existing Electron onHeadersReceived installation invokes the same central classifier on the response tuple plus request method/status. Eligible PDF gets the central PDF policy; every other renderer-origin response gets the existing static development policy, replacing arbitrary preexisting CSP instead of treating it as authorization. Only central code constructs the permitted exception. Foreign-origin behavior remains unchanged and egress still decides access. Main must pass method/status through the existing policy adapter; extend its structural types in the same file. Neither mode trusts public query/header flags as proof that a descriptor was validated.

Parent shell HTML has exact-origin-and-path frame-src and frame-ancestors none. PDF has the exact revision2 policy: default-src none; script-src none; frame-src none; object-src none; base-uri none; form-action none; frame-ancestors self. Preserve all quoting as CSP syntax in implementation. The accepted same-origin ancestry granularity is explicit: it cannot restrict the PDF to a particular parent pathname. Non-shell resources remain unframeable. Reject redirects from PDF and enforce subframe navigation/redirect containment through existing central installer (installed Electron will-frame-navigate and will-redirect event details.url/details.isMainFrame; preserve existing main-frame handling, cancel disallowed subframe destinations/redirects, and fail closed on missing classification). Installed onHeadersReceived supplies method/statusCode. Include raw and normalized encoded-path/dot-segment/duplicate-slash negatives in both modes; a normalization route that makes forbidden raw variants indistinguishable must return a precise finding rather than claim rejection. No foreign, blob, data, file, extension, object, webview or wildcard exemption is included.

## Descriptor and streaming behavior

Keep existing project-root access validation, canonical containment, instruction-root/.git exclusion, regular-file and opened-descriptor identity checks. PDF requests require .pdf extension and first five descriptor bytes `%PDF-`, positive observed size, exactly one content=pdf, one projectRoot, and exactly one path OR target; reject unknown/duplicate selectors. Signature is only minimum eligibility screening; malformed/polyglot files may reach Chromium and are mandatory native negative controls.

Choose full-response streaming only for this bounded increment: ignore Range and If-Range per full-response semantics, return 200 for an otherwise eligible request, omit Accept-Ranges and Content-Range. Do not implement partial responses or advertise range support. Large PDFs remain uncapped and streamed in bounded chunks. Chromium suitability with this behavior is a required native finding; if it needs byte ranges, propose the exact successor change rather than silently implement 206.

Read and validate the signature and re-stat the descriptor before constructing the eligible response. Re-check descriptor size/mtime before each bounded read and at completion; truncate/read/change error aborts the stream and closes the handle. Precommit failures produce typed non-PDF JSON with deny ancestry and no marker. A failure after header commitment cannot retract CSP or change status: abort, close descriptor, and record failure; never append an HTML/JSON error body to PDF bytes. Cancel/disconnect closes exactly once. These checks detect observed mutation, not atomic snapshot isolation; same-size restored-mtime concurrent edits cannot be guaranteed absent without a new snapshot/locking design. Native malformed/mutation proof must establish truthful unavailable/retry or the already present default-app fallback (do not claim reliable iframe error detection); iframe load alone is insufficient.
