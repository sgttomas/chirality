## Recommended candidate and alternatives

Recommend **B: versioned closed durable origin plus ephemeral authority state**, subject to owner contract/compatibility approval. An immutable request retains a Runtime-owned origin projection, linked by request digest to decision and settlement. A private lifecycle actor retains current authority; neither persisted history nor origin proof authorizes a later request. No separate durable live-child registry is proposed. After restart all old live capabilities are invalid; history is read only via a separately authorized audit view if selected.

Alternative A keeps current public/persisted schema and validates children privately. It is smaller, but cannot reconstruct exact child provenance after shutdown; select only if owner explicitly accepts that limitation. Alternative C persists a complete live child registry and recovers pending replies. It expands recovery semantics and risks in-flight reattachment; not recommended, requires separately owned scope/contract decisions. The existing primary-only behavior remains the safe implementation baseline until an option is accepted and implemented.

Candidate B fields: immutable origin `{kind, actorId, parentActorId, actorTurnId, parentTurnId, associationId}` containing Runtime opaque IDs; root binding stays `{canonicalRoot,cwd,accountId,accountEpoch,policyDigest,sessionId,turnId,workerGeneration,scopeDigest}`. Private correlation maps typed supplier request ID, thread/turn/item and immutable validated spawn identity to these opaque IDs within one generation. Do not overload requestedBy/scopeDigest. `requestedBy` identifies trusted broker; origin identifies requesting child; `approvedBy` is the accountable responder. API authentication/principal mapping must bind approvedBy to an authenticated actor or a documented trusted single-user identity policy, not arbitrary supplier text. Identity policy is an owner/App decision.

Request projection also freezes normalized available decisions and exact supplier dialect identity. Closed durable record permits decisions only from that list. Request hashing uses a specified deterministic serialization; exact scheme/version is a contract decision (fixtures use canonical sorted-key JSON SHA256). Proposed opaque IDs disclose no credentials, arbitrary command, raw vendor payload or ambient account metadata. Supplier raw correlation remains private and expires with generation. History can explain origin but cannot recreate an active provider capability.

## Current-authority checks and lifecycle

Use one serialized actor/critical section per root worker generation for lifecycle/response admission, with a monotonic authority revision. Asynchronous consent/account checks return to that section and compare revision before reserving a send. At the local send commit no awaited work may occur between final authority check and transport enqueue; retirement and invalidation share this serialization boundary. This prevents a local stale grant; it cannot revoke bytes already sent or prove when a supplier acted.

At **receive**, validate owned transport/generation, root continuity and ask posture; exact typed request identity, destination/item consistency, closed shape and choices; parent still authorized; validated spawn sender/tool/status/parent carrier; exact current child turn started and not terminal/replaced. For deeper descendants require a complete acyclic chain to current primary authority, each with immutable validated spawn provenance and live controlling relationship. No role/capability inheritance is inferred from descent. If protocol cannot establish a link, no prompt is authorized.

At **display**, repeat root/account/policy/consent/current child and parent checks, callback pending state and frozen choice identity; return a revision/digest-bound view. A display token is a comparison/preflight aid, never a grant. App refreshes on focus and before response and disables stale controls. Revocation notifications may lag; server revalidation remains authoritative.

At **respond**, authenticate responder; verify project/root scope, existing preflight/compatibility, request digest, revision, worker generation, child turn and ancestry lifetime; decision exactly advertised and explicitly chosen; unchanged consent for grants. Atomically reserve one response, durably record human intent, recheck after persistence, then enqueue once. Same attributed request/decision retries return recorded state; conflicting actor/decision fails without extra write. Transport callback success means sent only. Resolution, supplier acknowledgement and operation execution are separate facts; do not infer supplier application from request disappearance or turn success.

At **child completion/replacement**, invalidate only that child's active request capabilities and any descendant authority depending on it. Retain provenance and settlement. A parent can remain active only if containment/transport stay sound; do not synthesize a primary turn terminal merely because a child ends. At **parent completion/interruption**, invalidate all dependent descendants before allowing the next primary action. Child membership across later turns does not revive authority: resume/send-input requires newly validated current lifetime linkage and exact source evidence; until specified, fail closed.

At **retire/shutdown**, first revoke admission and increment generation authority revision; settle unsent requests with a Runtime retirement cause, drain or classify in-progress writes, and join the existing retirement coordinator/journal. Do not call store.resolve with provider-resolved for local shutdown. Candidate settlement writer uses a narrow trusted retirement capability for its already-bound request after liveness revocation; public approve/read live gates are not relaxed. Failed persistence leaves reconciliation-required, blocks next action per DEL-02-11, and never forges a decision. Once bytes were enqueued, classify delivery as unknown or sent as observed, never as denied. Audit fact “not sent” is allowed only before any enqueue. Primary conversation/history may persist while its active turn ends; generation retirement can interrupt that primary turn and App must say so. Restart terminalizes old active turn exactly once, then continuity determines thread/resume or fresh thread; no approval replay.

Out-of-order candidate join: retain sanitized untrusted evidence privately until exact association plus child-start evidence arrives. No public prompt, user decision, or grant before full join. Proposed parameters for owner review: 2-second monotonic expiry, 32 waiting joins, 128 total requests, 64 child associations, 8 ancestry depth, 256 KiB total projected buffer; expiry/overflow invalidates waiting callbacks and retires the generation if exact cancellation/isolation cannot be established. These are proposed bounds, not supplier guarantees or active limits. Never silently evict replay tombstones; capacity exhaustion fails closed. Tombstone typed request IDs and completed child turn identities for generation lifetime; conflicting duplicates/reuse are rejected. All queued observations remain non-authoritative and no arbitrary provider payload is durably stored.

## Decision dialect, App behavior, compatibility

| Supplier offered value | Runtime decision | App behavior |
|---|---|---|
| accept | allow | Allow this destination; retain same-destination queued-request caveat. |
| decline | deny | Deny only if actually advertised. |
| acceptForSession | acceptForSession | Separate explicit act and explanation of supplier session scope; disable until exact-pin scope/grouping evidence exists. |
| cancel | none | Never alias to deny. A distinct cancellation path requires exact supplier semantics and owner design; recommended initial escape is existing whole-generation interruption. |
| persistent network policy amendment | none | Recognize/redact known shape; do not offer or silently apply. |
| unknown / invalid / no supported choices | none | Unavailable/invalid request, no grant; retire if pending supplier work cannot safely be isolated. |

When decline is absent, show only supported grants plus “Stop this Runtime turn” with generation-wide consequence. This is an interruption action, not an approval decision. If App requires a per-child decline, blocker remains until supplier supports it or an owner-accepted distinct cancellation design has exact evidence. A prompt with no supported grants/decline is never converted into apparent consent. Closing a dialog performs no grant and no fabricated deny; expiry/stop is separately recorded.

App states proposed: waiting-for-authority (no actionable prompt), pending, decision-recorded, sending, sent-not-acknowledged, provider-resolved-without-inferred-decision, expired/retired, delivery-unknown, reconciliation-required. These are candidate approval-view states, not new HarnessEvent terminal identifiers. Authority failures yield refresh/unavailable; malformed/unadvertised decision yields bounded invalid/forbidden response; stale revision/duplicate conflict yields conflict semantics (exact HTTP choice requires contract review); shutdown/delivery failure disables retry until reconciliation. A human click is not displayed as network granted. Preserve conversation history and show whether child alone stopped or whole Runtime turn ended.

Compatibility recommendation: retain current v2 endpoints/events unchanged for consumers explicitly using their existing semantics. Negotiate a separately versioned approval representation/capability for B before enabling child approval display; route/header version selection is an owner decision, not a shipped endpoint. An old client must fail closed on child requests requiring origin, never silently receive a primary-shaped downgraded prompt. Primary v2 regression fixtures remain mandatory. New v2 event keys currently fail strict validation; therefore do not add fields in place. Preferred initial B view uses negotiated approval polling and current four terminal events, with any new attribution event schema separately ratified. Approval-request/decision events may retain their existing closed v2 shape only where documented actor meaning is unambiguous; no child data smuggled into actorId. SOCKS projection requires a deliberate enum/version decision or explicit unsupported-UI disposition, never mislabeled HTTPS. Replace ambiguous applied semantics only in the negotiated response with `{decisionRecorded,delivery,supplierApplied}`; retain old meaning documented for old clients. No fifth terminal, no silent new approval-resolved event.
