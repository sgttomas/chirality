## Cross-lineage analysis

All repairs through lineage six remained effective. Seventh intake was
non-circular, historical reads were exact, durable growth was visible,
`readlink` resolved correctly, builtin `wait` was shell syntax, and a pinned
zsh parsed the complete command mirror. The failure moved one layer deeper:
an executable script path is not the complete executable tool identity. Its
shebang interpreter and any mandatory launcher chain are part of the command
surface and must be resolved, pinned, and harmlessly probed too.

The catalog classified the mise npm wrapper as if its own bytes plus node were
sufficient. The child environment proved they were not. A future owner-
authorized lineage would need an explicit recursive executable-chain rule:
inspect shebangs/symlinks/wrappers, enumerate every interpreter/launcher byte,
freeze a PATH that resolves that chain, and probe the exact final invocation
in both manager and child environments before substantive authoring. Whether
to bind `/bin/bash`, invoke npm's JavaScript CLI directly with pinned node, or
choose another form is a new owner-directed packet-basis decision; this
manager does not select or implement one.
