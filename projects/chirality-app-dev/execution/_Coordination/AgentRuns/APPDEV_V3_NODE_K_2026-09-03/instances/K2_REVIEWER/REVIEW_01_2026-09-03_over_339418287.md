## Findings

### K1-F1 — MAJOR — both new `pass: false` assertions are vacuous with respect to the egress condition

**Location:**
`projects/chirality-app-dev/frontend/src/__tests__/scripts/run-packaged-security-proof.test.ts:143-179`, especially `:147-150` and `:166-170`.

Both new tests split the `[network-policy-probe]` JSON across three array
elements and then use `.join('\n')`. The real parser,
`frontend/scripts/run-packaged-security-proof.mjs:335-344`, parses each marked
log line independently. It therefore sees only the incomplete first line,
returns `{ parseError: true }`, and never observes either required network
probe. Consequently `blockedProbeObserved` and `loopbackProbeObserved` are both
false before the egress predicate is considered (`run-packaged-security-proof.mjs:397-405`).

Independent execution of the exact absent-egress fixture through the real
summarizer returned:

```json
{
  "probePayloadCount": 1,
  "blockedProbeObserved": false,
  "loopbackProbeObserved": false,
  "egressProbePayloadCount": 0,
  "egressProbeObserved": false,
  "pass": false
}
```

Thus the tests do exercise the real summarizer and their direct egress-field
assertions are meaningful, but the `pass: false` assertions would remain green
even if the overall proof stopped enforcing the absent/malformed egress-layer
condition. That defeats the brief's explicit non-vacuity requirement and leaves
the intended fail-closed regression guard incomplete.

**Required remediation:** make the unrelated prerequisites valid in both
fixtures. For example, construct the `[network-policy-probe]` payload as one
physical log line, as the pre-existing test at `:79-140` does, or reuse a shared
known-passing baseline and remove/replace only the egress-layer line. Then rerun
the focused test and dispatch a fresh reviewer over a new frozen commit.
