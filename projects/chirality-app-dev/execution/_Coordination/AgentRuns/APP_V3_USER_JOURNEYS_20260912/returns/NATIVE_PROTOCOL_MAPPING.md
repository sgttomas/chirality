## Current support and required wiring

1. **Message/progress evidence:** `packages/daemon/src/codex-supervisor.ts:442-506` receives notifications, already preserves raw params in progress and collects completed text, but text progress loses item identity and concatenates commentary and final messages. `packages/core/src/delegated-engine-adapter.ts:34,254-294` then drops message/reasoning/plan deltas and turn/completed. Remove loss for the approved projections: persist canonical raw notification or typed item events keyed by actual native `(threadId,turnId,itemId)`. Reconcile completed full text as replacement for that item, not appended duplicate. Reasoning is keyed additionally by summaryIndex. Keep phase null as unknown. Existing `chat:delta` compatibility may remain, but a projection with native item evidence must not render both copies. `frontend/src/lib/shell/harness-event-views.ts` and transcript/live/replay projections must use the same reducer. Checklist updates replace the current turn's array (retain prior events in history); never infer percentages, step completion, or native plan acceptance.

2. **Native children:** adapter lines 274-284 currently emits subagent.completed from completed collab calls, and `harness-event-views.ts:119-122` trusts it as child completion. Keep collab calls as calls; key native child rows by agent thread ID and expose separate call/agent statuses and result messages. Consume `thread/started`, `thread/status/changed`, child `turn/started`/`turn/completed`, child agentMessage items, and collab agentsStates. Preserve all receivers, including a failed call with running children. idle/notLoaded is thread availability, not a successful task verdict. Crucially supervisor currently wraps descendant notifications in the primary entry's provider IDs: use raw `params.threadId`, `params.turnId`/turn.id, or `params.thread.id`/parentThreadId to derive actual origin while retaining parent Runtime session routing. Primary turn completion alone must not mark all children completed. Supervisor entry lookup/retirement needs review for late child events: it currently attaches descendants via an active ancestor, so a projection alone cannot guarantee capture after primary retirement.

3. **Questions across inactive chats:** Runtime already owns execution independently of renderer subscription (`packages/daemon/src/turn-registry.ts:11-16`). `packages/core/src/delegated-runtime.ts:179-200` exposes pending requests by project/session, and `packages/daemon/src/runtime-daemon.ts:698-717` has authorized GET session requests and POST requests/:id/answer. Client port methods already exist in `frontend/src/lib/runtime-client/{daemon-harness-port,runtime-daemon-harness-port}.ts`, and UI methods in `frontend/src/lib/harness/client.ts`. Build a project/session keyed pending index using these reads for active sessions, refresh after resolution/reconnect, show sidebar badge and navigate to owning session. Do not derive actionable requests solely from selected-session bounded event buffer (`components/workspace/harness-events-provider.ts`) or a replayed historical pending row. Revalidate via live listing before answering. Preserve requestId, sessionId and method through navigation; key globally by project/session/requestId, not requestId alone. Existing request-resolved events and pending-map removal own closure. Fix descendant `serverRequest/resolved` handling if included: supervisor line 488 currently tests only primary thread, despite descendant requests routing into its pending map.

4. **Steering route chain:** add a typed `SessionSteerRequest` with stable operation/client message ID, expected Runtime turn ID and nonempty text; a response with accepted/rejected/unknown state and native accepted turn identity. Add session turn steer route in Runtime daemon, Runtime client, frontend DaemonHarnessPort, frontend route and harness client. Use `turn-registry` ownership to reject a stale Runtime turn before dispatch; map it to the currently owned native thread/turn using a supervisor capability (analogous to SupervisorRequestPort), passed through DelegatedRuntime. Do not accept arbitrary native thread IDs from the renderer. Supervisor sends `host.request('turn/steer',{threadId,expectedTurnId,input,clientUserMessageId})`; require returned turnId to match expected. This is a user input inside the same active turn: no new Runtime turn, instruction rebuild, role change or Stop+start.

## Persistence and uncertainty contract

Persist steering intent/operation ID and expected identities before supplier dispatch, then accepted/rejected/acknowledgment-unknown outcome. Append evidence to the owning session/turn stream so all subscribers and replay agree; do not emit a second turn.started or terminal for steering. Deduplicate repeated identical client operation IDs at Runtime (also reject payload reuse with different content). Supplier success means input accepted, not work completed. An explicit stale/no-active rejection preserves draft and prompts the normal next-send path; never silently convert it into a new turn. Transport failure after possible dispatch is unknown, not rejected: preserve submitted text and client ID, disable automatic retries and correlate subsequent userMessage.clientId from native events. If no confirming evidence arrives, keep uncertainty explicit; absent event is not proof it was not sent. Durable request identity/outcome is necessary if renderer reconnects or Runtime restarts; an in-memory dedup map alone does not establish crash safety.

Compatibility: additive typed events/contracts, preserve old persisted streams and unknown notification payloads. Native item evidence wins only for the native item/turn it describes; legacy chat text and managed child events retain their existing semantics. Scope pending cards to current live sessions, while history remains reviewable and non-actionable. No capability claim until actual composition wires the native steering port.
