# D-APP-20 Ruling - Document Content API Contract

**Status:** RULED
**Date:** 2026-06-19
**Decision ID:** D-APP-20

APPROVE: D-APP-20 **Option B**. The Phase 4 document content endpoint is a **read-only batch
GET** — `GET /api/working-root/deliverable/content` keyed by `deliverablePath` plus a
**validated relative file path within the deliverable** (`&file=<relpath>`), so the viewer can
open `_STATUS.md`, the deliverable body, or other in-deliverable markdown. Reuse the private
`readRequiredFile` and the existing path guards (`normalizeDeliverablePath`,
`assertWithinProjectRoot`, `realpath` containment, `DELIVERABLE_ID_PATTERN`); the `file`
parameter must resolve **inside** the deliverable directory. The sidebar Document view and the
doc-copilot viewer reuse `components/shell/chat-markdown.tsx`. Add focused route tests (happy
path, outside-root rejection, missing-file 404) + a viewer render test; `npm run typecheck`
green. This unblocks Phase 4.

This does NOT approve a write verb/PUT, reads outside the deliverable directory, streaming/SSE
content, an editor (see D-APP-21), provider/release changes, or any governance-state
(`CHECKING`/`ISSUED`) transition — those remain via the existing `status/transition` route only.
