bridge, full non-executable scaffolding, executable child turns, or continued hold.

| E | Hold R5 | No R5 source changes proceed. Future work must select another unblocked plan item or await a different human-gated direction. | All R5 implementation and executable subagent surfaces. |

## Recommendation

Approve Option A or Option B.

Rationale: the design package reduced implementation ambiguity but did not create executable
authority. Option A is the smallest source-bearing step and can prove Type 2 eligibility
without touching SDK option exposure. Option B is still non-executable but would exercise
the bridge and fail-closed `Agent` gate needed before any child turn is safe to consider.

Option C is reasonable if the human wants a larger non-executable scaffold before another
decision. Option D should be reserved for a later ruling after earlier slice validation
unless the human explicitly accepts the combined implementation risk.

  provider-neutral lifecycle events, adapter metadata isolation, bounded artifact references,
  and no project-truth promotion; `npm run typecheck`; `npm run test`.

  focused tests, `npm run test`, `npm run typecheck`, `npm run harness:validate:premerge`,
  and `npm run instruction-root:integrity`. Run `npm run proof:network-policy` only if a
  later ruling touches provider, network, API-key, or outbound behavior.

Every future implementation closeout must explicitly state that it makes no project-wide
dependency closure, release-readiness, lifecycle issuance, professional approval,
