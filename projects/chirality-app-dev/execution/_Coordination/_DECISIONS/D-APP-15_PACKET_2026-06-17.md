# D-APP-15 Decision Packet - Live Packaged agentSdk Read-Tool Proof

**Status:** PROPOSAL
**Date:** 2026-06-17
**Decision ID:** D-APP-15
**Prepared by:** WORKING_ITEMS
**Active plan:** `plans/PLAN_2026-06-17_live_packaged_agentsdk_read_tool_proof.md`
**Prior controlling ruling:** `execution/_Coordination/_DECISIONS/D-APP-12_RULING_STAB02D_PROOF_2026-06-17.md`

This packet asks whether the project should run one bounded live packaged
`agentSdk` read-tool proof before any future D-APP-12 packet may recommend making
`agentSdk` the default provider.

It does not approve default-provider cutover. It does not approve release readiness,
publication, signing, notarization, professional approval, certification, sealing,
authentication, or code-compliance acceptance.

## Decision Question

May WORKING_ITEMS execute one bounded live packaged `agentSdk` read-tool proof from the
macOS packaged app path, using the current opt-in SDK-backed Anthropic adapter, to collect
evidence for a later D-APP-12 default-provider review?

## Why This Packet Exists

D-APP-12 Option B accepted the no-live packaged SDK resolver/HOME proof but held default
provider cutover. Its ruling states that before any later D-APP-12 cutover packet may
recommend making `agentSdk` the default, WORKING_ITEMS should first request or prepare one
bounded live packaged read-tool proof path unless the human explicitly waives that proof.

The current active queue is therefore this proof-preparation plan, but the live provider
proof itself remains blocked until this packet is ruled.

## Blocks

Until this packet is ruled, do not:

- run a live packaged `agentSdk` provider call;
- load or use a stored Anthropic API key from the packaged proof path;
- change the default provider to `agentSdk`;
- declare the SDK-backed Anthropic adapter the active default in governance text;
- broaden provider/network policy;
- add concrete non-Anthropic providers;
- expose remote MCP, plugins, broad tool search, or domain tools;
- make release-readiness, lifecycle issuance, professional approval, certification,
  sealing, authentication, or code-compliance claims.

## Current Baseline

Proven before this packet:

- opt-in `agentSdk` scripted dev-turn validation through the SDK `query()` path;
- scripted `agentSdk` network-policy proof without broadening egress;
- no-live packaged SDK package/native CLI resolver proof from `app.asar.unpacked`;
- controlled `CLAUDE_CONFIG_DIR` and `HOME` propagation in the packaged SDK proof;
- mounted-DMG SDK presence and no-live resolver behavior;
- Section 8 and Section 9 validation surfaces for deterministic runtime evidence.

Not yet proven:

- live packaged `agentSdk` read-tool turn;
- live provider behavior from the packaged app path;
- live SDK transcript creation and location under packaged execution;
- default-provider readiness.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Approve one bounded live packaged read-tool proof | Future plan tranches may run one live packaged `agentSdk` read-tool proof, record package path, SDK transcript/HOME posture, API-key handling, network/redaction evidence, and proof artifacts. | Default-provider cutover, provider expansion, remote MCP/plugins/tool search/domain tools, release/professional claims. |
| B | Waive the live packaged proof prerequisite | Future work may prepare a D-APP-12 cutover packet without this proof, explicitly recording the waiver risk. | Default-provider cutover still requires a later D-APP-12 ruling. |
| C | Deny live packaged proof | No live packaged provider proof proceeds. `agentSdk` remains opt-in and default-provider cutover remains held. | Any live packaged provider evidence or default cutover. |
| D | Approve a narrower custom proof | Human supplies limits such as no stored-key use, dev-only key injection, no mounted-DMG run, or a different artifact set. | Anything not explicitly named by the custom ruling. |

## Recommendation

Choose **Option A** with strict boundaries.

Rationale: this is the narrowest evidence path named by the D-APP-12 hold ruling. It
keeps `agentSdk` opt-in, does not change provider defaults, and collects the one missing
packaged-live fact before any later cutover packet is prepared.

If live API use is not acceptable in this environment, choose Option B only if the project
is willing to carry the waiver risk into the later D-APP-12 review. Choose Option C if
default-provider cutover should remain held indefinitely.

## Required Constraints If Approved

- Run at most one bounded packaged read-tool proof tranche before returning to human
  review.
- Use only the current Anthropic/Claude Agent SDK first-adapter path; do not add provider
  routing or concrete non-Anthropic providers.
- Keep `agentSdk` opt-in. Do not change defaults.
- Use a disposable proof session and non-protected test workspace content.
- Record whether the API key was supplied through explicit environment/configuration and
  confirm it is not written to project files, runtime events, proof artifacts, logs, or
  imported SDK transcript summaries.
- Preserve controlled `CLAUDE_CONFIG_DIR` and `HOME` posture.
- Capture generated artifact paths and known limitations.
- Treat SDK transcripts as adapter evidence only; `.chirality/sessions/<id>/events.jsonl`
  remains the product-owned audit mirror.
- Stop immediately on unexpected network destination, secret exposure, uncontrolled HOME
  or settings source, missing package resource, transcript-path ambiguity, or provider
  behavior that cannot be classified.
