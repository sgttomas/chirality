# D-APP-22 Ruling - Live-Stream History / events.jsonl Replay

**Status:** RULED
**Date:** 2026-06-19
**Decision ID:** D-APP-22

SELECT: D-APP-22 **Option A now, Option B sequenced with the Phase 5 session-list**. The live
loop stays **live-only** for now (buffer reflects the active turn; `clearEvents()` at turn
start retained). When the Phase 5 session-list UI lands, add **hydrate-on-open**: seed the
buffer from the existing `replayHarnessEvents(sessionId)` then append live, so reopening a past
session shows its history.

Constraints carried to the future hydrate tranche: reuse `replayHarnessEvents` (do not fork a
second parser); respect the `MAX_LIVE_HARNESS_EVENTS` buffer bound (truncate oldest on
hydrate); do not double-count events already streamed live in the same turn; surface
`malformedLineCount` honestly. Continuous multi-client tailing (Option C) is **not** approved.

This does NOT approve continuous `events.jsonl` tailing or any change to the public event
contract or persistence.
