# D-APP-25 Ruling - Manager-Lifecycle & Anthropic-Manager Event Bridging

**Status:** RULED
**Date:** 2026-06-19
**Decision ID:** D-APP-25

APPROVE: D-APP-25 **Option C (both)**. Approve a bounded tranche that (a) bridges
**manager-level turn-lifecycle events** (`turn.accepted/started/cancelled/failed`,
`interruption.*`) to the live stream as `harness:event` so the loop can render a full turn
timeline, AND (b) brings **`AnthropicAgentSdkManager` to parity** so the Anthropic provider
emits the same rich `harness:event` stream as the Claude SDK manager.

Required constraints: keep exactly **one public event type** (`harness:event`) — add no
provider-shaped public names; the conformance check (`engine-conformance.ts` /
`PUBLIC_UI_EVENT_NAMES`) must stay green and `process:exit` must remain the terminal public
event. Run every bridged payload through `redactJsonLike` (same as persistence); no new leak
path. Reuse the provider-neutral `harnessEventToUiEvent` for the Anthropic path — do not fork a
second bridge. Update the exact-sequence manager tests + conformance tests; `npm run typecheck`
green. Implement as a **bounded tranche**, not combined with Phase 4 or with any
provider-expansion/release work.

This does NOT approve new public event names, any relaxation of redaction, the default-provider
cutover (that is D-APP-18), or provider expansion beyond the existing Anthropic/Claude paths.
