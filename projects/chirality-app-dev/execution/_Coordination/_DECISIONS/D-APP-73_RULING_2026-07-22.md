## Owner act

The owner supplied the decision-complete Shared Runtime and Local-Agent Pilot plan and explicitly instructed:

> PLEASE IMPLEMENT THIS PLAN

This record transcribes the app-dev effect of that act.

## Ruled selection

- Promote the provider-neutral executable harness from `frontend/` into root-owned `runtime/` packages without behavior change before adding daemon behavior.
- Preserve the current app-dev contract import path as a deprecated compatibility re-export for one migration cycle.
- Run the packaged Electron executable in headless `--runtime-daemon` mode as the single runtime/credential/session owner.
- Make the normal Desktop process a client; `/api/harness/*` becomes a thin daemon proxy preserving existing renderer routes, SSE names, replay semantics, and UI behavior.
- Add a bundled `chirality` CLI using Electron’s embedded Node runtime and the daemon’s authenticated Unix-socket API.
- Centralize sessions beneath daemon user data while lazily reading and non-destructively migrating existing project-local `.chirality/sessions` records.
- Add explicit oMLX status and activation control, one managed primary local LLM, drain-before-switch behavior, fail-closed `NO_MODEL`, redacted residency evidence, and residency epochs.
- Add tracked machine-independent app-dev and PEC project manifests with explicit re-registration after authority-affecting changes.
- Prove an app-dev Agent 1 run that must delegate exactly one bounded read-only task to an explicitly resident Pi/oMLX Agent 2, review the return, and terminate with `REQUIRED_DELEGATION_MISSING` if it fails to do so.
- Export only generic runtime, CLI, contracts, and safe adapters after validation.

## Prospective extension of D-APP-41

D-APP-41 remains immutable historical authority for canonical project-local session persistence. D-APP-73 prospectively permits the daemon to become the central session store for registered projects while:

- retaining JSON/JSONL as authoritative;
- lazily reading and migrating legacy project-local records on access;
- never bulk rewriting or destructively moving source records;
- preserving project attribution, replay, accepted input, tool evidence, and engine metadata;
- preventing daemon state from replacing checkout-contained governance truth.

## Prospective extension of D-APP-72

D-APP-72 and SCA-APP-002 remain historical. Their authenticated literal-loopback oMLX exception is extended only to:

- `GET /v1/models/status` discovery;
- explicit load and unload control required for one-primary-model residency;
- bounded drain and readiness timeouts;
- redacted residency transition evidence and epoch attribution.

Exact IDs, authenticated literal loopback, no redirects, no aliases, no automatic fallback, no remote provider, no force interruption, and the read-only Pi Agent 2 boundary remain mandatory.

## Preserved boundaries

Agent roles remain authority contracts independent of models. Credentials remain Desktop-managed and are not accepted or displayed by the initial CLI. No local Agent 1, automatic scheduling, multiple simultaneous primary local LLMs, piping, remote control listener, production-data use, lifecycle advancement, release, or professional-reliance act is authorized.
