# D-APP-24 Decision Packet - Type-2 Task-Agent Interaction in Direct Chat

**Status:** PROPOSAL
**Date:** 2026-06-19
**Decision ID:** D-APP-24
**Prepared by:** WORKING_ITEMS
**Active design:** `plans/DESIGN_2026-06-18_agent_orchestration_ui.md` (§3.3 direct chat with any persona, §6)

This packet asks how Type-2 (task) agents are surfaced in the proposed direct-chat screen.
It blocks the Phase 5 direct-chat surface. It does not relax subagent governance.

## Decision Question

In the direct-chat persona picker, how do Type-2 task agents behave: free chat, a structured
INIT-TASK brief form, or excluded (picker restricted to Type-0/Type-1)?

## Grounding (current state)

- Persona system prompts are composed by `PersonaComposer.buildSystemPrompt`
  (`src/lib/harness/persona-manager.ts`); the proposed `/chat` screen would pass an
  independent mode + persona to it.
- Subagent governance distinguishes agent **type** (`src/lib/harness/subagent-governance.ts`,
  `subagent-bridge.ts`): Type-2 are the governed task agents — the preflight path treats
  `agentType !== 2` specially, i.e. task agents are meant to run under the orchestrated/INIT
  contract, not ad-hoc.
- No `/chat` route exists yet; today personas are reached via the matrix → `/workbench`.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Free chat with any persona incl. Type-2 | Uniform UX; Type-2 agents receive a plain prompt like any persona. | (Accepts) ad-hoc task-agent invocation outside the governed INIT-TASK contract. |
| B | INIT-TASK brief form for Type-2 | Type-0/Type-1 get free chat; Type-2 require a structured task brief that satisfies the governed task-init contract before running. | Free-form Type-2 prompting that bypasses the brief. |
| C | Restrict picker to Type-0/Type-1 | Direct chat excludes Type-2 entirely; task agents run only via the orchestrated pipeline/subagent path. | Type-2 in direct chat at all. |
| D | Custom | Human supplies alternate handling. | Anything not named. |

## Recommendation

**Option C for the first cut, with B as the eventual richer path.** Type-2 task agents are
governed to run through the orchestrated/INIT path; exposing them to free chat (A) risks
bypassing that governance for the sake of UX uniformity. Restricting the picker (C) is the
smallest, safest first surface and keeps direct-chat to conversational personas. Promote to
**B** once the INIT-TASK brief contract is surfaced in the UI, giving Type-2 a governed entry
without ad-hoc prompting. Choose **A** only if task governance is explicitly relaxed for
direct chat (not recommended).

## Required Constraints If C (or B) Is Approved

- The direct-chat screen must not weaken `subagent-governance` preflight; a brief (Option B)
  satisfies, not replaces, the governed contract.
- Mode is selected independently per the §3.3 spec and passed to `buildSystemPrompt`.
- `npm run typecheck` + persona-resolution / picker tests green.
