# D-APP-32 Ruling - Tertiary-Form Affordance & Sidebar Tab Surface

**Status:** RULED
**Date:** 2026-06-19
**Decision ID:** D-APP-32

SELECT: D-APP-32 **Option A — new `SidebarTabId` tabs per tertiary screen**. The demoted
`/workbench` and `/pipeline` (and, as applicable, the portal matrix and file tree) are reached
from the right multi-view sidebar via new `SidebarTabId` + `SIDEBAR_TABS` entries, each opening
its full-screen tertiary form — matching DESIGN §3.2 ("the sidebar is the gateway to tertiary
screens; each view can open its full-screen tertiary form").

Constraints (carried from the packet): nothing deleted — `/workbench` + `/pipeline` routes stay
and still render their clients, every tertiary screen reachable; expanding `SidebarTabId` keeps
the existing WAI-ARIA tabs pattern and per-layout default-tab behaviour; no engine /
public-contract / permission-plane change; `npm run typecheck` + workspace-sidebar / shell tests
green.

This unblocks loop-first pivot tranche 28d (and, via D-APP-31 Option B, the in-place OPERATIVE
pipeline form). It does NOT approve a single-launcher (Option B) or top-nav-as-gateway (Option C)
affordance.
