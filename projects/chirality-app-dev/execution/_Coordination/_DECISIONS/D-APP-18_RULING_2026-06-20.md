# D-APP-18 Ruling - Default Provider Cutover After Live Packaged Proof

**Status:** RULED
**Date:** 2026-06-20
**Decision ID:** D-APP-18

SELECT: D-APP-18 **Option A — approve the bounded default-provider cutover implementation**. A
future bounded tranche **may change the harness default provider** from `stub` to the SDK-backed
Anthropic `agentSdk` path, now that the app-directory packaged live read-tool proof (D-APP-17,
model alias `sonnet`) has passed with `Read` tool use, proof-token read-back, an observed SDK
transcript under controlled `CLAUDE_CONFIG_DIR`, and redaction scans reporting **zero API-key
findings**. The post-merge loop-first-pivot audit (2026-06-20) independently re-confirmed the
provider / permission / redaction plane is intact and untouched, so the grounding still holds.

Scope of what this permits (carried from the packet): the cutover tranche may change the default
selection, align docs/control-plane surfaces to the new default, and run the relevant
runtime/package/harness validation gates.

Required constraints (binding on the implementation tranche):

- Implement the cutover in a **bounded tranche**; do **not** combine it with provider expansion or
  release-readiness work.
- Keep first-adapter scope to the existing **Anthropic / Claude Agent SDK** path only.
- Preserve the explicit **hard-deny** policy for remote MCP, plugins, broad tool search, domain
  tools, and professional-boundary changes unless separately ruled.
- Keep `stub` available as an **opt-in** provider after the default flips (nothing is deleted).
- Update docs / control-plane wording to state the new default **only after** code and tests land.
- Run focused provider/default tests, `npm run typecheck`, and the relevant package/harness
  validation selected from `docs/VALIDATION_STRATEGY.md`, `docs/RELEASE_QUALITY_GATES.md`, and
  `docs/BUILD_AND_RELEASE.md`.

Known limitations accepted by this ruling (not preconditions): mounted-DMG live parity was not
rerun under D-APP-17; the proof used a disposable generated project and a single read target rather
than a full user workflow; transcript content was not committed. A broader live-workflow smoke via
the existing env-var opt-in path is **recommended** before the cutover tranche lands but does **not**
gate this ruling.

This does NOT approve: provider expansion beyond the Anthropic path; remote MCP / plugins / broad
tool search / domain tools; **release readiness, signing, notarization, publication, attestation**,
or any distribution-release claim (those remain separate open decisions per
`docs/RELEASE_QUALITY_GATES.md` §10/§12 and `docs/BUILD_AND_RELEASE.md` §10); lifecycle issuance,
professional approval, certification, sealing, authentication, code-compliance acceptance, or any
professional-boundary change. All of these remain denied unless explicitly ruled.
