## Ruling

Option B is approved.

Default-provider cutover is **not** approved now. `agentSdk` remains opt-in until
STAB-02(d) packaged subprocess proof lands and WORKING_ITEMS returns with an updated or
superseding D-APP-12 packet.

STAB-02(d) packaged subprocess proof is required before any future cutover ruling may
approve making `agentSdk` the default provider.

Governance documents must not declare the SDK-backed Anthropic path the active default
runtime until a later ruling explicitly approves that cutover.

## Boundaries

This ruling approves continuing STAB-02(d) readiness work. It does not approve:

- changing the default provider to `agentSdk`;
- declaring SDK-backed Anthropic execution complete or default in governance text;
- release-readiness claims based on the SDK path;
- concrete non-Anthropic provider implementation or provider routing;
- provider-network expansion;
- Pi runtime paths;
- lifecycle issuance;
- professional approval;
- certification, sealing, authentication, or code-compliance acceptance;
- professional-boundary claim changes.

## Required Next Action

WORKING_ITEMS should continue STAB-02(d), recording packaged SDK subprocess evidence or
the exact blocker. After STAB-02(d) lands or blocks with evidence, WORKING_ITEMS should
prepare an updated or superseding D-APP-12 packet for the actual default-provider cutover
decision.
