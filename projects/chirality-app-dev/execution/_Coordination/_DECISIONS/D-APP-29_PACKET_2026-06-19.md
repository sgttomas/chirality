This packet asks whether and how to take up the deferred SECONDARY phase — growing the Workflow view from a thin peek into the agent+human task-management / workflow co-composition surface — and what the first bounded step is. It does not itself approve a build.

## Decision Question

Whether to advance the deferred SECONDARY phase next, and if so whether the first step is a dedicated design pass or a bounded build of a first slice.

## Grounding (current state)

- DESIGN §1 SECONDARY tier: run setup grows into "task management / workflow co-composition" — human-alone authoring -> a loose plan + an ongoing Type-1 session -> a composable, **non-programmatic** agent todo-list. It nucleates thin now; the full surface is a later phase.
- DESIGN §3.2 marks the Workflow view **Greenfield**; the current implementation is a thin placeholder peek (`src/components/shell/workspace-sidebar.tsx`: note "Workflow design is a thin peek now; the full surface is the deferred secondary phase").
- The seed model already exists: `CoordinationMode` (`COORDINATION_MODES`) + scaffold templates (`src/lib/harness/scaffold.ts`: `buildCoordinationTemplate`, `ScaffoldExecutionRoot*`), exposed via `POST /api/harness/scaffold`. `/pipeline` (`pipeline-client.tsx`) is the existing task-launch form.
- The secondary phase is the largest greenfield surface and has **no design of its own** — the active DESIGN scopes the PRIMARY loop + keystone, not the secondary phase internals. §5 closes: "the Workflow view stays a thin peek throughout; the full task-management surface is the deferred secondary phase."

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Defer (status quo) | The Workflow view stays a thin peek; no secondary phase now. Focus stays on the other follow-ons. | Any secondary-phase design or build. |
| B | Approve a bounded design step first | Produce a dedicated DESIGN doc + decision packets for the secondary phase (data model from `CoordinationMode`/`scaffold`; the human-authoring -> loose-plan -> agent-todo-list flow; non-programmatic composition) before any build. | Building the surface before its design is ruled. |
| C | Approve a bounded build of a first slice now | Build a first workflow-design view (e.g. composing a loose plan + agent todo-list from the scaffold seed) directly. | A design gate before code. |
| D | Custom | Human supplies alternate scope/sequencing. | Anything not named. |

## Recommendation

**Option B — a design step first.** The secondary phase is the largest greenfield area and has no design of its own, so jumping to a build (C) without a design pass is high-risk. If the owner wants to advance the secondary phase next, take **B**: produce its own DESIGN doc plus decision packets (data model from `CoordinationMode`/`scaffold`; the human-authoring -> loose-plan -> agent-todo-list flow; non-programmatic composition) before any code. Otherwise pick **A (defer)** while the editor (D-APP-26) and pivot (D-APP-28) follow-ons are sequenced. C is not recommended now: building before the surface is designed risks committing the largest greenfield area to choices made without a ruled design.

## Required Constraints If B (or C) Is Approved

- Keep the Workflow sidebar peek thin until a secondary-phase design is ruled.
- Reuse the `CoordinationMode` / `scaffold` seed rather than a parallel coordination model; composition stays **non-programmatic** per §1.
- Preserve the public UIEvent contract / permission plane / subagent governance unchanged.
- `npm run typecheck` + (for C) focused tests on the new view green.
