This packet asks whether to now commit to the full loop-first pivot (D-APP-23 Option B) — making the live loop the primary surface app-wide — or remain in the shipped hybrid. It is a routing/layout decision, not an engine change.

## Decision Question

Should the app commit to the full loop-first pivot now — live loop primary app-wide, route surfaces (portal/workbench/pipeline/file tree) demoted to sidebar-reachable tertiary forms, sidebar-right everywhere, matrix launches booting a session in-place — or stay hybrid?

## Grounding (current state)

- Hybrid shipped (D-APP-23 Option C): `LoopShell` is loop-first with the sidebar on the **right** for `/chat`; the route surfaces (`/`, `/workbench`, `/pipeline`) keep the sidebar on the **left** via `AppShell` + `ShellFrame`.
- `src/components/portal/agent-matrix.tsx` still `router.push`es to `/workbench?agent=…` and `/pipeline?category=…`, where the route `children` is the main execution surface and the loop is a side panel.
- DESIGN §3.1 target IA = the live loop is the primary surface; §5.2 explicitly recorded the sidebar-left placement as **transitional**, pending exactly this decision.
- All three routes work today; the chat stays mounted across sidebar collapse, so in-flight turns survive a relayout.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Stay hybrid (status quo D-APP-23 Option C) | Route surfaces keep sidebar-left; loop-first only for `/chat`. Incremental adoption; defers the rework. | The §3.1 loop-as-primary end-state app-wide. |
| B | Full loop-first pivot | The live loop is the primary surface app-wide; tertiary screens are reached via the sidebar (each opening its full-screen tertiary form) rather than as primary routes; sidebar-right everywhere; matrix-cell launches boot a session in-place (no route-as-main). Reaches the §3.1 end-state. | Preserving the route-as-main-surface model; (this is the largest remaining rework: `AppShell`/`ShellFrame`/routing/matrix). |
| C | Partial pivot | Make the portal `/` a loop-first home now, but keep `/workbench` and `/pipeline` as routes. A mid-step toward B. | A full demotion of all route surfaces in one tranche. |
| D | Custom | Human supplies alternate model/sequencing. | Anything not named. |

## Recommendation

This is a sequencing/appetite call, not a correctness call. **B is the stated §3.1 end-state** but the biggest remaining rework and the one most likely to disturb the working route surfaces. Recommend **C as the next increment** (portal -> loop-first home) if the owner wants to move toward B now, or **A** if the editor (D-APP-26) or secondary phase (D-APP-29) take priority. Commit to **B wholesale only if** the owner wants to accept the full route-surface rework in a single tranche.

## Required Constraints If B (or C) Is Approved

- Keep in-flight turns alive across any relayout (chat stays mounted, as it already does on sidebar collapse).
- Preserve the public UIEvent contract and the permission plane unchanged — this is a routing/layout change, not an engine change.
- Every tertiary screen (portal/workbench/pipeline/file tree) stays reachable via the sidebar; nothing is deleted.
- `npm run typecheck` + layout-geometry / route tests green; `next build` prerenders the affected routes.
