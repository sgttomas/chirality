# D-APP-23 Ruling - Portal Launch Model & Sidebar Placement

**Status:** RULED
**Date:** 2026-06-19
**Decision ID:** D-APP-23

SELECT: D-APP-23 **Option C (hybrid migration)**. Keep route navigation for the tertiary
screens (`/workbench`, `/pipeline`) and add a **loop-first "start session" entry** from the
portal that boots a session and focuses the live loop in place; relayout the multi-view sidebar
to the **right** only for the loop-first surface. This is the incremental path toward the §3.1
target IA (live loop as the primary surface); the full in-place pivot (Option B) is the eventual
destination but is **not** adopted wholesale now. This ruling resolves the DESIGN §5.2 sidebar
left→right question: left remains for the route surfaces; right for the loop-first surface.

Constraints: keep in-flight turns alive across any relayout (chat stays mounted, as it already
does when the sidebar collapses); fix the broken EVALUATIVE matrix cells as part of, or before,
the portal rework; preserve the public UIEvent contract and the permission plane unchanged
(this is a routing/layout change, not an engine change); `npm run typecheck` +
layout-geometry/route tests green.

This does NOT approve a full removal of route navigation or a big-bang loop-first rewrite.
