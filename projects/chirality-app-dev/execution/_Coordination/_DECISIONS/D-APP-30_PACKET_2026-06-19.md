This packet asks for the exact in-place launch interaction when a Type-0/Type-1 matrix cell is clicked on the loop-first portal: what happens to a prior in-flight turn, and what signals the boot. It blocks finalizing tranche 28c of the loop-first pivot. It does not change the public UIEvent contract or permission plane.

## Decision Question

When a Type-0/Type-1 matrix cell is clicked on the loop-first portal, what is the in-place launch interaction — specifically (a) the behaviour when a turn is already streaming, and (b) the visual transition that signals the new persona/session?

## Grounding (current state)

- `ChatPanel` (`src/components/shell/chat-panel.tsx`) boots route-free: persona resolves from `?agent=` (via `resolvePersona`), mode from pathname, and the session is created on FIRST message submission — not on page load. So swapping `?agent=` re-points the persona but does not itself start a turn.
- `buildDirectChatHref(persona)` (`src/lib/shell/loop-first.ts:19-24`) is the route-free href builder; the persona picker sets `?agent=` via `router.replace` today (`src/components/shell/persona-picker.tsx`).
- The matrix does NOT do a route-free in-place swap today: `AgentMatrix` Type-0/Type-1 cells currently `router.push` to a route-as-main (`src/components/portal/agent-matrix.tsx:66`, targets in `src/lib/portal/agent-matrix-cells.ts`). D-APP-28 / plan tranche 28c rewires these to the route-free `?agent=` path — so the in-place interaction this packet rules is net-new.
- In-flight turns survive relayout because `ChatPanel` is never unmounted (collapse is CSS-only). A shared `streaming` flag (`useHarnessStreaming` in `src/components/workspace/harness-events-provider.tsx:105`, set by the chat panel around a turn via `setStreaming(true/false)` at `chat-panel.tsx:285,468`) already exists and is the precedent guard: Tranche 5c disables the session-list "Open" button mid-turn (`disabled={openingId !== null || streaming}`, `src/components/shell/session-list-view.tsx:98`, with the mid-turn abort at `:179`) so a hydrate cannot clobber live events.
- `AgentMatrix` (`src/components/portal/agent-matrix.tsx`) coalesces same-tick navigation bursts to a single navigation via `createNavigationIntentScheduler` (`src/lib/workspace/navigation-intent.ts`, flushed on the next `queueMicrotask`; `navigation-intent.test.ts`). This is microtask-level de-duplication of click bursts — it does NOT gate on streaming-turn boundaries, so it does not by itself protect an in-flight turn.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Swap immediately on click, even mid-turn | Cell click re-points `?agent=` unconditionally; `ChatPanel` applies the new persona to the next message. Simplest. | (Accepts) changing the active persona while a turn is streaming, which can orphan the running turn context. |
| B | Guard mid-turn (reuse the Tranche 5c `streaming` precedent) | Swap immediately when idle; when a turn is streaming, block/confirm the switch (mirror the session-list "Open" guard via `useHarnessStreaming`) so an in-flight turn is not clobbered. A brief loop focus/transition signals the boot. | Silent mid-turn persona swaps. |
| C | Always open a fresh session/loop per cell click | Each launch starts a new session, leaving any prior session untouched. | Re-pointing the current loop in place; (accepts) session proliferation. |
| D | Custom | Human supplies alternate interaction. | Anything not named. |

## Recommendation

**Option B.** It reuses the existing `streaming` / `useHarnessStreaming` guard already shipped in Tranche 5c, so an in-flight turn is never clobbered by a cell click, while an idle click swaps immediately for a fast loop-first feel. A is too cavalier mid-turn (a silent persona swap mid-stream); choose A only if the owner accepts orphaning a running turn for the sake of the simplest path. C changes the session model — a new session per launch multiplies sessions and diverges from the single-loop-in-place intent of D-APP-28 — so choose C only if the owner wants each matrix launch to be its own session.

## Required Constraints If B (or C) Is Approved

- Preserve in-flight-turn survival: `ChatPanel` is never unmounted by a cell click; for B reuse the shared `streaming` flag rather than a new mechanism.
- No engine / public UIEvent contract / permission-plane change — this is a launch-interaction decision only.
- `npm run typecheck` + matrix / loop-first / chat-panel tests green.
