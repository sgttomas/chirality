## Question

How should the project treat REF-006, the repeated `docs/PRD.md` hash mismatch recorded by
deliverable-local reference files?

## Options

| Option | Meaning | Consequence |
|---|---|---|
| A - Refresh accepted hash | Accept the current `docs/PRD.md` content as the intended PRD basis and update downstream references through a bounded source-state refresh. | Best if the current PRD is authoritative. |
| B - Keep warning-limited | Continue allowing assessments and roadmap work to cite current PRD text while preserving the mismatch as a source warning until a later source-control audit. | Lowest immediate churn, but blocks clean issuance. |
| C - Block PRD-grounded issue readiness | Treat the mismatch as blocking any PRD-grounded issue-readiness package until source provenance is repaired. | Highest rigor, but delays many deliverables. |

## Recommendation

Choose Option A if the current PRD is authoritative. Choose Option B only as a temporary hold. Do not
issue PRD-grounded deliverables while REF-006 remains unresolved.

## Non-Approval Statement

This packet is not a ruling and does not refresh any hash by itself.
