# D-APP-16 Decision Packet - Model-Corrected Live Packaged agentSdk Proof Retry

**Status:** PROPOSAL
**Date:** 2026-06-18
**Decision ID:** D-APP-16
**Prepared by:** WORKING_ITEMS
**Active plan:** `plans/PLAN_2026-06-17_live_packaged_agentsdk_read_tool_proof.md`
**Prior controlling ruling:** `execution/_Coordination/_DECISIONS/D-APP-15_RULING_2026-06-18.md`
**Evidence basis:** `plans/artifacts/lp03_live_packaged_agentsdk_read_tool_evidence_2026-06-18.md`

This packet asks whether the project should authorize any follow-up after the single
D-APP-15-approved live packaged `agentSdk` read-tool proof failed before tool execution
because the selected model was unavailable or inaccessible for the supplied key.

It does not approve default-provider cutover. It does not approve release readiness,
publication, signing, notarization, professional approval, certification, sealing,
authentication, or code-compliance acceptance.

## Decision Question

After the D-APP-15 one-run proof failed with a selected-model availability/access error,
may WORKING_ITEMS run one additional bounded app-directory packaged `agentSdk` read-tool
proof using an explicitly selected accessible model, or should the plan close/continue
with the failed proof as a blocker?

## Why This Packet Exists

D-APP-15 Option A approved one live provider run only. LP-03 consumed that run. The run
reached live provider execution but returned:

```text
There's an issue with the selected model (claude-sonnet-4-20250514). It may not exist or you may not have access to it. Run --model to pick a different model.
```

Because no `Read` tool use occurred, the intended packaged live read-tool evidence remains
missing. Running again with a different model would exceed D-APP-15 and therefore requires
a new human ruling.

## Blocks

Until this packet is ruled, do not:

- run a second live packaged `agentSdk` provider call;
- provide or read a new live API key for a retry;
- change the model and rerun the live proof;
- change the default provider to `agentSdk`;
- declare the SDK-backed Anthropic adapter the active default in governance text;
- broaden provider/network policy;
- add concrete non-Anthropic providers;
- expose remote MCP, plugins, broad tool search, or domain tools;
- make release-readiness, lifecycle issuance, professional approval, certification,
  sealing, authentication, or code-compliance claims.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Approve one model-corrected retry | One additional app-directory packaged live read-tool proof using an explicit `--model <name>` supplied or approved by the human, with a fresh explicit key-file path and the same LP-02 redaction/stop conditions. | Any further live retries, default-provider cutover, provider expansion, remote MCP/plugins/tool search/domain tools, release/professional claims. |
| B | Deny retry and record blocker | No second live run proceeds. The plan records LP-03 as blocked by model access and keeps `agentSdk` opt-in. | Any live retry or default cutover. |
| C | Waive successful live read-tool proof prerequisite | Future work may prepare a D-APP-12 cutover packet while explicitly carrying the failed-proof/waiver risk. | Default-provider cutover still requires a later D-APP-12 ruling. |
| D | Custom ruling | Human supplies a narrower or different disposition, such as requiring model discovery outside the packaged proof, selecting a different provider-account path, or closing the queue. | Anything not explicitly named by the custom ruling. |

## Recommendation

Choose **Option A** only if the human can supply or approve a model known to be accessible
for the intended key, and can provide a fresh temporary key file. Otherwise choose
**Option B** and close the current queue with `agentSdk` still opt-in.

Do not choose Option C unless the project is willing to consider default-provider cutover
without the packaged live read-tool evidence that D-APP-12 previously requested.

## Required Constraints If Option A Is Approved

- Run at most one additional app-directory packaged live read-tool proof.
- Use `plans/artifacts/lp02_live_packaged_agentsdk_read_tool_procedure.md` as the base
  procedure, with only the human-approved `--model <name>` and key-file path changed.
- Use app-directory package path first; mounted-DMG parity remains unapproved unless
  explicitly named.
- Keep `agentSdk` opt-in. Do not change defaults.
- Use only the current Anthropic/Claude Agent SDK first-adapter path; do not add provider
  routing or concrete non-Anthropic providers.
- Preserve controlled `CLAUDE_CONFIG_DIR`, controlled `HOME`, `settingSources: []`, and
  read-only tool exposure.
- Record redaction checks and remove the temporary key file after the attempt.
- Stop immediately on secret exposure, unexpected package path, missing package resource,
  model/access error, transcript-path ambiguity, or any requirement for write/shell/web,
  remote MCP, plugins, broad tool search, domain tools, or more than the one approved
  retry.

## Minimum Validation If Option A Is Approved

- Reuse the already-built package only if no source/package change occurs after LP-03;
  otherwise rerun `npm run desktop:pack`.
- Rerun `npm run harness:validate:agentsdk-packaged-proof` as the no-live baseline if the
  package is rebuilt.
- Run the live proof command once with explicit `--model <human-approved-model>` and
  `--api-key-file <fresh-key-file>`.
- Review `summary.json`, redaction results, and failure/pass observations.
- Record evidence under `plans/artifacts/`.
