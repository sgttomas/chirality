# D-APP-08 Decision Packet - Bounded Executable R5 Subagent Implementation

**Status:** PROPOSAL
**Date:** 2026-06-16
**Prepared by:** WORKING_ITEMS
**Active plan item:** Post-`D-APP-07` bounded executable R5 implementation gate

This packet asks whether a bounded executable R5 governed subagent implementation tranche
is approved after the provider-neutral contract prerequisite and residual SCC posture
ruling have both landed.

It does not implement executable R5.

## Decision Question

Is a bounded executable R5 governed subagent implementation tranche approved now that:

- the provider-adapter-neutral agent/subagent runtime contract prerequisite has landed; and
- `D-APP-07` ruled that the residual six-node SCC blocks project-wide strict
  dependency-closure claims only, not bounded R5 dispatch selection?

The ruling may approve a bounded implementation, approve a narrower non-executable bridge,
require more design/evidence first, or continue to hold executable subagent capability.

## Blocks

Until this packet is ruled, do not implement or expose:

- model-visible SDK `Agent` tool execution;
- executable SDK `agents` definitions;
- child turn execution;
- child output artifacts from executable child runs;
- child capability inheritance or expansion;
- concrete provider implementation or provider routing;
- network expansion;
- Pi runtime paths;
- release-readiness claims or professional-boundary changes.

This packet does not authorize dependency-register edits or any claim of project-wide
strict dependency closure.

## Current Baseline

Landed runtime posture:

- provider-neutral child-run records exist;
- executable delegation remains blocked;
- child runs do not inherit parent capabilities;
- adapter-specific identifiers remain adapter metadata;
- controlled Bash, read/write hooks, tool descriptors, permission overlay, runtime events,
  and split-root instruction packaging have landed;
- Pi is pattern corpus/reference only;
- concrete non-Anthropic providers and provider routing remain blocked.

Current dependency posture:

- project-wide strict dependency closure remains unclaimable;
- the residual six-node SCC remains active in dependency evidence;
- `D-APP-07` allows bounded executable R5 selection without treating that SCC as a
  dispatch blocker for R5, provided no project-wide closure claim is made.

| C | Require an implementation design package first | No executable code lands; WORKING_ITEMS prepares a design/evidence package decomposing executable R5 into smaller implementation slices and validation gates. | Executable child turns, model-visible `Agent`, SDK `agents` that can run, provider/network broadening, Pi work. |

Future work must select another unblocked plan item or await a different human-gated direction. | SDK subagent execution, concrete provider expansion, remote MCP/plugins, Pi runtime paths, project-wide closure claims. |

## Recommendation

Approve Option B or C before Option A.

Rationale: `D-APP-07` removes the SCC as an R5 dispatch-selection blocker, but executable
R5 still spans tool descriptor exposure, SDK option construction, hook governance, child
definition generation, event persistence, and child output artifacts. A bridge or design
package can reduce implementation risk while preserving the current denial of
model-visible `Agent` execution.

If the human wants to proceed directly to implementation, Option A should be constrained to
a single bounded tranche with fail-closed behavior and no project-wide dependency closure,
provider/network, Pi, release, or professional-boundary claims.

## Validation Implications If Option A Is Ruled

Minimum expected validation for a bounded executable R5 tranche:

- focused tests for SDK `agents` definition generation from eligible Type 2 instruction
  files;
- denial tests for non-Type-2, non-allowlisted, unsealed, missing-approval, malformed, and
  unknown subagent requests;
- SDK options tests proving `Agent` is model-visible only after descriptor, mode,
  permission, and governance checks pass;
- hook tests proving `Agent` preflight fails closed on evaluator errors, missing metadata,
  inherited capability expansion, child cwd violations, and child tool violations;
- event tests for parent-child linkage, adapter metadata isolation, and child lifecycle
  event categories;
- output artifact tests proving child outputs are bounded records and not project truth;
- regression tests proving `readOnly`, `dontAsk`, and developer-only `bypass` do not grant
  ungated subagent autonomy;
- `npm run test`;
- `npm run typecheck`;
- `npm run harness:validate:premerge` when browser-facing session, SSE, or turn behavior
  changes;
- `npm run instruction-root:integrity`;
- `npm run proof:network-policy` only if implementation touches provider, network, or
  outbound behavior, which Option A does not authorize by default.
