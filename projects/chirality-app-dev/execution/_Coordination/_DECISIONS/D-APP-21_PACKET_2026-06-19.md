# D-APP-21 Decision Packet - Document Editor Technology

**Status:** PROPOSAL
**Date:** 2026-06-19
**Decision ID:** D-APP-21
**Prepared by:** WORKING_ITEMS
**Active design:** `plans/DESIGN_2026-06-18_agent_orchestration_ui.md` (§3.3 Document + copilot editor, §6)
**Depends on:** D-APP-20 (content contract; an editor needs read+write)

This packet asks which editing technology, if any, the doc-copilot tertiary screen should
use. It does not approve write capability itself (that rides on D-APP-20 Option C or a later
content-write ruling) nor any governance-state transition.

## Decision Question

When the editable document screen is built, should it be a markdown-source editor, a WYSIWYG
editor, or deferred (read-only viewer only) for now?

## Grounding (current state)

- No editor exists. The viewer is read-only markdown via `chat-markdown`.
- Deliverables are plain markdown/CSV under governance + issuance contracts (`_STATUS.md`,
  `Dependencies.csv`, body) — source files that flow through git and `status/transition`
  gating, where source fidelity and clean diffs matter.
- The editable screen is a Phase-5-adjacent tertiary surface, not required for Phase 4.

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | Markdown-source editor (CodeMirror 6 or Monaco) | Edit raw markdown with syntax highlighting; lossless round-trip; clean git diffs; light-to-moderate dep. | WYSIWYG rendering-while-editing; write itself until D-APP-20 grants it. |
| B | WYSIWYG (ProseMirror / TipTap) | Rich rendered editing; friendlier for non-technical authors. | Accepts markdown round-trip fidelity risk + heavier dep + larger surface. |
| C | Defer — read-only viewer only for now | Phase 4 ships the viewer; the editor decision is revisited after Phase 4/5. | Any in-app document editing. |
| D | Custom | Human supplies alternate tech/sequencing. | Anything not named. |

## Recommendation

**Option C now, with A as the chosen tech when an editor is built.** Deferring keeps Phase 4
unblocked and avoids committing an editor dependency before the content contract (D-APP-20)
and portal model (D-APP-23) settle. When editing is taken up, prefer **A (CodeMirror 6)**:
deliverables are governed markdown source where fidelity and diff-ability outweigh WYSIWYG
convenience, and the dep is lighter than ProseMirror. Choose **B** only if a non-technical
authoring audience is a hard requirement and markdown round-trip loss is acceptable.

## Required Constraints If An Editor Is Approved

- No write path until D-APP-20 authorizes content write; the editor is inert (read-only
  buffer) until then.
- Document edits never perform governance-state transitions; `CHECKING`/`ISSUED` stays gated
  through the existing `status/transition` route with `actor=HUMAN` + `approvalSha`.
- Bound the new dependency; record bundle-size impact against the Electron build gates.
- `npm run typecheck` + focused editor/component tests green.
