# D-APP-41 Ruling - Session Folder Migration Duplicate-Shape Semantics

**Status:** RULED
**Date:** 2026-06-21
**Decision ID:** D-APP-41
**Ruling basis:** Owner ratification, 2026-06-21 (during review of the D-APP-39 autonomous run).
The owner had given only a *general* direction — favor long-term consistency, no preference for
backward compatibility, cleanup acceptable — and did **not** select this option. WORKING_ITEMS
selected Option D under that general steer and initially recorded it as `RULED`, which mis-attributed
the agent's own choice to the owner (since corrected; the choice was within the invited initiative). On 2026-06-21 the owner
reviewed the fork on its merits and **explicitly ratified Option D** (eager legacy conversion to
canonical session folders). This ruling is valid as of that ratification, not as of the original
autonomous recording.

## Ruling

SELECT: D-APP-41 **Option D - eager legacy conversion**.

Canonical session storage is `.chirality/sessions/<sessionId>/session.json`. Flat legacy session
records must be converted to canonical folders on first read, list, resume, or save through a
deterministic migration path. After successful conversion, runtime behavior uses only the canonical
folder record. New sessions must never write flat session records.

## Duplicate-Shape Policy

If both `.chirality/sessions/<sessionId>/session.json` and `.chirality/sessions/<sessionId>.json` exist,
the runtime must resolve the duplicate shape by migrating, archiving, or removing the flat record
according to the migration implementation. Tests must prove no field loss for supported legacy fields.
After resolution, read, resume, list, save, and delete operate on the canonical folder record.

## Required Follow-Through

- Implement canonical folder creation for new sessions.
- Implement deterministic conversion for flat-only legacy records on first read/list/resume/save.
- Implement duplicate-shape resolution with no field loss for supported legacy fields.
- Update session-manager/API tests for canonical create/get/list/save/delete, flat conversion, duplicate
  resolution, and session-root override behavior.
- Record DEL-05-01 evidence and update the active autonomous queue and completion log.
