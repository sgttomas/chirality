## Question

What UI evidence bar should be required before UI/product deliverables can be considered
issue-ready?

## Options

| Option | Meaning | Consequence |
|---|---|---|
| A - Logic/API tests sufficient | Accept helper, route, and non-browser tests when they cover behavior. | Fastest, but weak visual/interactivity assurance. |
| B - Component/render tests required | Require component-level render tests for UI controls, state, and disabled/active behavior; browser screenshots only when layout risk is high. | Balanced and recommended. |
| C - Browser E2E required | Require browser-level interaction evidence for all UI/product deliverables. | Strongest, but heavier than current project needs. |

## Recommendation

Choose Option B. It matches the inspection findings: many UI mechanics are covered by logic/API tests,
but the gate still needs a consistent render-level bar for user-facing controls and layout-sensitive
states.

## Non-Approval Statement

This packet is not a ruling and does not make any UI deliverable issue-ready.
