# D-APP-27 Decision Packet - Type-2 INIT-TASK Brief - Governed Direct Entry for Task Agents

**Status:** PROPOSAL
**Date:** 2026-06-19
**Decision ID:** D-APP-27
**Prepared by:** WORKING_ITEMS
**Active design:** `plans/DESIGN_2026-06-18_agent_orchestration_ui.md` (§3.3 direct chat / pipeline, §3.4 operator modes)
**Depends on:** D-APP-24 (RULED Option C now / B later: the `/chat` picker is restricted to Type-0/Type-1; Type-2 is excluded; the INIT-TASK brief is the staged follow-on; no relaxation of subagent governance)

This packet asks how the staged Type-2 INIT-TASK brief (D-APP-24 Option B) should be surfaced so task agents get a governed direct entry without ad-hoc free chat, and what that brief contract requires. It does not relax subagent governance.

## Decision Question

How should a governed Type-2 entry be surfaced — a new INIT-TASK brief form inside `/chat`, a reuse of the existing `/pipeline` launch surface, or kept excluded — and what does the brief contract require?

## Grounding (current state)

- D-APP-24 restricted the `/chat` picker to Type-0/Type-1; `assertDirectChatPersona` (`src/lib/harness/agent-roster.ts`) hard-rejects a Type-2 persona at session-create when the section is `CHAT`, so a Type-2 cannot boot as a top-level chat persona. Type-2 agents currently have **no** direct-chat entry.
- There is **no existing INIT-TASK / task-init / "brief" contract** in the harness (verified: no such symbol in `src/lib/harness/subagent-governance.ts` or `subagent-bridge.ts`). A brief would be a **new** contract to define.
- `subagent-governance.ts` governs the **delegated-subagent** path, not a top-level persona run: it requires `CHIRALITY_ENABLE_SUBAGENTS=true`, resolves delegated subagents (each must declare `AGENT_TYPE=2`), and evaluates gates (e.g. ENVIRONMENT). Type-2 agents are designed to run **as delegated subagents under an orchestrating persona**, not as a top-level chat persona.
- `/pipeline` (`src/app/pipeline/pipeline-client.tsx`) is the existing OPERATIVE task-launch surface; DESIGN §3.3 says it "stays the OPERATIVE launch surface; surface task-agent choice explicitly."
- Persona system prompts compose via `PersonaComposer.buildSystemPrompt` (`src/lib/harness/persona-manager.ts`).

## Options

| Option | Ruling | What it permits | What remains denied |
|---|---|---|---|
| A | New INIT-TASK brief form inside `/chat` | Selecting a Type-2 persona reveals a structured brief (objective, scope, deliverable target, acceptance criteria, governance/approval fields) that constructs a new governed task-init request; `assertDirectChatPersona` is relaxed for Type-2 **only when accompanied by a valid brief** satisfying that contract. A governed Type-2 entry from the loop-first surface. | Free-form Type-2 prompting that bypasses the brief; any weakening of subagent-governance preflight. |
| B | Route Type-2 selection to the existing `/pipeline` launch surface | Make task-agent choice explicit on `/pipeline` (already the §3.3 plan); `/chat` stays Type-0/Type-1. Reuses the existing governed launch; no second task-init contract invented. | Type-2 inside the `/chat` loop-first surface. |
| C | Keep status quo (D-APP-24 Option C stands) | Type-2 excluded from direct chat; no brief; revisit later. | Any Type-2 direct entry. |
| D | Custom | Human supplies alternate handling. | Anything not named. |

## Recommendation

**Option B**, with A as the richer path only if a loop-embedded Type-2 entry is a hard requirement. `/pipeline` already is the governed task-launch surface and "surface task-agent choice explicitly" is already the §3.3 plan, so B reuses an existing governed path and avoids inventing a second task-init contract. A is correct only if the owner specifically wants Type-2 governed inside `/chat` — in which case the brief must be a real governed contract (satisfying, not replacing, subagent-governance preflight), not a thin form. C remains valid if Type-2 direct entry is simply not wanted yet.

## Required Constraints If A (or B) Is Approved

- Must not weaken `subagent-governance` preflight: a brief (A) **satisfies**, not replaces, the governed contract; a Type-2 still never boots as a free-chat top-level persona.
- Mode is selected independently per §3.4 and passed to `PersonaComposer.buildSystemPrompt`.
- For B, reuse the existing `/pipeline` launch + governance; do not fork a parallel launch path.
- `npm run typecheck` + persona-resolution / picker / `assertDirectChatPersona` gate tests green.
