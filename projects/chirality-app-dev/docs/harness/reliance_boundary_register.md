surfaces and validation evidence. It is governance and implementation-review

validate, or release the product or any professional work.

## Register Schema

Each P0 row carries these fields:

| Field | Requirement |
|---|---|
| BoundaryID | Stable ID for the reliance boundary. |
| BoundaryCategory | Audit, permission, filesystem, lifecycle, transcript, settings, subagent, human-gate, engine, tool-surface, hook, redaction, or fallback. |
| ProductSemantic | Chirality-owned behavior being protected. |
| SourceRefs | Governance and product source support. |
| EnforcementOwner | Chirality code, SDK option, SDK hook or callback, MCP wrapper, human gate, release check, prompt support, or mixed. |
| EnforcementSurface | Concrete module, API, hook, file, test, or check. |
| PromptOnlyAllowed | Must be `NO` for P0 boundaries. |
| SDKDefaultOnlyAllowed | Must be `NO` for P0 boundaries. |
| ValidationID | Implemented Section 9 ID when available; otherwise `TBD` with residual risk. |
| ResidualRisk | Known unresolved risk or downstream closure condition. |
| DecisionStatus | `PROPOSED` in this CHECKING-stage register until accepted by the owning lifecycle workflow. |
