# Concept Method and Attribution

> **NON_AUTHORITATIVE — CONCEPT EVIDENCE**

## Method

The concept tranche used three parallel, read-only host-platform subagents with
the same accepted Gate-2 ceiling and a common return contract. They did not
write repository files. The integration owner normalized their returns,
performed the shared journey/component analysis, built the comparison, and
retained sole write ownership of this packet.

| Host-platform subagent | Bounded assignment | Write scope | Result |
|---|---|---|---|
| `agent1_terminal_hardening` | Concept A — Workroom first | None | Complete |
| `desktop_runtime_controls` | Concept B — Agent Room first | None | Complete |
| `sca003_initial_audit` | Concept C — hybrid peers | None | Complete |

The host platform did not expose independently verifiable model identifiers
for these three subagent returns. No model attribution is invented.

These subagents are not Chirality sessions or governed AgentRuns. Their use
demonstrates the development work pattern only; it does not expand the shared
runtime's current one-Agent-1 / one-read-only-Agent-2 pilot capability.

## Integration decisions

- Kept all three proposals within the existing runtime and compatibility
  ceiling.
- Used one shared evaluation rubric.
- Normalized region, journey, state, accessibility, performance, decomposition,
  and acceptance sections for comparison.
- Recommended Concept C with Workroom startup behavior from Concept A.
- Did not modify authority, decomposition, runtime, or production frontend.
