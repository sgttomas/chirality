## Why this option

The exact validator `tools/validation/validate_candidate_whitespace.py` uses Git `diff --check` for tracked changes. Its separate untracked scanner checks ASCII trailing spaces/tabs and terminal empty lines, but does not inspect the `whitespace` attribute. Consequently, a narrow `-whitespace` rule would leave pre-staging validation failing. Marking textual logs `-diff`, `-text`, or `binary` would make the scanner skip them, but also classify actual text as binary or hide review diffs. That approach is not recommended. No attributes or root policy changes are proposed.

The earlier packaging run already uses three maps and an explicit `PRESENTATION_README.md`. All 14 retained originals in those maps decoded and matched their historical SHA256 values during this review. The recommended approach follows that precedent while making final source-versus-presentation claims explicit. It preserves every original byte and old hash; it does change the readable path's representation, so final evidence must never describe that path as still containing its original raw bytes.
