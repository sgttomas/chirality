# Bounded descendant tracker proposal

OpenAI GPT-6 ephemeral Agent2, role instruction-asserted; exact serving ID unavailable. Evidence-only proposal pending parent release of two code paths: packages/core/src/descendant-tracker.ts and tests/descendant-tracker.test.ts. No code or process mutation in this planning step.

Implement a tracker with explicit start/stop/reconcile lifecycle, one timer, bounded poll interval/deadline, maximum census/output size and no overlapping scans. Census requests only pid, ppid, pgid, uid and start identity, never args/environment/command lines. Resolve descendants transitively while the leader identity is live; retain observed identities after reparenting or group detachment. Reconcile known records against fresh identity immediately before signaling. Never signal an unknown/reused/mismatched identity; stop scanning on close and surface scan failures.

Portable census proposal: /bin/ps or /usr/bin/ps with fixed literal argv and LC_ALL=C, no shell: Darwin -axo pid=,ppid=,pgid=,uid=,lstart=; Linux -eo equivalent. Strict parse four decimal fields and the remaining fixed start string; bounded buffer and timeout; malformed rows fail closed rather than guessing fields. This provides ancestry discovery but Darwin lstart has seconds precision. It cannot by itself justify a mechanically PID-reuse-safe kill.

Identity and signal must therefore be injected through a host backend. Linux can strengthen identity with /proc/<pid>/stat start ticks (no args/env), with pidfd-based signaling preferred if available. Darwin strong identity requires libproc PROC_PIDTBSDINFO start_tvsec/start_tvusec or another verified host backend. The two proposed TypeScript files alone cannot pretend ps supplies microsecond identity. Until a strong backend is available, return unresolved known detached processes rather than kill using coarse ps identity. Group retirement and orphan reconciliation remain separate outputs.

Meaningful tests: fake census proves transitive ancestry, reparent retention, PID reuse rejection, unrelated process exclusion, bounded scans and cancellation; an actual isolated helper spawns a detached descendant that remains alive long enough for a census, reports its PID over a dedicated test pipe, then exits. Verify the tracker retains that observed descendant after reparenting. Actual kill tests require a strong identity backend or a still-owned ChildProcess handle; otherwise record discovery-only evidence and clean the fixture through its dedicated private control channel.

Residual: a process can detach and reparent between polls before observation. Polling alone cannot prove comprehensive orphan capture. Report this gap explicitly; complete process containment may need stronger kernel supervision or an accepted no-detach restriction. Never label observed-descendant reconciliation as proof that no orphan can escape.

Recommendation: release the two files for the bounded tracker and injected backend contract, discovery plus deterministic fail-closed reconciliation tests. Do not add a platform helper or new production dependency without a specific path/scope release. Parent may instead release a small Darwin libproc helper if actual PID-safe cleanup is needed in this tranche.
