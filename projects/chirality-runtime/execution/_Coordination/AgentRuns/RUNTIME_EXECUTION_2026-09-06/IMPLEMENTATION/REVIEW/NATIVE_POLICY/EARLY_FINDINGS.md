# Early native action policy findings

Provisional read-only review during concurrent authoring. No tests or vendor execution. Source hashes are review-time observations, not a final freeze. Items sent to manager immediately.

1. **P1 — Production launch omits App Server subcommand.** At inspection, native launchArguments returns executable plus config overrides only, and supervisor directly spawns them. Without the exact observed App Server argv, this starts the ordinary CLI instead of the intended server. Coordinate compiler/supervisor owners to restore exact subcommand/transport flags and test launch argv.
2. **Blocking evidence gap — platform defaults are intended, not yet proved disabled.** includePlatformDefaults:false occurs in digest identity, not explicit emitted override. Compiler return already labels enforcement NOT_PROVEN_G_SBX and its return correctly distinguishes intended semantics. Establish exact named-profile decoding/effective config and real primary/descendant canaries; do not interpret the digest label as enforcement.
3. **Blocking coverage gap — protected-path language is a strict subset.** Compiler rejects paths inside canonicalRoot and every glob. R16 N3.2 explicitly requires representative mid-path globs through read/file-change/shell-write representations for primary and descendants. Exact control-root denials are useful but cannot discharge full G-PROT. Record unsupported rule classes until implemented/empirically validated; no silent subset acceptance.
4. **Boundary review gap — trusted provider host configuration is not yet fully enumerated.** Native compiler explicitly trusts the project and supplies selected overrides while the provider host is unsandboxed. Disabling plugins/web_search is not evidence that all MCP/hooks/notification/custom-provider or other host-side process/network pathways are absent. Inspect exact loaded configuration sources and host-side tool inventory, enforce safe configuration ownership/isolation and demonstrate closed surfaces. No escape has been observed; this is an unverified surface, not a claim of vendor behavior.

Positive findings at this reading: native policy requires canonical disjoint project/private account paths; explicit enclosing control-root protection; denied control roots cannot overlap read grants; command network is emitted false; login shell false; scratch is inside the project; actor constructor freezes profile/digest and rejects caller override fields; profile is forwarded on start/resume/turn; supervisor checks compiled digest against trusted continuity and excludes its controlled launcher from production boundary verification.
