## Smallest useful no-account additions, in order

**P1 — read + environment, one primary/child pair.** Use the existing advertised exec tool and native spawn/wait mechanism; no new binary grant. Parent stages synthetic known-byte project file, separate foreign-root and broker sentinels, and project `.codex` sentinel. Each role executes exactly one bounded shell probe with STARTED/FINISHED; uses `/bin/cat` to require the project marker, records only boolean absence/denial and numeric exit for protected reads. Put a synthetic `CHIRALITY_AMBIENT_CANARY` in the *test harness ambient* environment before exact launcher creation; assert it and SSH_AUTH_SOCK/OPENAI_API_KEY are absent in actual action environment without dumping values. Verify `$PWD` canonical project, HOME/CODEX_HOME/TMPDIR against trusted intended paths or explicit documented absence (observe vendor filtering before choosing a requirement); never compare a fabricated desired environment to itself. Sentinel shell startup file attempts a marker write if executed; verify `login:false` leaves marker absent. Emit hashes/booleans and bounded safe paths, not account/ambient dumps. One primary+child profile target under30s, strict60s; each shell probe <=10s.

**P2 — process boundary, separate normal/cancel/timeout profiles.** Positive: actual tool starts a short foreground child and waits for its literal done marker. Negative: parent starts a disposable *owned* sibling process outside vendor lineage with a harmless SIGUSR1 handler and counter; parent baseline confirms handler readiness. Actual primary/native shell attempts that specific signal; require command start/end, denied return and sibling counter unchanged. Never target unrelated processes or infer denial from loader failure. Lifetime: primary then native child starts an owned background sleep with a ready marker; interrupt through actual Runtime API or force bounded test timeout; verify parent-tracked child process groups and observed descendants disappear. If leader exits while pipes/descendants remain, require cleanup/reconciliation rather than exit0 success. Do not signal PIDs merely reported by model text: cleanup authority comes from original fixture-owned group plus independently verified lineage; uncertain detached survivors => reconciliation failure. Use /bin tools already in profile; validate actual process identity before assertions. Three profiles at most60s each; every signal/lifetime probe <=10s and outer kill cleanup after8s. This does not prove all kernel process APIs or escaped-PID ownership.

**P3 — protected rules, four bounded profile families.** Reuse the compiler test's exact pattern grammar: `packages/*/private.env`, `secrets/**/*.key`, `env?.txt`, `config[ab].txt`. Each is a real named deny rule through compiler/digest/readback, never pre-expanded into today's files. Stage matching existing file, nonexistent matching target, and nearby nonmatching positive target. Both primary and native child attempt read, shell write and actual apply_patch against selected matches; require explicit failures, unchanged host hashes, nonexistent target still absent, and positive sibling creation/read. Include default `.codex` literal, an explicit in-project literal, broker root, and canonical project symlink pointing at foreign sentinel; alias reads/writes must not escape. For nonexistent matches, create the matching path *after* policy compile before action to prove dynamic matching. Test directory/ancestor traversal separately; do not treat returned config strings as matching proof. Keep one family/profile, <=60s; each individual shell/patch probe <=10s. Do not touch real immutable system leaves: use synthetic protected writable fixtures; their topology differs and must be labelled. Glob parser/action failures remain genuine gaps, no silent downgrade to explicit file lists.

**P4 — role parity, bounded public-path profiles.** Drive requested untyped/Agent0/Agent1/Agent2 and TASK alias through existing Runtime API/actual exact factory. ## Timing and evidence rules

Each profile explicitly measures wall-clock setup+work+cleanup and fails above60s; each action measures issuance-to-terminal/cancel and fails above10s. Setup/source hashing should be accounted for, not hidden. Keep a longer teardown watchdog only to clean failed runs; it cannot turn overruns into passes. Existing S/F had a210s test watchdog and no separate60/10 budget fields: prior pass cannot establish that requirement. New probes must emit result fields, actual method/role/lineage, source/supplier/policy hashes before+after, permission table, positive/negative outcome, tool start/end, and teardown facts. No generic all-limbs PASS aggregator from fixture success. Candidate identity/owner acceptance/account owner-live remain separate.
