# Operator sign-in component return

`CodexLogin` is a lazy single-use operator component: construction does nothing; startLogin requires trusted operator provenance, dedicated private home/executable paths, exact accepted supply verification plus immediate revalidation, and macOS containment before creating a separate login-purpose actor. Configuration pins file credential storage, disables plugin loading/login shells/updates/analytics/feedback. No model selection or model initialization occurs. Provider-enabled networking is permitted only through the trusted provenance configuration; that record is not itself an authentication mechanism and must never come from ordinary client request flags.

API: startLogin→loginId/authUrl; status→pending/completed/failed plus sanitized account presence and binding digest; cancel/close terminate bounded process lifecycle. The URL must use HTTPS with no credentials/nondefault port/fragment and exact auth.openai.com, accounts.openai.com or chatgpt.com hostname. URLs are returned only for the operator ceremony; no browser opens automatically. Login completion requires actual matching notification, successful account read and owner-private bounded regular auth.json with stable file identity. Raw account/token bytes are never returned. Credentials remain in persistent CODEX_HOME after close; only fresh containment scratch is cleaned. Binding reads are capped1MiB and identity-checked. Completion/failed polling closes the process; pending timeout defaults5minutes/max15minutes.

The actor's login purpose rejects all thread/model work. Unknown refresh/approval server requests still fail closed. Process exit0 never indicates login completion. Startup/close race is checked before initializing the actor. Controlled fixture entry is separately named and can emit only controlled-fixture evidence; no production supply acceptance is inferred from it.
