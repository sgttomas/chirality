## Contract-Gap Observations

Reported as canary findings. None blocked this run, because the brief explicitly ruled the conversion machinery out of scope for `MODE=INIT`; without that ruling the companion files would be ambiguous.

1. **`TOOL_POLICY.md` "Required order" steps 3–5 have no `INIT` branch.** Step 2 names all three modes explicitly ("`INIT` is source-grounded authoring and `VERIFY` is read-only"), but steps 3, 4, and 5 are then stated unconditionally over "the evidence candidate" — a `CONVERT`-only construct. Read literally, an `INIT` run is ordered to refine an evidence candidate that does not exist, then map and finalize it.
2. **The step-4/5 tools are structurally `CONVERT`-only, which is what makes the gap safe to resolve but should be stated.** `map_scope_of_work_claims.py` requires `--source-dir` and iterates `sow-source-begin` blocks; `report_scope_of_work_parity.py` and `finalize_scope_of_work.py` consume the same marker-bearing candidate. An `INIT` document has no markers and no legacy source directory, so steps 4–5 cannot execute at all. The policy should say so rather than leaving it to the caller's brief.
3. **Steps 6–7 say "the clean production candidate" without defining it for `INIT`.** In `INIT` there is exactly one document and it is clean by construction, so `{ScopePath}/ScopeOfWork.md` is the only possible referent — but the term is defined in §6 of the standard solely as the finalizer's output.
4. **`TOOL_POLICY.md` step 1 ("Read and hash the authoritative source kit and `_STATUS.md`") has no `INIT` meaning.** There is no "source kit" for a first authoring; the analogous act is reading and citing the accepted decomposition/ledger/PRD grounding. This run did the latter and hashed only the produced contract.
5. **`QA_CHECKS.md` is `CONVERT`-shaped throughout.** Checks 1–3, 5–7, 10–12, 14–15, and 17 presuppose four legacy sources, source markers, a finalizer pair, or `MIGRATION_DUAL`; check 3 additionally asserts `_STATUS.md` "remains `IN_PROGRESS`", which contradicts a legitimate `INIT` at `OPEN` and would fail a literal reading of an otherwise correct run. Checks 4, 8, 9, 13, 16, and 18 are the `INIT`-applicable subset and all pass.
6. **`SKILL.md` "Method" step 5 is unconditional** ("Run source mapping and parity on the evidence candidate, then use the deterministic finalizer…") even though step 2 has already branched on mode. Same defect class as observation 1, in the skill body rather than the tool policy.
7. **`BRIEF_SCHEMA.md` `ExpectedOutputs` is the one field that already handles `INIT` cleanly** ("Contract or verification result; **for conversion**, distinct evidence candidate…"). That conditional phrasing is the pattern the other companion files are missing.

Suggested remedy (for `HELPS_HUMANS`, not applied here): make the mode branch explicit in `TOOL_POLICY.md` steps 1 and 3–7 and in `SKILL.md` Method step 5, and split `QA_CHECKS.md` into a common set plus per-mode sets, with check 3's lifecycle assertion restated as "`_STATUS.md` is byte-identical and its state is unchanged".
