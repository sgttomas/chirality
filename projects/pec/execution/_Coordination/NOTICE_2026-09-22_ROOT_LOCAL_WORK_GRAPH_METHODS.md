# Local work graphs and bounded reconciliation

Root registers two bundled workflows in `chirality-root`:
`construct-local-work-graph` and `bounded-reconciliation`. The first develops
user intent from steering/chat, selects the relevant DAG route and builds
executable scope. The second reconciles a stable code slice with the affected
deliverable documents, preserving intended requirements and unresolved work.
It follows current Root claim-granularity guidance when that basis applies.

Root `AGENTS.md` now distinguishes updating a designated current-graph pointer
within an authorized undertaking from changing instructions. The pointer
itself grants no scope. Agent role definitions remain unchanged.

This is notice of new shared source and the Root navigation-pointer rule.
The receiving loop decides whether and when to adopt or package that source.
Its accepted instruction basis, current graph, product guidance and method
selection are unchanged here. No consumer re-pin, product rebuild or release
is performed by this notice.

The App/Piping development loops no longer require duplicate per-session
narratives, handoffs or new receipts when graph/results supply those facts.
Historical receipts and their integrity validators remain intact. Other
selected workflows keep their own output contracts. Attribution is retained
in available execution evidence, not deleted or assumed to exist in a database.

Authorization, affected paths and routing are in
`docs/governance_harness/tranche_manifests/ROOT-LOCAL-WORK-GRAPH-METHODS-20260922.yaml`
from the repository root. The implementation/review record is
`execution/_Coordination/LOCAL_WORK_GRAPH_METHODS_20260922.md`.
