## Production and Verification Method — Praxeology

Production proceeds in the order per-loop grammar table → declaration-driven
discovery → parser → limitation reporting → fixtures and tests, because each
stage is the acceptance surface of the next: a grammar written down before any
parsing code exists cannot have been retrofitted to whatever the code happened
to accept, which is what REQ-002 requires to be visible in the result. All work
is bounded to this deliverable folder, the `PKG-02` service-core source it names
and the fixture paths a ruled packet names; this contract authorizes no
register, decomposition, PRD, registry or upstream-deliverable edit, no v2
source write by itself, and it neither defines nor reshapes the record-tier
Receipt type it emits into. Tests implement the verification methods below and
create no scope.

- **VER-001** — Execute the parser over one fixture per covered loop and generation and assert that the applied grammar is the table's declared one and that every emitted Receipt names its loop, generation and grammar; then execute it over a surface the table does not cover and assert an uncovered report with no Receipt emitted.

- **VER-005** — Review the emitted payload field by field against the accepted `DEL-01-01` contract's Receipt obligations in force at review time, asserting no extra field, no dropped availability distinction and no record-tier type definition, and assert that marker-carrying, prose-structured and central-receipt outputs are distinguishable by inspection alone.

## Governing Values and Decisions — Axiology

- **AX-001** — `PEC-K-02` files govern. `LOOP_RECEIPTS.md` ledgers and central receipts are derivative accounts that their live sources override (CLM-022). The parser reads them, never rewrites them, and a parsed Receipt is never citable as authority over a receipt, a ledger, or the sources they defer to.
- **AX-002** — `PEC-ORI-006` coverage honesty governs, and it is why the register description ends "with stated limits". Two grammar generations across differently shaped loops guarantee uneven field availability, and several trial runs have no receipt at all; the value protected is that the unevenness and the absence are *stated* rather than smoothed. A parser that returned a tidy uniform Receipt across differently shaped sources would defeat `SOW-009` at the point where the information still existed.
- **AX-003** — `PEC-K-10` content-minimal is a residency posture, not a storage optimization. For a parser the strongest available enforcement is inexpressibility, which is why REQ-007 binds the emitted field shapes rather than the reading behaviour. CON-003 records the reading of *best-effort* this rests on, in the open.
- **AX-004** — `DL-4` makes this deliverable atomic, and `SOW-013` keeps central receipts in it with "DL-4 unchanged": one Receipt feed kind, one separately testable unit, its own grammars. Absorbing a sibling feed grammar, the Receipt type itself, the registry, the reconciler that ingests these entities, or the limitation-honesty surface that renders their gaps would undo it (REQ-018).
- **AX-005** — The edges cited here are `[E-P05]` (upstream, `DEL-01-01` → `DEL-02-03`, `PROPOSAL`), `[E-P21]` (downstream, `DEL-02-03` → `DEL-03-01`, `PROPOSAL`) and `[E-N03]` (downstream, `DEL-02-03` → `DEL-04-05`, `DECLARED`), each with an empty `Flag` in the exhibit. `D-PEC-62` recorded the DAG candidate v0.2 as "accepted, all strata as presented". Stratum is provenance, not authority: it records how an edge was derived, and citation converts no `PROPOSAL` into a `DECLARED` edge.

Upstream, `[E-P05]` makes the record-tier contract an input that types this parser's output; it transfers no schema authorship and no entity-model decision into this contract. The acts named in CLM-015 are cited here and discharged nowhere in this document.
