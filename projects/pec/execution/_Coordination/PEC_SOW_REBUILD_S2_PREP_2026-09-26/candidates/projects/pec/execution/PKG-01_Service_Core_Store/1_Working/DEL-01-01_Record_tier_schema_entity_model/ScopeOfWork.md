## Completion and Reliance Basis — Epistemology

The requirements below state what future production must satisfy. Nothing in
this section asserts that a schema, an entity type or a test exists.

- **REQ-001** — The schema and entity model shall define exactly the sixteen record-tier entity types named in CLM-005 — Loop, Workplan, Step, Gate, Receipt, DecisionRow, Fence, Package, Deliverable, DependencyEdge, RunRecord, CandidateBrief, OrientationSnapshot, DriftFinding, WorkGraph, WorkNode — with none added and none dropped, and each type shall carry a recorded trace to its `PRD.md` §7.1 row and stated purpose (CLM-006).
- **REQ-002** — The three compound §7.1 rows shall be decomposed exactly as the register records, each type carrying its row's purpose (CLM-006): (a) Workplan / Step / Gate as three distinct types of a declared historical-grammar entity, in which Workplan and Step index workplans as history only and Gate carries gate state re-sourced from decision registers, scope-change pointers and work-graph `BLOCKED` nodes, with no field populated from `LOOP_INIT.md` (CON-007); (b) Package / Deliverable as two distinct types carrying the lifecycle census from `_STATUS.md` (`OPEN`→`ISSUED`) and stuck-age, requiring no remaining-items value for any deliverable (CON-004); and (c) WorkGraph / WorkNode as two distinct types able to hold the content-minimal set the §7.1 row enumerates — declared run-identity token, node IDs, closed-vocabulary node states, DEL bindings, PR numbers, hex SHAs, linked paths and per-state counts — and no graph prose, in which a node state is represented as declared activity at its cited commit and never as a liveness or completion claim.
- **REQ-003** — Every record-tier entity type shall carry provenance sufficient for a per-claim citation to its live source — file path, anchor, and/or SHA, per `PEC-ORI-004` — because §7.1 defines the tier as "citable with sources". The act of attaching citations to an orientation response is `DEL-04-03`'s under `SOW-007` (CLM-012); this requirement obliges the model to hold what that act needs, and no more.
- **REQ-004** — The model shall represent examined-through SHA provenance structurally, so that staleness is a comparison and never a judgment (`PEC-K-04`, `OBJ-002`): OrientationSnapshot shall be stamped with the examined SHA, and two successive snapshots shall be comparable field by field such that a DriftFinding can record a classified difference. ## Production and Verification Method — Praxeology

Production proceeds in the order entity types → persistence schema → tests,
because that order is what REQ-009 requires to be visible in the result: types
authored before any persistence exists cannot have acquired a dependency on
it. The sixteen types are enumerated from CLM-005 and grounded row by row
against the §7.1 table of CLM-006 before any field is designed, so that
REQ-001 is satisfied by construction rather than audited afterwards. All work
is bounded to this deliverable folder and the `PKG-01` service-core source a
ruled packet names; this contract authorizes no register, decomposition, PRD,
registry or upstream-deliverable edit, and no v2 source write by itself
(constraint `C14`). Tests implement the verification methods below and create
no scope.

- **VER-001** — Inventory check: enumerate the delivered types and diff them against the sixteen names of CLM-005 and the twelve rows of CLM-006, asserting the recorded per-type trace, the compound-row decomposition of REQ-002, the absence of any Gate field sourced from `LOOP_INIT.md`, the absence of a required remaining-items value, and WorkNode's declared-activity representation.
- **VER-002** — Provenance resolution: for a sample instance of each type, resolve the recorded citation provenance to a live file source and assert that path, anchor, and/or SHA are present and locatable.
- **VER-003** — Snapshot comparison exercise: build two OrientationSnapshots over different source states, compare them structurally, and assert that the difference is expressible as a DriftFinding with no judgment input. The exercise is read-only over sources; it performs no reconciliation act owned by `DEL-03-02` or `DEL-03-03`.
- **VER-004** — Rebuild-and-compare: regenerate the record tier from the same fixture sources and assert instance-level reproduction, then inspect the field inventory for any state the rebuild cannot reproduce.
- **VER-005** — Tier-boundary and RunRecord inspection: assert no presence-tier type is present; represent RunRecords from a central-receipt, a work-graph, a `MEMORY.md` run-index and a JSON run-evidence fixture and assert each contribution's provenance; attempt to represent Runtime service user-data state as a RunRecord and assert that the model rejects it.
- **VER-006** — Content-minimal type inspection: review every field's type for capacity to hold file or diff content or prose, and attempt to express a fixture carrying file content, diff hunks, register-row prose, work-graph outcome text and a run description, asserting that it cannot be expressed.
- **VER-007** — Receipt availability review: model the `receipt-contract-v2` field set, a ledger without the marker and a central `RECEIPT.md` shape against the Receipt type, with live and historical ledger labels, and assert that per-loop and per-grammar availability is readable from the model and that no shape is privileged by construction.
- **VER-008** — Seam inspection: inspect the import and dependency graph between the entity types and any persistence module, asserting one-way dependency, and run a classification exercise in which a reviewer sorts candidate `PKG-01` changes into core and adapter using the delivered structure alone.
- **VER-009** — Dependency and locality inspection: review the service-core dependency manifest and the model's import graph for third-party runtime dependencies and network calls; re-run the `DEL-01-05` enforcement once available, without discharging it here.
- **VER-010** — Slice review: compare the delivered artifact structure against the envelope record of CLM-007, asserting either a single cohesive slice or a split along the recorded line with its seam evidence recorded.
- **VER-011** — Consumability and write-scope check: confirm that the published schema and types could be referenced as dependency inputs by the twelve active consumers of CLM-010 without republication, and that the change set touches no path outside `PKG-01`.
- **VER-012** — Test-run mapping: run the service-core test suite and confirm that each of VER-001 through VER-011 and VER-013 through VER-016 has a corresponding executing automated test and that no test asserts a criterion absent from this contract.
- **VER-013** — Boundary inspection: inspect the change set and the model's call surface for any feed parsing, response stamping, orientation or gate derivation, limitation rendering, reconciliation, store lifecycle, guard, registry or enforcement logic, or presence-tier type, asserting none.
- **VER-014** — Generation-label and limitation exercise: represent one instance from a live-profile fixture, one from a declared-historical fixture and one with a field the fixture withholds, and assert the labels and the explicit unobtained-field record.
- **VER-015** — Loop field review: enumerate the Loop type's fields and assert that each is loop identity, entrypoint, procedure SHA or registry listing, with no step, gate or execution-state field.

## Governing Values and Decisions — Axiology

- **AX-001** — `OBJ-001` governs: orientation is a sub-second query with per-claim citations. Entities in this tier exist in order to be cited, so provenance is a structural property of the model rather than a downstream decoration. A type that cannot say where it came from cannot serve a cited orientation, whatever else it holds.
- **AX-002** — `OBJ-002` governs: staleness is detected structurally by SHA comparison, never by judgment. The schema is where that is made possible or impossible; a field that requires interpretation to compare converts a structural check into a judgment call and defeats the objective at its foundation.
- **AX-003** — `PEC-K-05` governs the tier boundary: two trust tiers, never blurred, and "Presence facts never enter record-tier citations". The boundary is enforced here by what the schema is unable to express, not by convention downstream.
- **AX-004** — `PEC-K-02` governs status: files govern, and the record tier is a projection regenerated from sources. This schema is never an alternative source of truth, and `PEC-K-08` extends the same discipline to derivation — "Every status, verdict, and warning carries rule ID, threshold, and contributing cited sources. Drill-down never dead-ends" — which is only achievable if the model carries the sources to drill into.
- **AX-005** — `PEC-K-10` content-minimal is a residency posture, not a storage optimization. The strongest available enforcement for a data model is inexpressibility, which is why REQ-007 binds field shape rather than ingest behaviour; the ingest-side guard is `DEL-01-03`'s.
- **AX-007** — `C-10` `STRATUM_RULE` is a register-wide, non-gating constraint recorded in `_DEPENDENCIES.md`, whose text ends "strata are provenance not authority". Every edge cited here — the upstream `[E-P01]`, the twelve active downstream edges of CLM-010 and the retired `[E-P14]` — is `PROPOSAL` stratum with `Flag=none`; `[E-P79]` and `[E-P80]` were seeded under `D-PEC-93`. Citation converts no `PROPOSAL` into a `DECLARED` edge, and no edge is read as an obligation on another deliverable. Blocker output under `FULL_GRAPH` at threshold `INITIALIZED` is advisory visibility only and never work assignment.
- **AX-008** — Edge direction is respected in both directions. Upstream, `[E-P01]` makes `DEL-00-01`'s contract an input that shapes this deliverable's seam; it does not transfer ADR authoring, the core-isolation decision or ADR acceptance into this contract. Downstream, the consumer edges make this model an input to other deliverables; they impose no duty on those consumers and grant this contract no authority over them. The acts named in CLM-012 are cited here and discharged nowhere in this contract.
- **AX-009** — Unknowns stay marked. TBD-001 through TBD-005 and CON-001 through CON-007 are recorded rather than resolved by inference; a production choice that settled one of them would be a decision taken in the wrong place.
- **AX-010** — This contract is lifecycle-neutral. `_STATUS.md` remains the sole lifecycle authority and is untouched by the run that authored this document; the deliverable is at `INITIALIZED` and nothing has been built.
- **AX-011** — Rebuild provenance. This contract rebuilds, as a whole, the prior contract with SHA-256 `43f1f57a13bb96b3235bbbb460342bd03518c503f23cb8b0560914f27a2f0170`, under the S2 Scope of Work rebuild packet (provisional `D-PEC-100`), authored from revision 1.6 and PRD v2.4 (SCA-005 `Propagation_Plan.md` §B4: `STALE_REBUILD_REQUIRED`). Retired: the prior contract's `DEL-01-01/AX-006`, its revision-1.2 basis statement with its `_REFERENCES.md` note, which no longer holds. Every other prior ID is kept with its meaning, restated against current sources where they changed: REQ-006 keeps its subject — the tier boundary and what RunRecord admits — and now states the PRD v2.4 rule, under which RunRecord is no longer limited to JSON run evidence; REQ-008 and AC-007 keep per-loop Receipt availability, now per grammar and against the `receipt-contract-v2` marker in place of the `D-APP-57` field set; CLM-006 carries the current §7.1 table, including the DependencyEdge purpose cell; REQ-001, REQ-002, REQ-012 and their criteria now count sixteen types, three compound rows and twelve active consumers; REQ-009 keeps the seam but no longer asks for validity under both candidate styles, and CON-001 keeps the core-isolation item, now recording the `D-PEC-72` ruling. New: CLM-014 to CLM-017, TBD-003 to TBD-005, REQ-014 to REQ-017, AC-013 to AC-017, VER-013 to VER-016, CON-003 to CON-007, and AX-011 to AX-013.
- **AX-012** — A feed profile is PEC's reading hypothesis, never the loop's truth (PRD §16.3: "a profile is PEC's reading hypothesis, never the loop's truth"). The model may record which generation a fact came from (REQ-015) but never turns a profile declaration into a record-tier claim about the loop (REQ-016, TBD-005).
- **AX-013** — Declared activity is not liveness, and historical silence is not staleness. A work-graph node state records what a graph declared at a commit, and a frozen generation's silence is its nature, not a gap (CLM-015); modelling either as a live signal would make orientation report finished work as active or history as stale (REQ-002, REQ-015).
