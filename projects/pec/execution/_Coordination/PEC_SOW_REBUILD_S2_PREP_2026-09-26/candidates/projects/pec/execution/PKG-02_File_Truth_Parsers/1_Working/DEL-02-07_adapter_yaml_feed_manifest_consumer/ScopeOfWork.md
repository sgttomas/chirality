## Deliverable Definition — Ontology

`DEL-02-07` is typed `BACKEND_FEATURE_SLICE` at Context Envelope `S` with
`PhaseHint` `P1`. Its `AnticipatedArtifacts` field reads "Manifest reader +
fixture tests" and its `ContextEnvelopeNotes` field is empty. The two outputs
below are that list and nothing beyond it.

## Production and Verification Method — Praxeology

Production proceeds in the order grammar declaration and YAML approach →
loop-to-project resolution under CON-002 → loop-set acquisition through the
port → population comparison → finding emission and limitation reporting →
fixtures and tests. A grammar declared before code exists cannot have been
fitted to whatever the code happened to accept (REQ-009). All work is bounded
to this deliverable folder, the `PKG-02` service-core source and the fixture
paths a ruled packet names; this contract authorizes no register,
decomposition, PRD, registry, harness, `software-workflow.json` or
upstream-deliverable edit, and no v2 source write by itself. Production waits
for the gates of CLM-016. Tests implement the verification methods below and
create no scope.

- **VER-001** — Execute the reader over a valid fixture manifest and assert that the yielded field values equal the fixture's declared expectation; compare the set of fields actually read, by instrumentation or code inspection, against the documented grammar; mutate an undeclared field and assert output invariance.
- **VER-002** — Inspect the reader's loop-set acquisition path and assert that it calls only the `LoopRegistry` port; search this deliverable's source and fixtures for any registry path, filename or serialization token and assert that none is present.
- **VER-003** — Execute the reader against absent, unreadable, malformed and schema-invalid manifest fixtures and against a fixture with an unobtainable population; assert, per case, an explicit limitation naming the project and the fault, the missing-peer outcome for the absent manifest, and no empty, partial or defaulted result.
- **VER-004** — Hash the fixture repository's objects, refs, index and worktree before and after a reader run and assert byte-identity; inspect the module's call graph for write, create, delete or ref-updating operations against any source path.
- **VER-005** — Inspect the `PKG-02` dependency manifest and this module's import graph for third-party runtime dependencies and network calls, and re-run the `DEL-01-05` zero-dependency and locality enforcement once that deliverable is available, without discharging it here.
- **VER-006** — Inspect the reader's emitted payload for a fixture project whose population paths name files with distinctive content, and assert field by field that it contains only declared manifest-derived fields and population paths and counts, with no file content and no undeclared manifest content.
- **VER-007** — Run the `PKG-02` test suite and confirm that each of VER-001 through VER-006, VER-009, VER-010, VER-011 and VER-014 has a corresponding executing automated test and that no test asserts a criterion absent from this contract; VER-008, VER-012, VER-013 and VER-015 are recorded inspections and are checked for their records instead.
- **VER-008** — Inspect the commit history of the production branch and assert that the grammar and YAML-approach artifact is committed before the first reader source, and that it names every field the reader reads.
- **VER-009** — Execute the comparison over an agreeing fixture and over fixtures seeded with a PEC-only path and a manifest-only path; assert agreement with no finding, and divergence naming each one-sided path; assert that the PEC-side population is supplied only through the interface fixed under CON-003.
- **VER-010** — Mutate each manifest field in turn, including `status_glob`, and assert that no feed selection, feed locator or grammar choice changes and that the reader's output contains no feed locator or selection.
- **VER-011** — Inspect each emitted divergence for project, manifest path and blob SHA, examined commit, population sources and grammar identifier; search this deliverable's source for record-tier type definitions, added upstream fields and persistence calls, asserting none.
- **VER-012** — Inspect the production packet and source for the recorded loop-to-project resolution and its accepted-evidence citation or owner ruling, and search the source for any derivation of the relation from `loop_init_path`, another path or file presence.
- **VER-013** — Inspect the module's file access and call surface for any of the excluded acts of REQ-014, including any harness invocation or read of harness-generated output.

- **VER-015** — Inspect `projects/pec/software-workflow.json` after the ruled production packet's act and assert that it registers the fixture suite as that packet's check, in the form the packet names.
