Production proceeds in the order grammar declarations → registry-driven
discovery → LOOP_INIT field extraction → historical workplan indexing → limitation
reporting → fixtures and tests. Each stage is the acceptance surface of the
next, and a grammar declared before code exists cannot have been fitted to
whatever the code happened to accept. All work is bounded to this deliverable
folder, the `PKG-02` service-core source and the fixture paths a ruled packet
names; this contract authorizes no register, decomposition, PRD, registry or
upstream-deliverable edit, and no v2 source write by itself. Tests implement
the verification methods below and create no scope.

## Governing Values and Decisions — Axiology

- **AX-001** — `OBJ-001` governs: orientation is a sub-second query with per-claim citations. `PEC-ORI-004` requires every claim to carry a citation to its live source, so a loop identity or procedure SHA that cannot say which file, blob and commit it came from cannot serve a cited orientation; provenance is therefore a property of what this parser emits (REQ-006) rather than a decoration added downstream.
- **AX-002** — `OBJ-002` governs indirectly, through the record tier. The procedure SHA is a fact the SHA comparison operates over; this parser does not perform that comparison, and no requirement here may be read as claiming otherwise. Its contribution is that its output is deterministic and regenerable (REQ-010), so a difference between two reconciles is a structural difference and never a judgment.
- **AX-003** — `PEC-K-06` observation, not participation, governs this feed. A `LOOP_INIT.md` is a loop's own instruction surface; PEC may report its identity, entrypoint and digest and may not advance, satisfy or infer anything the loop decides. `PEC-GAT-004`'s prohibition on any adoption, ruling or direction write path is absolute across PEC, and REQ-004 keeps this parser well inside it by reading no gate state at all.
- **AX-004** — `PEC-K-08` explainability is why gate evaluation lives in `PKG-05` and gate serving in `PKG-04`, not here. An Explain-shaped verdict needs a rule, a threshold and contributing citations over current sources; a token copied from a retired plan supplies none of those and would mislead if it were read as one (CLM-012).
- **AX-005** — `PEC-K-10` content-minimal is a residency posture, not a storage optimization, and both inputs of this feed are instruction prose with no machine-readable shape (CLM-015). The strongest available enforcement is emitting facts that have nowhere to put prose (REQ-009); the ingest-side guard is `DEL-01-03`'s.
- **AX-006** — `PEC-K-02` files govern. A `LOOP_INIT.md` and a workplan are authored loop truth, and PEC's parse of them is a projection, regenerable and never citable as authority over the file itself. `PEC-RCN-004` and `PEC-RCN-006` make the read-only posture a rule rather than a habit (REQ-008).
- **AX-007** — `PEC-K-01` graceful absence governs: no governed act may require a PEC read or write. A loop whose `LOOP_INIT.md` is missing at its `loop_init_path`, or whose row declares no workplan surface, is a stated coverage limitation, never a blocked act and never a silent gap (REQ-007, REQ-014).
