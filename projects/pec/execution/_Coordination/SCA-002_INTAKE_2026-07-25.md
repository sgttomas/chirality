## §5 Hard constraints (present at Gate 3 with the amendment text)

1. **Register token/separator convention.** `ObjectiveIDs` /
   `SupportsObjectives` cells keep the register-native convention: bare
   `OBJ-NNN` tokens, `;`-separated when multiple (e.g. the existing
   `OBJ-001;OBJ-002` cells). No qualified tokens (e.g.
   `OBJ-001(indirect)`) — any indirect/qualified attribution lives in a
   separate column, §3 mapping notes, or the amendment record, never
   inside the token. **Accurate mechanism note (R-2a/R-2b corrected):**
   the SOW validator imposes no format regex on frontmatter objective
   refs (only non-emptiness, `common.py:213-215`); the matrix check
   (`common.py:266-267`, union built at `:251-253`) splits matrix cells
   on comma/whitespace only. The binding conversion rule therefore sits
   in **brief construction** (D-PEC-63 §3 template): PROJECT_SETUP
   splits register cells on `;` and emits `PACKAGE_OBJECTIVE_REFS` as an
   inline YAML list of bare tokens — a `;`-joined cell copied verbatim
   would silently become one unusable token. Bare tokens in the
   registers are required so that this split yields validator-legal
   tokens; qualified tokens would survive the validator in some paths
   but break the mixed frontmatter/matrix case and downstream tooling.
   **Owner-awareness flag:** this is a downstream consumer's parser
   shaping the representation of authoritative truth; since the
   constraint coincides with the register-native convention already in
   use, no representation change is being forced — but the inversion is
   surfaced rather than assumed.
2. **No topology change; IDs append-only (I5).** MODIFY-class metadata
   amendment only.
3. **OUT/TBD rows untouched.** Their empty mapping is by design and out
   of scope.
4. **Intentionally-unmapped class (Gate 1 scope ruling needed):** §3's
   **Mapping notes** (SOFTWARE_DECOMP.md:333-336) record that
   ingest/bridge items "serve OBJ-001/OBJ-003 freshness indirectly
   through PEC-K-07 and are intentionally not force-mapped" — of that
   ingest/bridge range, **SOW-033..038 are the unmapped members**
   (SOW-039 is already mapped to OBJ-003). Revision log **DL-14**
   separately records "SOW-063 left unmapped intentionally (instruments
   PEC-K-07, which no §3 objective states)". The unmapped deliverables
   this class lands on — DEL-00-02, DEL-03-05, DEL-07-02..04, DEL-10-08
   — are all **out-of-wave** (DEL-07-01 receives SOW-033 but is already
   mapped via SOW-039). Mapping this class would supersede recorded
   design rationale in §3 mapping notes + DL-14 — an explicit owner act
   at Gate 3, with the amendment text editing the §3 notes themselves —
   see §7 options.
5. **Supersession posture:** §7's best-effort metric (full quote in §3
   above) and §3's best-effort framing are superseded to the extent
   Gate 3 approves. Gate 2/3 must rule whether a **`Supersession_Delta.csv`**
   binding is owed for the superseded posture (the cumulative
   `Supersession_Map.csv` is never hand-merged), and the revision
   history (Decision Log + Revision table) gains the SCA-002 entry.
