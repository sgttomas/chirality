The run completed; these are the canary findings. None blocked authoring,
because `TOOL_POLICY.md` step 2 itself states that `INIT` is source-grounded
authoring, and `docs/DELIVERABLE_SCOPE_OF_WORK_STANDARD.md` §2 and §6 scope the
finalization machinery to conversion. The gap is that the companion files then
continue in conversion-only vocabulary without restating the `INIT` branch.

1. `TOOL_POLICY.md` step 1 — "Read and hash the authoritative source kit and
   `_STATUS.md`." "Source kit" is the four legacy documents. `INIT` has no
   source kit; it has a decomposition basis, a scope ledger row, a product
   requirement, and control files. Satisfied by analogy (hashes recorded
   above); the clause does not say so.
2. `TOOL_POLICY.md` steps 3–5 — "Refine the evidence candidate…", "Run
   `map_scope_of_work_claims.py` and `report_scope_of_work_parity.py`…", "Run
   `finalize_scope_of_work.py` into a distinct production-candidate path…".
   These have no `INIT` antecedent: no evidence candidate exists, and the three
   tools bind conversion artifacts. Treated as non-applicable rather than
   improvised.
3. `TOOL_POLICY.md` steps 6–7 — "against the clean production candidate" /
   "against the clean production SOW". Under `INIT` the authored
   `ScopeOfWork.md` is the production contract directly; "clean" carries the
   conversion sense of "no residual migration markers", which is vacuously true
   for `INIT`. Read that way and executed.
4. `QA_CHECKS.md` items 1–3, 5–7, 10–12, 14, 17 are conversion-only and cannot
   be evaluated for `INIT`. Item 2 ("All four source files exist…") is false by
   construction here. Item 3 is the sharpest mismatch: it asserts `_STATUS.md`
   "is byte-identical and **remains `IN_PROGRESS`**", but a Phase 2.2 `INIT`
   deliverable is at `OPEN`. The byte-identical half holds; the `IN_PROGRESS`
   half is wrong for the `INIT` branch and would fail a literal QA reading of a
   correct run.
5. `BRIEF_SCHEMA.md` write boundary lists only conversion-shaped targets ("an
   evidence-candidate `ScopeOfWork.md` in the isolated conversion workspace",
   "a separate clean production-candidate `ScopeOfWork.md`…"). A first-authored
   `INIT` production `ScopeOfWork.md` at the deliverable root is not named. The
   brief's explicit `AllowedWriteTargets` fence supplied the authority; the
   skill's own boundary text does not.
6. `SKILL.md` "Method" steps 5–7 and the "Return" contract likewise assume the
   finalizer/claim-map/parity chain. Step 7's required return fields (source /
   evidence / production hashes, finalization report, claim map, parity report)
