## Source-supported causal chain

1. `PipeViewport.tsx:3496–3499` uses `shortEntityToken`: it splits on `:` and returns the last nonempty component. A001 has no colon and is passed intact, matching the DOM. This is not string shortening to A0 or an identity mismatch.
2. `styles.css:1370–1392` gives the button fixed width 58px, horizontal padding 5px each, border 1px, inline-flex layout, 4px gap and 11px/700 text. Global `box-sizing:border-box` is at `:41–43`. `ViewportTargetIcon` at `PipeViewport.tsx:3460–3463` requests a 13px icon. Icon, gap, borders and padding share the finite internal width with the text.
3. The selected-button rule `styles.css:3443–3445` adds a 3px inline-start border, while fixed border-box width stays 58px. It therefore consumes two more CSS px inside a selected plate than the base 1px border. Ordinary flex sizing/shrink can distribute the remaining width. This is a concrete contributing mechanism for the observed selected A001 constraint, not yet a measured attribution of the exact 29/28 values. The global comfortable-density min-height at `:3479–3480` explains why a specified 26px height can measure 32px; the placement code uses the actual box, not the nominal 26px declaration.
4. `styles.css:1406–1411` explicitly applies `min-width:0; overflow:hidden; text-overflow:ellipsis; white-space:nowrap` to the span. That is implementation intent to shrink and clip/ellipsize content within the span. It is not proof that a governing product decision accepts every loss of inline identity. Exact glyph choice, ink and rounding depend on the resolved font, flex layout and renderer.
5. `PipeViewport.tsx:1379–1384` measures the button's actual `getBoundingClientRect()` width/height. `labelPlacement.ts` places and collides that measured rectangle. It does not measure untruncated text, tooltip, shadow or focus outline. CSS shadows/active outlines can extend outside a border box by design; this failure concerns span text and supplies no new shadow/outline collision evidence. The existing clipping rule is why intrinsic span text overflow does not on its own invalidate the measured-plate collision dimensions.
6. `PipeViewport.tsx:2432,2458,2462` separately supplies an aria label, title with full label and raw ID, and short token text. For this fixture label=ID=A001, so both semantic name and title carry A001. In general the aria name uses the authored label rather than always including the raw ID; the title includes the raw ID. Do not generalize this trial into proof that every full raw ID appears in every accessible name.

High confidence: the full string reaches the DOM; selected A001 exceeds its span's reported client width; the source deliberately clips/ellipsizes it; full A001 survives in the recorded semantic attributes. Moderate confidence: fixed internal width plus selected border is a contributor. Diagnostic06 establishes fractional span/range widths and actual visible ellipsis; it fails full inline identity readability. Still not isolated: resolved font face, icon width and whether the selected border is the decisive threshold. Font fallback/flex rounding remain contributors to that threshold; they do not overturn the observed clipping. Coordinate coincidence is irrelevant to this text-width mechanism; the same content/layout could encounter it in another model.
