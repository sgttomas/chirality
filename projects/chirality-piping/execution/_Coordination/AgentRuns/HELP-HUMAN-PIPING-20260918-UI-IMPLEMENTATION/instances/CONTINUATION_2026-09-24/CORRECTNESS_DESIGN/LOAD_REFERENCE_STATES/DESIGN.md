Design handoff by `/root/load_state_design`, HELPS_HUMANS, delegated-harness-native child of ROOT. Scope: M10, M16, M21, M29 and their M15 interface. This is a prospective design, not an implemented or verified product capability. `P/` denotes `projects/chirality-piping/`; `C/` denotes the parent continuation directory. The owner delegates physics/method design while retaining user ownership of material/component data and code rules. [Owner direction](../../OWNER_PHYSICS_AUTHORITY_2026-09-25.md) supplies that authority; this proposal adds no owner checkpoint for ordinary engineering selection.

## Outcome and present basis

An analysis case must identify the actual configuration being solved: element temperatures and constitutive properties, natural strain, support positions/laws, physical loads, fluid/mass state and any genuine predecessor history. A name such as Operating, Hydrotest or Cold Spring is a label, not an instruction to invent these inputs. Build a small case-resolution layer around existing element, boundary, pressure, mass and result machinery. Do not introduce a second solver or general workflow engine.

## 1. Resolve a complete physical case before assembly

Add one explicit `analysis_state` object to an authored load case under a new closed contract, provisionally `piping.load_reference_state/v1`. ROOT allocates final model/result versions before source freeze. Existing cases remain on their actual legacy/profile interpretation until an explicit reviewed migration. Never infer new semantics from a field merely having a familiar name. Unknown versions/fields must not be silently discarded.

A compact authoring shape is:

```text
analysis_state {
  contract,
  reference_configuration_ref,
  element_states: [{pipe_ref, operating_temperature, material_selection,
                    expansion_law_ref, mass_state_ref}],
  support_states: [{support_ref, participation, motion?, device_state?}],
  load_sources: [{source_ref, factor}],
  history: {kind: independent_equilibrium}
        | {kind: continuation, predecessor_case_ref, predecessor_state_hash,
           segments: [...]},
  provenance
}
```

`reference_configurations` is a small model collection containing named geometry identity, each member's explicit stress-free/installation temperature, and optional declared natural-length mismatch. It is not a saved solved state. Material laws remain user-owned material records. Mass states name explicit pipe/fluid/insulation inputs, with purpose-specific section references from M30. Existing `primitive_loads`, pressure regions and support records remain their storage owners; `load_sources` references stable authored IDs rather than copying or nesting solved cases. In the new contract this list is the complete inclusion list for scalable ordinary applied loads, including any locally stored primitives; there is no second implicit application of the owning case’s array. Pressure, eigenstrain and device actions enter only through their resolved state owners and are echoed in the same ledger. Authoring initializes explicit references when migrating old cases, previews omissions, and never treats a valid unreferenced stored primitive as an applied force.

Authoring may use an explicitly chosen case-wide default plus per-member overrides. Resolve it into exactly one record per active element, retaining which input supplied each value. Duplicate/overlapping declarations, unknown elements, missing coverage and ambiguous precedence block solving. Do not implement array-order-wins. Support coverage is similarly complete: an explicit `use_model_device` declaration can apply to a named set, but omission is not permission to silently lock or remove a support. IDs and resolved entity lists persist with the case.

The internal `ResolvedAnalysisCase` is the single source for assembly and evidence:

```text
case/model/reference identities;
per element: source material + selection, E/nu/derived G, actual operating T,
             material-selection T (when defined), T_install,
             expansion definition/datum, normalized thermal and fit strains,
             stiffness/physical-pressure/mass/stress section basis IDs;
per support DOF: selected device law, actual constraint/base position,
                 enabled/replaced state and explicit preload/reference;
physical contribution ledger: stable source ID, participation, factor,
                              external/eigen/device classification;
selected mass generation receipts and history state identity.
```

Keep per-element selection keyed by `(case_id, pipe_id)`. Material IDs remain real user identities: do not synthesize duplicate material records just to work around a map. Refactor the current material resolver into a pure selection function used for each element; build each element with its resolved constitutive values. Within homogeneous isotropic E/nu mode, derive G from the same selected pair. Rebuild stiffness and support boundary per case; never reuse a cached matrix under an unchanged case label when those inputs change. Cache keys include actual consumed normalized inputs and method/profile versions.

## 2. Prescribed support motion (M10)

Accept actual displacement/rotation values at an identified physical support and global DOF. First wire the existing UI primitive `category=imposed_displacement`, support target and UX/UY/UZ/RX/RY/RZ tokens into the new case resolver; normalize lengths to m, rotations to rad. Retain load/source ID, support ID, case and sign. It becomes a boundary input, never an ordinary force-vector entry or a scalable ordinary load-source term. A reviewed migration moves its meaning into the per-support case boundary record while retaining the original source ID; simultaneous legacy and new prescriptions for the same device DOF block rather than adding or silently choosing one.

For a rigid or explicitly prescribed DOF use `u_c = g_c`, absolute relative to the declared reference geometry. Compile to the existing boundary preparation and nonzero reduction:

`K_ff u_f = f_f - K_fc g_c`; reconstruct complete `u`; recover constraint actions from the original unreduced equilibrium including actual mechanical/eigen/device terms. All-fixed systems still have a valid zero-size free problem and nontrivial reactions. Numerical source retention, source-recovery admissibility and original-equation residual checks must carry the actual prescribed map and coupling. A method lacking that coverage returns an explicit unsupported-method result, not implicit zero motion.

For a spring, support-base movement is a different field and law: support-on-pipe action `F = F0 - k (u - g - u0)` in its defined direction, with dimensions N or N*m. `g` is actual case base motion; `u0` is a declared installed reference offset; `F0` is declared preload at that reference. The same datum must not be specified twice through both preload and an equivalent offset unless the user intentionally defines both independent contributions. First implementation can require one of preload-at-reference or unloaded-reference offset for a scalar spring. Do not convert base motion into a rigid constraint or into an arbitrarily stiff spring. Devices with missing reference/preload data remain incomplete rather than adopting another hanger field by name.

A motion on an existing rigid support replaces that DOF's zero prescribed value in the resolved case; it does not add a second competing support. Different supports claiming the same constrained DOF remain an attribution/conflict issue and must not be silently merged even when numbers match. Motion on an unrestrained support DOF requires explicit creation/activation of a prescription. An imposed translation with angle units, rotation with length units, unknown support or nonlinear DOF without a defined base-motion law blocks. Explicit zero is distinct from absent. General local/skew and connected-node constraints remain M19 work; avoid implying they are supplied by adding global prescriptions. Small rotations follow the present frame formulation; this does not authorize finite rotations by vector addition.

## 3. Temperature, expansion definitions and material state (M16)

Keep three temperatures distinct: operating `T`, element stress-free/installation `T_install`, and coefficient-data datum `T_m`. The temperature selecting E and nu is the actual operating temperature unless the user explicitly chooses an alternate analysis material basis; that exception is labelled and echoed. Keep actual operating temperature and material-selection temperature in distinct evidence fields, including when an interval-strain route is used. A selected property point is not a source for an unentered actual operating temperature. A later stress-range reference modulus is a separate evaluation choice and never changes the already solved stiffness or reactions. No ambient value or alpha value is inferred.

The safest common thermal carrier is a free-length function `lambda(T)=L_free(T)/L_free(T_m)`. Resolve user data to `lambda`, requiring positive finite lengths, explicit absolute temperatures, source/interpolation identity and full interval coverage. Then for an uncut member whose reference geometry is stress free at `T_install`, use `epsilon_th = lambda(T)/lambda(T_install) - 1`. Use stable difference/ratio evaluation near unity; do not manufacture a loss of accuracy by subtracting two rounded long lengths. This is an input reference transformation, not a finite-deformation claim: the current frame still uses small-strain kinematics, undeformed axes/sections and linear elasticity.

Closed input definitions, all explicit user data:

| Definition | Conversion to free length | Required distinction |
|---|---|---|
| Engineering dilation table | `lambda=1+d(T)`, `d(T_m)=0` | d is fractional length change referred to length at T_m. Piecewise-linear d is a declared interpolation. |
| Mean/secant coefficient table | `lambda=1+alpha_sec(T)*(T-T_m)` | Interpolate alpha as declared, then form dilation. `alpha_sec(T)*(T-T_install)` is wrong when the two reference temperatures differ. Constant engineering alpha is this form with a constant value. |
| Differential coefficient per datum length | `lambda=1+integral[a_ref(t) dt, T_m..T]` | `a_ref=(1/L(T_m))*dL/dT`; integrate piecewise-linear input exactly interval by interval. |
| Instantaneous coefficient per current length | `lambda=exp(integral[a_log(t) dt, T_m..T])` | `a_log=(1/L(T))*dL/dT`; use expm1 for strain. This definition must not be silently treated as the preceding form. |

These definitions deliberately avoid the ambiguous word “tangent” alone. Preserve raw user values and the declared definition. Cover both integration endpoints and all intervening brackets; no extrapolation, hidden constant tails or fallback to base alpha. Exact table endpoints are valid when explicitly present; the new resolver may admit them directly rather than perpetuate legacy strict-interior interpolation. Duplicate temperatures and nonfinite/nonpositive stretches block. Mechanical E/nu selection needs only its selected point/bracket, but thermal integration may need the entire interval. Also retain an explicit `constant_alpha_interval` input with user alpha, declared constant-coefficient meaning, deltaT and an explicit applicable material selection. It needs no invented absolute temperatures where fixed material data and that interval suffice; its evidence records those actual inputs. Absolute temperatures become necessary when temperature-dependent properties/free-length data are requested. This direct interval denotes engineering strain for that entered interval. A user-entered total thermal strain for a named interval can be a separate explicit direct input; never combine it with a temperature-generated strain on the same member without intentionally adding distinct sources.

Legacy `alpha * deltaT` retains its historical “selected coefficient applied to entered interval” meaning and does not become a proof of a mean or instantaneous coefficient. The reviewable migration asks the user to identify their supplied data definition and reference temperature when unavailable; this is missing engineering input, not a new solver-method approval. New state mode rejects simultaneously consumed legacy thermal primitive and resolved temperature strain on the same member unless the former is an explicitly distinct additional imposed eigenstrain.

Per-element uniform temperature is the first implementation. Axial/cross-section gradients, anisotropy, plasticity, creep and temperature-history material laws need their own kinematics/data/recovery; one scalar average is not an automatic substitute. M16 remains open for any such promised scope. Modern primary solver documentation continues to use these reference and coefficient distinctions; a newer release does not replace compatibility/equilibrium fundamentals. [Reference scope and limitations](REFERENCES.md) distinguish verified definitions from our derivation.

## 4. Cold spring and installation (M29)

A cut-short is a mismatch of natural length and assembly geometry, not a thermal load, an equipment movement, or an arbitrary nodal force. Keep displayed assembly coordinates unchanged. For a straight member of reference assembly length `L`, explicitly input signed natural-length change `delta_L_fit` at `T_install`: negative means cut short, positive cut long, requiring `L+delta_L_fit>0`. Define `lambda_fit=1+delta_L_fit/L` and

`epsilon_star = lambda_fit * lambda(T)/lambda(T_install) - 1`.

In the present small-strain straight formulation the axial law is `Nw = E(T) A_stiffness [(u_j-u_i)/L - epsilon_star] + pressure_Poisson_term`, using the pressure profile's established ledger and physical/stress section mapping. Assemble the corresponding eigenload once; recover wall actions using that same eigenload once. The geometric natural-length conversion includes its explicit reference ratio; this does not turn the constitutive/frame approximation into an exact finite-strain rod. Record fit and thermal contributions separately plus their actual combined eigenstrain. At installation temperature the constrained cut-short is tensile, and a released end moves inward toward the shorter natural length. E changes alter forces from fixed misfit even when thermal strain is unchanged.

First product support is an explicitly named straight member or declared set with a user-provided distribution of mismatch. A whole-line cut at a weld does not uniquely determine an element-by-element intrinsic strain field; do not distribute it by equal length or simulate it by automatically moving an anchor. A joint closure with transverse/rotational fit mismatch requires a connection/assembly-stage formulation and is a linked follow-on with M07/M19, not silently approximated by axial cut-short. Save measured actual mismatch separately from an intended construction target if both are supplied; mechanics uses the selected actual input. No default percentage of theoretical thermal growth and no cold-spring code credit is added.

For purely linear elastic, small-displacement systems with unchanged topology, final equilibrium can be calculated directly from total temperature/fit/loads/supports; repeated hot/cold cases do not accumulate a new cut-short. Contact with possible multiple equilibria, friction/slip, supports installed or removed after deformation, or inelasticity requires an explicit loading/assembly history. A prior displacement used as an iteration seed is not a physical predecessor state. Do not make cold-spring operating results qualified for those cases until the needed path/state transition is implemented and checked.

## 5. Hydrotest as an explicit physical case (M21)

Hydrotest reuses the same resolved-case solve. The user supplies test temperature/material selection, pressure and closure paths, fluid density/fill condition, included insulation/attachments, gravity, and support participation/lock conditions. No test-pressure multiplier, density for “water,” locked-hanger assumption, code formula, or ambient temperature is operational data. Display missing fields before Solve rather than accepting and ignoring a hydrotest pressure record.

A pressure input becomes the same validated pressure-region input as an ordinary case, with test-source identity; it cannot simultaneously feed a legacy pressure primitive. Preserve the selected profile's topology restrictions. A uniform pressure region means the user explicitly chooses uniform static pressure; it does not mean hydrostatic head has been calculated. For a gravity column or significant elevation variation, require explicit pressure-field support (and fluid/body/closure force consistency) before claiming a hydrostatic pressure distribution. Do not automatically substitute maximum bottom pressure everywhere: that can be a stated separate bounding scenario, not the actual field or a universal conservative response. The initial bounded uniform-pressure/full-fluid capability requires zero axial gravity projection on every pressurized member (a horizontal straight region under vertical gravity), within the declared cross-section-averaged beam approximation. Nonzero axial projection with contained fluid requires the pressure-head/weight formulation successor before physical qualification; merely choosing a uniform pressure does not waive that check. Drained cases have no contained-fluid body force. Spatial head/partial fill remain planned pressure/mass successors. [The column control](HYDROSTATIC_CONTROL.md) proves why both reactions and wall/effective axial-force distributions must be checked: true cap-force imbalance already carries axial fluid weight in a wall-force formulation. Do not add that weight again; an effective-force formulation may carry it only with its matching pressure recovery and boundary transformation.

Mass state distinguishes pipe metal, contained test fluid, insulation and attachments. Full-fluid mass per length is `rho_test * A_bore_mass`; drained is explicit zero contained mass. Partial fill needs geometry/orientation/centroid and free-surface treatment where relevant; no arbitrary fill percentage alone establishes these. Section M30 owns physical bore and separate mass/stiffness/stress bases. Do not change M35's known formula while adding state input: extend its source projection and method version, and use the same pure inspector/refresh pipeline.

For each generated distributed weight keep the same explicit case/pipe/source identity and dependency hash covering the actually consumed resolved mass state, mass-section basis, density, inclusion flags and gravity. E/nu and a changed case label do not make an otherwise unchanged weight stale. A changed T only invalidates it if density/geometry selection actually consumes T. A changed pressure does not change weight unless the declared mass method consumes pressure. A new length can change total load through integration even when q and its generation receipt remain unchanged. Never carry a generated operating-fluid load into hydrotest and add full test-fluid weight on top. Modified generated values remain user-preserved manual values only after the existing explicit action; that manual state is shown and not silently regenerated.

Support states are `active`, `inactive`, or `locked` with the resolved law and explicit locked DOFs/position. A locked hanger replaces its spring/constant-effort action on those DOFs for this case; the reported total locked-support assembly action is the resulting constraint action, not that total plus a duplicated spring force. This is not necessarily the force in the internal locking pin. A real pinned hanger may retain internal spring preload; pin force and spring force then partition the total. Withhold internal pin/spring force claims unless a device-internal model supplies that partition. Other device DOFs remain as declared. Temporary supports are actual support records with case participation. A lock can use an explicitly entered position or a bound predecessor solved position. The latter requires predecessor model/state compatibility and history evidence; it must not mean zero by default. Lock release/restoration changes only that case/history step, not the global device definition. Contact/friction not replaced by a lock retains its actual nonlinear solve and history requirements.

Until these connected input/assembly/mass/support/result paths exist, retain the current hydrotest-pressure block for unsupported requests. A generic block is containment, not M21 completion. The first tranche must pass pressure + test-fluid weight + mixed locked/unlocked support witnesses together, including save/reopen and generated-load stale/refresh.

## 6. Persistent loads and solved-state algebra (M15 interface)

Physical case assembly resolves source IDs exactly once. A persistent support force/preload and a cold-spring reference strain belong to that selected device/reference state, not to every primitive case that happens to be included in a combination. `load_sources` may carry factors for truly scalable applied actions. It must not multiply temperatures, absolute support positions, density states, locks, closure topology or reference geometry by a result-combination coefficient. Resolve those as explicit state inputs. Duplicate references to the same authoritative physical source ID in a requested physical composition are reported and rejected rather than guessed as intentional doubling. Equal numeric vectors, similar names, or equal labels are not evidence of duplication: separately authored physical source IDs can legitimately contribute separately; an explicit factor is the way to request doubled scalable action.

Provide a “Solve combined physical loading” operation that materializes one reviewable case with its resolved state and source ledger, then runs the real solver. W and T are not required default categories: a user may choose these labels, and the actual source membership decides. Ordinary result sums retain the strict compatibility rules already designed; every reference/preload/eigenstrain affine term must have coherent participation. Two total states containing the same preload cannot be treated as two independent increments. A later incremental-case API can name a common baseline and prove its affine accounting; it is not needed to deliver the direct composed-load solve.

State subtraction retains both authentic solved states and their temperature/material/support/history identities. It is useful even when stiffness differs, but no equilibrium state or automatic code expansion stress follows. A stress-range evaluation must name its material/section/reference method. Do not simply rescale all forces by one E ratio, subtract unsigned maxima, or feed a componentwise envelope vector into stress recovery. An “operating support state” evaluation with contacts artificially held fixed is an explicitly constrained derivative analysis; it is not the actual sustained equilibrium and cannot silently inherit that claim.

For history-dependent support response, a continuation names an authentic prior state and ordered segments with complete target fields (or explicit deltas translated to targets). Retain physical slip/internal state, contact status and base positions separately from numerical seeds; rejected trial states are never committed as predecessors. Adaptive substeps may be used inside a prescribed path, with equilibrium/complementarity and convergence receipts, without inventing unentered material laws. Restart binds model, topology, reference, methods and consumed data. Incompatibility/stale predecessor blocks that continuation but does not invalidate other independent cases. A branch from the same predecessor makes a new path. First implementation may support history-independent linear/contact states and explicitly withhold frictional/assembly-history continuation until the support method owns those state variables.

## 7. Producer, authoring, results and persistence

One WORKING_ITEMS integration owner holds product facade/validation. Add a pure `case_state` module, per-element material selection, support-boundary compilation and a source contribution ledger; retain the current lower-level kernels. Coordinate these concrete seams:

| Surface | Required change |
|---|---|
| Product DTO/normalization/validation and pressure adapter | New tagged state input, exact consumed dimensions, support target, per-element properties, actual prescribed values, eigenstrain and pressure/mass compatibility. Never ignore new fields. |
| `linear_supports`, `frame_kernel`, nonlinear integration and source recovery | Reuse prescribed reduction/reconstruction; include nonzero constraints and original residuals. Add base-motion/preload law only where supported. History methods own and return actual internal state. |
| `product_physics/self_weight.rs`, self-weight WASM and `operation_applier` | Case mass projection/version under M35 ownership, stable IDs, old lineage preserved, before/after stale/modified validation and atomic replacement. |
| Desktop `types.ts`, load-case/material/support/pipe authoring, typed operation contracts/applier, native migration and native/headless request adapters | Complete user data editing; case resolution preview with reference/operating temperatures, coefficient definition and source membership. Enter/apply/undo/reopen without lossy DTO projection. Old unsupported imposed records become targeted diagnostics or explicit migrations, not whole-model serde errors. |
| Raw producer / semantic validator / analysis records / result export / desktop result interpretation | New versioned resolved-state evidence and classification; actual case basis remains primary. Pressure's case/region/result-ID bijection and exact per-pipe material evidence must agree with resolved state. |
| Project/analysis persistence and portable packages | Save authored data, applied source receipts, resolved consumed inputs, raw result hash, continuation state and authentic predecessor references. Historic bytes/hashes unchanged. Imported incomplete case remains editable but cannot be Current. |

Proposed additive evidence namespace `contract_evidence.load_reference_states` contains case/reference IDs, the complete normalized resolved member/support/contribution records, expansion method and interpolation/source evidence, mass receipt IDs, and history/solver method linkage. No broad new evidence framework: reuse actual model/run hash and existing pressure/exact_cases/numerical evidence, cross-check duplicated values, and bind new rows by real result IDs. ROOT must allocate a new semantic table/ID for a joined producer; frozen physics-1/source-blocks-1 meanings stay frozen. Do not qualify a case from a user-authored receipt or a display string.

Results show displacement versus reference, explicit actual support movement, signed device actions, fit/thermal contributions and state labels. These are distinct from exaggerated deformed rendering. Results preserve source and comparison state for differences. Qualified output requires actual material/geometry/mass/pressure/support/history coverage, not merely a successful serializer. All generated tables and rule inputs carry state identities; no standard code category or allowable is built in.

Case edits, reference changes, predecessor edits or changed consumed material/mass data invalidate relevant results and dependants. An unaffected case may remain valid only if an actual dependency comparison proves that fact; never clear stale flags solely because an ID matches. Save/reopen must not reconstruct a newer reference basis while displaying old results as Current.

## 8. Connected implementation slices and honest completion

1. **Prescribed motion + resolved per-element material/thermal state:** implement the new case resolver, bounded input/authoring mapping, nonzero boundary/residual/reaction path and explicit thermal-definition conversion. Reuse numerical R04 and add rotational, same-material/different-temperature and coefficient-datum controls. Carry actual state evidence through native/headless/results/save/reopen together. This gives a useful engineering capability before any general history engine.
2. **Reference strain + persistent source composition:** straight cut-short/cut-long, direct total-state solve, support preload/base reference with its owning support work, and physical combined-load case creation. Deliver cold/hot/return and duplicate-preload controls. Nonlinear history requests remain visible unsupported work until slice 4; pure elastic cold spring does not wait for every contact feature.
3. **Hydrotest mass/support state:** explicit uniform test pressure with zero axial gravity projection for full-fluid members, fluid/insulation selection and active/locked/temporary supports; M35 and M30 owners supply mass projection and section bases. Qualify mixed support pressure+weight response and stale/refresh/persistence. Add spatial head/partial-fill pressure/mass work where the requested model needs it, using the column force-distribution and no-double-counting control; do not advertise those as complete with uniform/full-fill support alone.
4. **Nonlinear state continuation:** join actual M06/M18 device-state methods and staged installation/locking, load ramps/reversal, bound predecessor persistence and recovery. Direct nonlinear total-load solves can be available before arbitrary continuation, but do not erase load-history requirements where the physical law needs them.

These are engineering dependencies and useful integration boundaries, not mandatory sequential mini-PRs. ROOT/managers may batch independent source and interface work and consolidate expensive checks. No library population or code-rule content is required. No consequential owner decision is needed to implement these selected mechanics. The user must supply missing model-specific engineering data; ambiguous old alpha records and real installation history cannot be inferred by the agent.

Complete each claimed finding only after the connected production and relevant native witnesses pass on the actual candidate. M10 is not closed by a kernel test; M16 is not closed by another case-wide temperature picker; M21 is not closed by ignoring pressure or automatically pinning hangers; M29 is not closed by a percentage label or a code credit. This design and its independent examples close none of those implementation findings themselves.
