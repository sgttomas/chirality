# Source-blocks-1 carrier proposal

Status: concrete implementation proposal for ROOT/WORKING_ITEMS review. This document does not activate a producer or consumer. The exact affine engine is owned by the core TASK; the product facade is owned by the parent. The author writes this evidence folder only.

## Selected identity and compatibility

ROOT reserves `openpipestress.result_semantics/0.3.0/source-blocks-1` under raw mechanics schema `0.2.0`, producer `open_pipe_stress_product_physics` version `0.2.0`, canonical/result/AnalysisRun/stress-neutral schema `0.3.0`. The producer version does not establish a build identity: existing actual build/input/model authentication remains required.

The frozen precision-1 table, p1 records, old source rows and legacy serializers are unchanged. Create a distinct additive source-blocks table; copy the p1 signatures without changing their identities/meanings, and add the six selected support signatures in [support_semantic_rows.json](support_semantic_rows.json). Its final full table bytes receive their own reviewed SHA-256; do not reuse p1's digest or hash this proposal as though it were that table. `physics-1` remains a separate reserved route. Source-blocks-1 does not accept a physics-1 producer or silently compose pressure/material/section/stress changes from that branch. The minimal adapter declines pressure, thermal/distributed loads, nonlinear supports, bends/user elements/releases, unsupported modifiers and combinations until the owning implementation supplies their reviewed source/recovery method.

Add one optional raw field on MechanicsEnvelope, `source_block_recovery`, omitted under p1. It is mandatory under source-blocks-1. The complete closed shape is [source_block_receipt.schema.json](source_block_receipt.schema.json). All defined object keys are required; absence differs from an explicit nullable unavailable value. All objects reject unknown keys. Arrays are ordered and resource bounded; JSON numbers must pass the existing checked I-JSON finite-number profile, safe-integer counts and additional semantic checks below. No string such as `reference_verified` makes this route eligible.

Keep the existing `numerical_quality` shape and `M03-INTEGRITY-v1` policy as the **ordinary attempt** evidence under this new contract. It must truthfully reflect a successful ordinary report, sensitivity, rejected assembly/solve or no assessment. N06 can have ordinary `unresolved` plus selected-source receipt `qualified`. Do not forge `checks_passed` or overwrite assembly-loss fidelity to represent its exact successor. Only the source-blocks dispatcher understands that distinction; p1 keeps its current gate unchanged. Each receipt case's `quality_case_index` binds the matching unique actual load-case entry in this ordinary summary.

The raw source-blocks envelope has the existing declared MechanicsEnvelope keys plus this one field. Reject additional unrecognized method/physics evidence namespaces in this bounded branch rather than accepting an unreviewed join. P1/legacy dispatch explicitly rejects `source_block_recovery` even if its producer header has been changed to p1/legacy. Existing imports that already reject unknown source semantics keep rejecting until the concrete new route is implemented.

## Receipt fields and exact meaning

The outer record has exactly `body` and `receipt_sha256`. The body has exactly:

| Field | Type / meaning |
|---|---|
| `receipt_version` | literal `1.0.0` |
| `policy` | literal `SOURCE-BLOCKS-1` |
| `status` | `qualified`, `partial`, or `unavailable`, computed from cases |
| `invocation` | closed digest descriptor: algorithm `sha256`, canonicalization `openpipestress_jcs_ijson_v1`, scope `source_blocks_invocation_v1`, lowercase digest |
| `publication_sha256` | digest of the final raw envelope with only `source_block_recovery` removed, using the domain below |
| `cases` | one ordered entry per actual requested load case, no inferred cases from output rows |
| `envelope_observation_result_ids` | exact row IDs for non-case observations only; never an escape for unaccounted physical output |

Each case has exactly `basis_ref,outcome,requested_mode,selected_method,ordinary_attempt,source,projections,rows,supports,failure,work`.

- `basis_ref` is exactly `{ref_type:"load_case",ref_id:<actual case ID>}`. `requested_mode` is exactly `dense_scrutiny` or `sparse_interactive`; it must equal the actual invocation and ordinary-attempt mode.
- `outcome` is `qualified`, `unsupported` or `failed`. `selected_method` is `retained_source_blocks_exact_v1`, `ordinary_dense_structural_v1`, or `ordinary_sparse_structural_v1` for a qualified selected response; otherwise null. Ordinary selections are explicitly ordinary and must pass every unchanged p1 case predicate. They have source=null and no exact projections/support certificate. A mode/method disagreement rejects. The record never presents ordinary values as partly exact.
- `ordinary_attempt` records `requested_mode`, `outcome` (`not_attempted/checks_passed/sensitive/rejected`), nullable actual structural-report diagnostic reference, nullable failure `{stage,diagnostic_ref}`, and the matching ordinary quality index. Its failure-stage enum is closed in the schema. A rejected attempt may have an actual partial/report diagnostic; one must never be invented. `not_attempted` has null report/failure and `not_assessed` ordinary quality. Passed/sensitive requires an actual report and no failure; rejected requires an actual failure diagnostic. Report and failure references resolve to unique current-envelope diagnostics.
- `source` is null until a complete eligible private source plan is constructed. Otherwise it records exact level `complete_identified_represented_contributions`, normalized-source and functional-plan digests, source counts, complete global free/prescribed DOF lists, positive free-block partition, ordered member IDs and support IDs. `dof_count<=256`, stiffness+force terms<=16,384 and each free block has length one or two. Free/prescribed indices are unique, disjoint, in range, and cover every DOF. Blocks partition the free map exactly, using exact source coupling. Lists/counts are producer-derived, never accepted as completeness assertions from a caller. A >2 block gives unsupported, `source:null`, and `failure.block_order>2`; the failure diagnostic retains the reached source observation. This version does not encode an inadmissible plan as an admitted source object.
- `projections` contains the actual final-unit projection certificate summaries for published affine scalar rows: unique projection/function/result IDs, quantity enum, finite value and its sixteen lowercase hex IEEE bits, unit, two ordered interval endpoints, nonnegative absolute/relative bounds, fixed relative limit 1e-9, and basis `exact_zero/exact_identity/outward_interval`. Value/bits must agree exactly. Every interval encloses its value, excludes zero for a nonzero result, and the bound/criterion/basis comes from the actual private projection. Exact zero and identity have zero bounds and point intervals. The wire does not independently prove an interval encloses the exact ratio: that construction remains source-owned and independently tested. No ratios are imported from this record.
- `rows` accounts for every case-owned published result once, with `result_id,treatment,projection_id,recipe_id,input_result_ids`. Treatment is `qualified_projection`, `checked_derived`, `ordinary_checked`, or `inspection_only`. Ordinary_checked is allowed only on an ordinary-selected qualified case, uses inherited p1 signatures, and has null projection/recipe; it is operational p1 evidence with no exact-source bound. Projection rows have exactly one matching projection, null recipe and no projected-row operands. Checked derivations have null projection, a listed recipe and real same-case input refs. Inspection rows have neither projection nor recipe; they retain actual dependencies when any exist. No unknown/extra row can be hidden by omitting it from this ledger.
- `supports` contains each actual support exactly once for an exact-selected qualified case, bound to its actual node, unique attributable source and all six distinct components. Each component names its actual result/function and source action terms (`ideal_constraint`, `ground_spring`, or `structural_zero`). This explains physical ownership; it is not a force list copied from global residuals.
- `failure` is null for qualified cases. Otherwise it is a closed `{stage,code,diagnostic_ref,block_order}` with the schema's exact enums. Block order is null except the specific unsupported-block case. Failure stage is the actual furthest relevant stage, not an invented successful source proof. `unsupported` covers method scope/attribution/closure/derived-family limits; `failed` covers invalid/mismatched source, arithmetic, budget, projection or finalization failure.
- `work` records safe integer `limit,charged,reserved_unobserved_failure` plus `rejected_reservation:{kind,amount}`. Finite reservations use a safe integer amount; overflow uses `kind:"overflow",amount:null`, not an imprecise JSON usize::MAX. Charged work never exceeds the admitted cap. An observed accepted charge remains charged after failure. A pre-reserved but unobservable legacy-constructor failure is stated separately and debited conservatively; it is not labelled actual executed work. Retain per-stage detail in the actual diagnostic/run evidence if the minimal record cannot carry it.

The schema states shape; the preceding relationships, current-source binding, predicate/projection proof and coverage require executable validators/finalization. Passing JSON Schema is not numerical qualification.

## Normalized payload scope and noncircular hash sequence

Exact private payload keys/types are in [HASH_PAYLOADS.md](HASH_PAYLOADS.md). Use the existing checked canonicalizer; never substitute Python default JSON sorting/number formatting. Every new digest is SHA-256 of checked canonical JSON for `{ "domain": <fixed ASCII scope>, "payload": <the specified JSON value> }`. The sixteen-digit operand strings encode f64::to_bits including signed zero; the outer canonicalizer's normal treatment of numeric -0 does not erase these operand identities.

1. Before parsing, privately capture `InvocationV1 = {request:<entire actual raw product request Value>,solver_mode:<actual resolved requested mode>}`. Preserve all raw request fields, member/case order, unknown keys accepted by the parser, and absent-versus-present material override fields; do not insert defaults or serialize a typed DTO to reconstruct this payload. The fixed domain is `source_blocks_invocation_v1`. No response/run receipt/hash is in this payload. Outer routes must recompute this from their independently retained actual solve request, not from the returned receipt or result rows. A model hash alone is insufficient when request material overrides or mode differ. Preserve the outer run/model/input-manifest checks; the invocation digest supplements them.
2. The source-owning adapter computes a normalized source digest with domain `source_blocks_normalized_source_v1`. Its closed private payload contains: exact source identity and actual case/material-basis selection; ordered node/DOF entity map and unit labels; original aggregate stiffness/force operand bits; complete ordered stiffness terms with owner/source ID, row, column and value bits; complete force terms with owner/source ID, DOF and value bits; ordered free and actual prescribed `(dof,value_bits)` maps; source-owned frame/local-matrix/transform/scatter, spring `(support,node,dof,k_bits,g_bits)` and supported load descriptors; explicit absent/unsupported-family decisions. Every arithmetic operand used by solve or recovery is here, including tiny source tails. No expansion/projection result or receipt digest is part of this payload.
3. Compute the functional-plan digest with domain `source_blocks_functional_plan_v1` over the exact ordered required plan: typed functional ID, global source/owner references, row/end/station/component/unit/sign description, exact coefficient product/sum operands and offset terms, publication row mapping, final-unit conversion operands, and required projection criterion. Bind the normalized-source digest in this plan payload. No projected values, row hash or receipt hash is present. The core helper supplies the exact plan/response identity; the facade must not reconstruct an equivalent-looking plan from published u.
4. Solve and recover. The private finalizer verifies full source matching, exact positive blocks, complete free equilibrium/prescribed compatibility, actual functionals, projection identities/criteria, support attribution, derived recipes and complete expected rows from the owned invocation. Create all final rows, summaries, numerical-quality/diagnostic metadata and header. No field in this pre-receipt envelope may contain the future receipt digest. Compute `publication_sha256` using domain `source_blocks_publication_v1` over that exact envelope (the complete raw MechanicsEnvelope value before adding `source_block_recovery`).
5. Build the closed body from those facts; hash it with domain `source_blocks_receipt_v1` to form `receipt_sha256`. Insert `{body,receipt_sha256}` into the raw envelope. Final source-carrier hashing, authenticated solve binding and AnalysisRun hashing then follow the existing machinery. The carrier digest includes the full receipt. The receipt does not include that final carrier digest, the AnalysisRun digest or its own digest.

These commitments bind what the actual approved producer used. This tranche retains the source and exact response privately through finalization; it does not introduce a public arbitrary-precision artifact store or promise replay after those objects are dropped. The normalized-source/plan commitments may be retained in provenance even when their private payloads are not serialized. Public consumers can recompute publication/receipt/invocation checks and validate coverage/semantics; they cannot regenerate hidden exact source ratios from hashes. State this limit expressly. An authenticated producer's finalized method evidence is trusted only under the existing source/build provenance boundary plus independent implementation qualification. Rehashing a forged JSON receipt does not create that provenance.

If a future persisted exact replay is required, it needs its own scoped retained-payload/import design. This proposal does not call digest-only history “replayed exact proof.”

## Private producer lifecycle and consumer validation

Input structs are currently Deserialize-only and deliberately do not retain original JSON. Add `run_linear_static_preview_from_value(actual_request: Value, mode: PreviewSolverMode)` as the new qualified entrypoint. A private `CapturedInvocation::parse` checks and retains the exact Value/mode, then deserializes from its retained clone. It returns the parsed request together with its unforgeable private capture to a private implementation function. Do not expose a constructor taking an already parsed DTO plus a claimed hash. Existing typed entrypoints pass no capture and preserve their historical ordinary/p1 behavior; they cannot emit an eligible source-block receipt. A separate internal arithmetic observer may inspect a stronger computation without declaring invocation qualification. Headless/native/WASM/the maintained observer must use the Value entry to claim this contract. A bridge may construct an actual request object from its own raw command arguments at the point of invocation, but it must retain that exact constructed Value and its provenance, not later reconstruct one from solved output.

Recommended Rust ownership is `PreparedSourceCase -> SolvedSourceCase -> ProjectedSourceCase -> FinalizedSourceBlockCase -> FinalizedSourceBlockReceipt`. Fields and constructors are private; constructors receive the actual borrowed/owned kernel Response, validated functional plan, same-invocation source and row builder. Successful finalize performs the full checks above before exposing Serialize or a read-only wire conversion. No Deserialize, public “passed” setter, caller-supplied proof hash, or construction from numerical_quality. A standalone ordinary failure record has its own honest path and cannot mint the finalized selected method.

The facade owns atomic case selection, output row construction and receipt finalization. Core TASK provides privately bound functional/projection accessors, row-neutral source identities and metered failures. It need not know JSON schemas, support row naming, currentness or contract IDs. Facade must retain all case finalizers until it can check model-wide expected case and row coverage, so a partial success cannot masquerade as complete.

The public validator has three results, not a boolean proof claim: supported-and-consistent record, unsupported/malformed record, or supported record whose selected numerical use is unqualified. It checks exact keys/enums, safe finite numbers, all hashes it can recompute, actual requested case/mode/invocation correspondence, unique IDs and row ownership, projection-to-row value/unit/metadata agreement, semantic signatures, source counts/maps/blocks, support attribution references, closed derivation recipes, actual ordinary-summary correspondence, and aggregate status. An independent invocation value/digest must be supplied by the actual route; no new-source positive eligibility from the existing two-argument `source,requested_case_refs` alone. Extend with a required source-block validation context, or return needs_recompute when it is absent. Keep p1's API behavior.

That validator validates the producer's structured statements and bindings; it does not infer exact arithmetic truth from labels or independently replay private ratios. Actual current-use callers additionally require their existing authenticated source/model/input/build/AnalysisRun binding. Historical raw sources retain their original bytes and are inspectable; checksum match alone remains insufficient to make an imported receipt Current.

## Aggregate, mixed cases, and derivative limits

Case order equals authored requested case order. No empty request is qualified. Aggregate is qualified iff every requested case is qualified by its explicitly selected exact or ordinary method; partial iff at least one is qualified and at least one is not; unavailable iff none is qualified. The existing ordinary numerical_quality aggregate remains independently truthful. A mixed ordinary/source run is expressed as a new source-block carrier: exact cases use the complete stronger warrant; ordinary cases use the unchanged p1 predicates and explicit ordinary method tag, with source=null, projections=[], supports=[] and ordinary_checked row accounting. This tagged ordinary selection does not inherit exact-source guarantees. A Sensitive/rejected ordinary case never qualifies by this branch. Unsupported/failed cases withhold the whole envelope. Do not silently drop cases or advertise one successful N05 as complete coverage. A no-recovery run stays on p1; a source-method attempt with no selected success may retain an unavailable source-block carrier for honest inspection. Ordinary cases retain their existing p1 row set; this tranche does not fabricate exact support-component certificates for them.

The initial method declines combinations/state differences rather than giving derived cases exact-solve standing. Keep real combination basis/source references and inspection if the facade emits them; their existence prevents whole-envelope source-block qualification until a reviewed exact composition/derived contract is implemented. No synthetic extra load-case receipt is created for a combination.

Projection guarantees cover only the listed affine quantity and the declared represented source. For a published mm displacement, multiply the exact ratio by the actual conversion operand before the final projection; converting an already projected m value does not inherit the same bound automatically. A small exact free-row residual says nothing by itself about stress, maxima or model validity.

The proposed closed derivative recipe set is intentionally small: `translation_norm_v1`, `support_force_norm_v1`, `straight_open_stress_v1`, `reviewed_stress_summary_v1`, `section_property_from_source_v1`. These names are proposed method identities, not pre-qualified algorithms. Enable a recipe only with a concrete implementation mapping, source/operand coverage, finite/range behavior, independently reviewed source and meaningful quantity checks; a wire string alone never passes finalization. `checked_derived` means the registered finite binary64 recipe actually consumed the selected source-owned inputs. It does not inherit an exact affine projection bound, correct-rounding claim or certified stress extrema. If its needed recipe is not implemented/qualified, mark the row inspection_only and withhold dependent qualified use. In particular, do not claim physics-1's new certified stress-maximum method here, and do not register a guessed generic maximum by reusing its name.

For the minimum whole-envelope gate, **any inspection_only physical output or unqualified required derived headline prevents whole-envelope Current/rule/canonical-export qualification**. Nonphysical observational rows may remain disclosed without blocking. This preserves today's all-or-nothing gates and avoids introducing a new per-row capabilities framework. The implementer can either complete the small required derived recipes or explicitly return an unqualified envelope; it cannot hide mandatory stress/reaction work by removing required rows. Stress-neutral has its own stress exclusion but must not use that exclusion to bypass the shared whole-envelope numerical gate. Later selective use needs explicit allocation, not an accidental exception.

Normal straight signed actions, standard unmodified section stresses and existing legacy force/displacement magnitudes are candidates for those bounded recipes. Nonlinear/contact/sliding results, mechanical SIF/flexibility/user modifiers, pressure/thermal composition, unsupported section transformations and arbitrary rotated coupled recovery do not become available because the receipt serializes. Their actual scope remains governed by the selected source plan; a modifier's presence must be checked, not ignored because its displayed effect happens to be zero.

## Six physical support rows

The selected ROOT interface is `CORRECTNESS_DESIGN/RAW02_INTERFACE_ALIGNMENT.md` SHA `00ef23b2cbf430309989dc63019aae3daaed331bef146cbb7a28cb4d02520450`; the supplied af412 physics interface SHA is `4da9cc53f515342a3043d32de7e83dfc4005a6bf06e51070dda0aed848974b62`. Actual read origins are in `_run_records`. Its support basis token is `recovered_from_assembled_support_law`.

For each uniquely attributable supported entity and case, emit six rows with raw `kind` (the consumer's sourceKind) `support_reaction_component_v2`, actual support `entity_ref`, and actual load-case `basis_ref`. Do not assign a pipe ID or a fabricated nodal support ID. Components are exactly Fx/Fy/Fz in N with physical/target dimension force, and Mx/My/Mz in N*m with dimension moment. All use metadata coordinate_system=`global`, location=`node`, basis=`recovered_from_assembled_support_law`. Proposed common exact sign_convention text is `support_on_pipe_positive_global_force_right_hand_couple_at_attachment_node`; this fills the existing required metadata field, adds no metadata key and does not alter the selected physical meaning.

IDs use exact length-prefixed UTF-8 case/support identities with component tokens, e.g. `result:support-component-v2:<case byte length>:<case><support byte length>:<support>:Mx`. The producer must reject any collision with existing result/diagnostic IDs. Row indices are not entity identity. Canonical and stress-neutral derivatives retain original kind/unit/component/frame/location/basis/sign as source annotations, plus carrier/row checksums and real support/load-case references.

For a scalar ground spring, action is -k*(u-g) at its actual DOF. A root free-equilibrium residual of zero does not replace it. At a prescribed DOF with an owned spring and constraint, a total support component is the sum of the separately owned ideal-constraint residual and spring device action belonging to that support. Multiple springs can be attributed by their own source laws. Duplicate/coincident ideal constraints on the same global DOF are not individually determined by the global residual; fail `support_attribution_ambiguous` instead of copying/splitting it. Do not infer an attribution rule from numeric zero.

The supports ledger preserves those source terms and IDs. `structural_zero` is allowed only for a component proven absent from this supported support's owned law; it records the real support and corresponding global DOF. It is not a placeholder for unsupported rotational/nonlinear behavior. Every emitted support component is projected from its complete signed functional. Legacy `reaction_resultant` rows retain their original translational-magnitude meaning and cannot carry torque. New six-component rows have physical category/family reaction; they are never diagnostic-work scalars or governing-ratio values. Mechanical/code adequacy, support design acceptance and nonlinear attribution remain separate.

## Review acceptance

Review should reject any positive new-source path that accepts only header/hash/status labels, lacks actual invocation/material/mode binding, omits a requested case or required functional/row, converts projected u back into cancellation-prone forces, hides ordinary failure, clones a nodal reaction onto coincident supports, drops the receipt during a derivative/history round trip, or interprets source-blocks-1 as p1/physics-1. Required actual tests include both modes on unchanged N05/N06, signed six-component mapping, spring/ideal separation, mixed/unsupported cases, old p1/history unchanged, every hash/coverage/mode/value mutation, and actual native/headless/TS/Python consumer routes. This proposal supplies no passing production receipt.

The finalized raw carrier is immutable. Later rule-check status, user review notes or history annotations belong to their existing separate records/state; they cannot patch the source-block raw envelope after publication hashing. Existing AnalysisRun rule-status overrides remain separate from the received raw source. If a route changes raw source bytes, the receipt/publication binding must fail until the owning producer regenerates them from its actual source; downstream code cannot repair this by rehashing a fabricated finalized receipt.
