## Concrete implementation recommendation

Confine the first repair to `apps/desktop/src/features/viewport/labelProjection.ts` and its maintained tests. Keep the public return type, picker, placement search, policy, DOM target, fonts, camera actions, and protected tests/limits unchanged.

1. Validate each visible primitive and derive original endpoint maximum camera depth D exactly as today. Preserve the original D≤0 skip. Compute R once as max(original radius, actual OD radius for the original pipe key, 6 CSS pixels converted at D). Never recompute eligibility or R for a subsegment.
2. Preserve the existing whole-primitive box→view-box→clipped-projector as the fallback. For the smallest conservative tranche, split only a nonzero capsule whose original un-clipped view enclosure lies strictly between the near and far planes. A zero-length capsule, an envelope touching/crossing either depth plane, or nonfinite/unsafe subdivision arithmetic uses the original enclosure. Invalid original input still throws so the caller suppresses placement. A wholly clipped original enclosure still yields no rectangle as today.
3. For eligible capsules, partition the complete start-to-end segment into exactly eight contiguous equal-parameter pieces. Use shared computed boundary points; retain the exact original first/last endpoints. Each piece receives the same R, including both end caps. Expand each piece's world AABB by (R,R,R), transform all eight corners to a view AABB, clip and project through the existing helper, retain the existing outward CSS guard and canvas intersection. Append all resulting rectangles independently. Do not replace their union with a new enclosing screen rectangle.
4. Spheres and cones retain their existing behavior and physical height/radius. Hidden keys suppress every primitive with that key. Process every supplied primitive, including repeated entity keys; never deduplicate away geometry. Actual OD is taken from the same original map/key for all pieces.
5. If an intermediate subdivision cannot be represented safely, discard that primitive's partial subdivision result and use the original envelope. Never return the partial union or an empty replacement after a failed computation. If the fallback itself is unrepresentable, preserve fail-closed throwing.

Eight is a fixed small engineering choice, not a measured optimum or a new protected acceptance limit. It is not permission for adaptive unbounded subdivision, more placement attempts, or a second fixture search. If the exact retained case remains omitted, stop and inspect that failure before changing K or scope. The current record does not claim that eight pieces already pass the browser case.

## Conservative coverage argument

For a successful ray hit on a capsule, the picker's closest point lies on the original segment. Rigid camera depth is affine along that segment, so its positive depth d cannot exceed D. The picker radius r=max(physical radius, OD, pixel tolerance(d)) therefore satisfies r≤R. Broad-phase and near/far rejection can only reduce the set of successful hits.

Let S be the original closed segment, partitioned into S1…S8. A radius-R capsule is S⊕B(R). Minkowski addition distributes over this union, so S⊕B(R)=union(Si⊕B(R)). Each subcapsule is contained in its expanded world AABB. An affine camera transform preserves containment; the AABB of the transformed box corners contains that transformed box. Thus the union of the eight camera-space boxes contains every successful picker hit, even though it removes empty corners of the single whole-primitive enclosure.

Intersecting those boxes with the positive-depth near/far slab preserves every accepted hit point. For the validated perspective matrix, screen x and y are linear-fractional coordinates with a strictly positive denominator throughout that slab. Their extrema over each axis-aligned box occur on its corners. Projecting all eight clipped corners therefore encloses its projection. Canvas clipping preserves all pointer locations the picker accepts. The original outward guard remains in force. Closed capsule joints cannot open gaps because the adjacent pieces share endpoints and both retain full radius.

The argument is mathematical containment, not a formal floating-point error proof. Shared boundary coordinates, the existing guard, finite checks, and original-envelope fallback preserve the current numerical posture; required tests must probe joins and near-tangent hits. Do not advertise arbitrary-magnitude IEEE-754 certification. Keep the original near/far-crossing fallback in this tranche to avoid introducing a new clipping/roundoff boundary while fixing ordinary diagonal over-exclusion.

The actual `pointPickPrimitives` source currently creates one straight endpoint capsule per pipe, plus sphere/cone markers. It does not expose a curved primitive. This recommendation covers that actual picker support; it must not claim to cover a different curved rendering surface. If a curve is represented by multiple supplied capsules, apply the union independently to every capsule. A future truly curved picker requires its own conservative bound and review, not a chord substitution.

## Work bound and preserved policy

For C nondegenerate eligible capsules and M other primitives, output is at most 8C+M rectangles, never 8 per entity plus an extra coarse blocker. Computing the original envelope for eligibility/fallback plus eight sub-envelopes performs at most nine constant-size envelope calculations per capsule; time/output remain O(number of primitives). No recursion or convergence loop is introduced. The collision index retains at most 256 cell references per rectangle and its existing oversized fallback. A dense query may still inspect all rectangles: this design does not promise worst-case sublinear placement. Each label retains at most 24 candidates, so conservative worst-case pick-obstacle comparisons remain bounded by 24(8C+M) per label, apart from the existing occupied-label comparisons and bounded grid traversal.

The owner's context-over-budget policy and non-overlap/containment/picking exclusions remain unchanged. All removes only the count cap; Off retains context where placement is possible; explicit Hide wins. Real spatial insufficiency continues to produce truthful omissions. No selected-geometry exception, font shrink, timeout increase, assertion relaxation, first-profile mutation, artifact alteration, benchmark/oracle change, or numeric-limit change is proposed.
