# Guidance — DEL-059-06 EPC Vendor Package Review and Acceptance

## Purpose

This deliverable provides the EPC Integrator's review-and-acceptance evidence for the vendor-engineered NGL storage bullet package (PKG-059). It is the structural counterpart to the vendor production deliverables (DEL-059-04/05) and closes the EPC anchor set (DEL-059-01/02/03) by recording that the vendor outputs satisfy the EPC basis (`_CONTEXT.md` Notes; DELIVERABLE_REGISTER row 467).

## Principles

- **EPC-owned, vendor-supported.** The EPC Integrator leads acceptance; the Package Vendor supports with submittals, test/inspection evidence, and turnover records (`_CONTEXT.md` ResponsibleParty).
- **Source-anchored acceptance.** Every acceptance finding cites its evidence in the vendor submittals or EPC basis documents; unresolved items remain TBD and are surfaced for human decision (program governance pattern; K-PROV-1 ASSUMPTION).
- **Interface integrity.** Acceptance verifies that the package integrates with the surrounding facility per the Package Datasheet interfaces and the Construction Work Package tie-in plan.
- **Spacing and siting are non-negotiable.** API 2510 distances (DBM Pressurized Bullet Spacing table) bound what is acceptable on the plot plan, irrespective of vendor preferences (`4-25_Deepcut_DBM.md` lines 245-266).
- **Acceptance != approval.** The deliverable produces an acceptance recommendation with cited evidence; binding approval authority remains with the human owner (program governance ASSUMPTION).

## Considerations

- **Plot plan dependency.** Final layout verification (R-06) depends on plot plan CIV-235633-5002, which is identified as an open external deliverable gap (`4-25_Deepcut_DBM.md` lines 237, 323). Acceptance of layout-related requirements should be held in "partial / pending plot plan" status until the governing drawing is available.
- **Bullet detailed design TBDs.** Detailed NGL bullet design parameters are not fully developed in the locally accessible product-storage basis (`4-25_Deepcut_DBM.md` line 1629). Acceptance criteria for many bullet-level attributes will originate from the Package Datasheet (DEL-059-02) once it matures; today, those criteria are TBD.
- **Source extraction gap.** The workbook-derived source (26020-Package_Requirements.docx heading 14) is referenced but not extracted into a local markdown slice (`_REFERENCES.md` Missing/Deferred References). Acceptance findings that would normally cite workbook clauses are currently `location TBD`.
- **Sibling-deliverable maturity.** DEL-059-01..05 are upstream inputs. The acceptance run cannot exceed the maturity of the basis documents and vendor submittals it consumes; partial maturity must be reflected, not hidden.
- **Spill containment vs spacing.** The DBM requires grading under the bullets to redirect spills away from pipe rack/process areas (`4-25_Deepcut_DBM.md` line 2722). This is a civil/layout interface that the acceptance review should not assume the vendor owns.

## Trade-offs

- **Breadth vs depth in review log.** A line-by-line review log is auditable but expensive; a discipline-grouped log is faster but harder to trace. The deliverable defaults to a per-document entry list (R-02) with discipline tagging as metadata.
- **Hold-until-plot-plan vs partial-accept.** The package can be partially accepted on equipment grounds while layout verification remains open. Recommended practice: track these as distinct acceptance states rather than blocking the entire package.
- **Vendor ITP vs EPC witness scope.** Maximum vendor ownership reduces EPC cost but increases reliance on vendor quality records; witness/hold-point participation increases assurance but extends schedule. The selection is TBD pending Package Datasheet (DEL-059-02) provisions.
