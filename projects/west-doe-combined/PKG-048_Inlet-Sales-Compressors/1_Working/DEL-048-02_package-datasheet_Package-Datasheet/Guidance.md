# Guidance: DEL-048-02 — PKG-048 Inlet / Sales Compressors Package Datasheet

## Purpose

This deliverable is the mandatory EPC Integrator technical handoff document for **PKG-048 Inlet / Sales Compressors**. It exists so that a third-party package vendor (and the EPC discipline engineers integrating around the package) can engineer, design, and procure the five (5) parallel multi-service inlet/sales reciprocating compressor packages on a single, source-grounded basis. It is the Gate 5 EPC anchor deliverable for this package and intentionally carries interface evidence rather than deferring it to standalone interface deliverables (`_CONTEXT.md` Notes).

## Principles

1. **Source authority over convention.** Every non-trivial datasheet value must trace to an accessible source (primary: `DBM-Deepcut/4-25_Deepcut_DBM.md` SEC-05 "Compression and Acid Gas Handling Basis"; package row in `PACKAGE_REGISTER.csv`). Generic API-618 conventions, vendor catalog norms, and engineer judgment are not substitutes for cited basis.
2. **Multi-service is the design intent.** Each of the five packages provides one sour-inlet compression stage and two sweet sales compression stages on a common frame; this arrangement is intended to balance facility loading and cap any single-package outage at approximately 20% production loss (DBM-Deepcut SEC-05). The datasheet must preserve this configuration distinctly from a conventional split inlet-/sales-compressor arrangement.
3. **Two scopes, one document.** Package Vendor scope and EPC Integrator scope are both visible in the datasheet but never merged. The datasheet records what the vendor will engineer/design/supply and the boundaries the EPC owns (PACKAGE_REGISTER.csv row PKG-048).
4. **Mark unknowns; do not invent.** Values that the DBM marks TBC carry forward as TBC. Items that depend on `26020-Package_Requirements.docx` heading 3 (not locally accessible) are marked `location TBD`. Inferences are labelled `ASSUMPTION`.
5. **DBM beats register summary on equipment basis.** Where PACKAGE_REGISTER.csv row PKG-048 summary text disagrees with DBM-Deepcut SEC-05 on engineering substance (notably the "DOL with soft-start" wording vs. DBM "starting VFD with synchronous transfer"), the DBM is authoritative under Authority Hierarchy item 1 (accessible source) and the discrepancy is recorded in the Conflict Table.
6. **Interface evidence is first-class.** The interface types in PACKAGE_REGISTER.csv row PKG-048 are carried verbatim; DBM-anchored interface counterparts (inlet/TEG HEX, amine inlet, J-T/expander upstream, sales-gas booster downstream, fuel-gas purge, VRU suction, packing drain seal pot) are recorded inline.

## Considerations

- **Sour service.** The DBM facility composition basis is sour; specific mol% H2S applicable to the inlet/sales compressor service is not isolated in the accessible DBM SEC-05 slice for this package, and the package-specific material clauses live in `26020-Package_Requirements.docx` heading 3 (`location TBD`). Until that slice is accessible, the datasheet flags sour service but does not invent metallurgy clauses.
- **Starting basis (DBM vs register).** PACKAGE_REGISTER.csv row PKG-048 describes the driver as "DOL with a soft-start," whereas DBM-Deepcut SEC-05 "Inlet / Sales Compressor Basis" requires a starting VFD with synchronous transfer to a normal-service bus. The DBM is authoritative for engineering substance; the register wording is treated as descriptive scope language only. This is logged as Conflict C-048-02-001.
- **Driver horsepower.** Current basis is 6,700 hp per package; a legacy 7,000 hp value remains unresolved in the DBM "Open Items / TBC Items" (Conflict C-048-02-002). The datasheet carries 6,700 hp as the current basis and flags the conflict.
- **Frame selection.** Current basis is Ariel KBC/6, TBC; a legacy conflicting frame reference (KBZ/6) is logged in DBM "Open Items / TBC Items" (Conflict C-048-02-003).
- **Inlet capacity disagreement.** Current basis is 62.4 MMSCFD per package / 312 MMSCFD total. Detailed pressure/capacity tables carry 60 MMSCFD / 300 MMSCFD. The datasheet carries the supported basis and the TBC alternate (Conflict C-048-02-004).
- **Sales second-stage discharge pressure.** Current basis is 1,500 psig; the detailed pressure table also carries 1,700 psig as an initial estimate (Conflict C-048-02-005).
- **No installed spare.** The 5 x 20 percent philosophy (DBM-Deepcut SEC-05) means a single package outage is approximately a 20% production loss. This is a design intent of the project basis and must not be re-characterised in the datasheet.
- **Sales-service suction pressure control.** There is no modulating suction PCV on the sales service; suction pressure is held steady upstream by the J-T valve/expander, and package loading is regulated through the inlet-service suction PCV. This coupling is a constraint on vendor controls philosophy and is recorded explicitly.
- **Recycle valve failure actions.** Currently stated as fail-open (inlet) / fail-closed (sales), with final actions TBD (Conflict C-048-02-006). The datasheet records the expectation as TBD, not as a confirmed requirement.
- **Cross-package coupling.** Upstream the inlet service receives sour gas from the inlet/TEG cross exchanger combined with 03-25 Compressor Station gas; downstream the inlet service feeds amine sweetening. The sales service receives from the turbo-expander compressor aftercooler and discharges to PKG-049 Sales Gas Booster Compressor. These are interface anchors the datasheet must surface.

## Trade-offs

- **Carry-vs-cite interface data.** Carrying interface anchors inline (DBM-cited counterparts) makes the datasheet usable as a single handoff document at Gate 5 but creates duplication risk if downstream interface deliverables (DEL-048-03 to DEL-048-06) later restate them. Mitigation: keep cited-source pointers in the datasheet so any divergence is traceable to source rather than to drafting drift.
- **TBC values now vs deferred filling.** Filling current TBC items (frame confirmation, hp confirmation, per-package inlet capacity, sales 2nd-stage discharge, scrubber and clearance-pocket selections, recycle valve failure actions, NACE/MR clauses) requires vendor input or access to `26020-Package_Requirements.docx` heading 3. Closing them now without source would violate K-PROV-1; leaving them as TBC defers risk to vendor review. The chosen trade-off is to keep TBC items explicit and flag them in the Conflict Table when they would otherwise block downstream design.
- **DBM authority vs register wording.** Adopting DBM substance (starting VFD) over register summary wording (DOL + soft-start) creates a documentary mismatch with the PACKAGE_REGISTER row. The conservative choice is to honor the accessible source (DBM) and surface the discrepancy in the Conflict Table for human ruling rather than silently overwrite either.
- **Strict deliverable-level objective mapping vs package heuristic.** The decomposition's objective-to-deliverable mapping is package-grouped, so this deliverable inherits OBJ-001 and OBJ-003 through OBJ-010 as an ASSUMPTION. A stricter mapping would either drop or pin specific objectives; absent human ruling, the conservative choice is to carry the full set with the ASSUMPTION label.
