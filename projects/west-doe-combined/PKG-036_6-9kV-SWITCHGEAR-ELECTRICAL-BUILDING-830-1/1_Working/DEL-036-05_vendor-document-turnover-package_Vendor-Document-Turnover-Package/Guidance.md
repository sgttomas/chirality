# Guidance: DEL-036-05_vendor-document-turnover-package

## Purpose

The Vendor Document Turnover Package exists so that one Package Vendor deliverable consolidates the vendor document register, vendor document submittals, any source-required vendor documentation, and turnover records for PKG-036 (6.9kV SWITCHGEAR ELECTRICAL BUILDING (830-1)), with EPC Integrator interface/integration review. It is the documentation channel that lets the EPC Integrator perform the separate package review and acceptance work (`DEL-036-06`) and ultimately integrate the vendor-engineered package (`DEL-036-04`) into the facility. (Source: `_CONTEXT.md`; `DELIVERABLE_REGISTER.csv` rows `DEL-036-04`, `DEL-036-05`, `DEL-036-06`.)

## Principles

- **Vendor authors; EPC reviews.** Vendor documentation is owned by the Package Vendor; integration review belongs to the EPC Integrator. Do not blur authorship by re-creating vendor documents inside the EPC scope. (Source: `PACKAGE_REGISTER.csv` row `PKG-036`; `DELIVERABLE_REGISTER.csv` row `DEL-036-05`.)
- **Register before submittals.** A vendor document register defines the document set the vendor will submit before submittals begin to land; the register is the control surface against which submittals are tracked. (Source: `_CONTEXT.md` anticipated artifacts; `_Sources/DBM-Comp_and_Liquids/3-25_Comp_and_Liquids_DBM.md` line 617.)
- **Source rows are evidence, not new deliverables.** Where source material exposes specific vendor document table rows for this package, they are carried as artifacts/evidence inside this deliverable rather than minted as separate deliverables. (Source: `_CONTEXT.md` notes; `DELIVERABLE_REGISTER.csv` row `DEL-036-05` notes.)
- **Interface coverage matters.** The register and submittals should provide the package-side data needed for all twelve declared PKG-036 interfaces. Missing interface data is a turnover gap, not a vendor preference. (Source: `PACKAGE_REGISTER.csv` row `PKG-036`; `INTERFACE_REGISTER.csv` rows for PKG-036.)
- **Source-anchored MV-electrical content.** Where the DBM does specify substantive medium-voltage requirements that bear on the vendor documentation set (6.9 kV system characteristics, neutral grounding resistor sizing, MCC PLC interface), those facts must be reflected in the submitted documents rather than left as generic. (Source: `_Sources/DBM-Deepcut/4-25_Deepcut_DBM.md` lines 2935, 2955, 2985.)
- **Turnover is the closeout, not a backlog.** Turnover records consolidate certified data, tests, and handoff documentation; missing items at turnover become punch items against EPC acceptance (`DEL-036-06`). (Source: `_CONTEXT.md`; `ARTIFACT_REGISTER.csv` `ART-8F50EF826E`.)

## Considerations

- **Source gap for package-specific requirements.** The Gate 7 artifact register explicitly flags this deliverable as a "Vendor Documentation Gap Evidence" item: detailed vendor-document requirements are not present in current source material for PKG-036. The register and submittal scope therefore start from the general package-deliverables expectation and require source closure before they can be finalized. (Source: `ARTIFACT_REGISTER.csv` `ART-462B18445D`.)
- **Cross-discipline application of the package-deliverables paragraph.** The locally accessible package-deliverables paragraph addresses mechanical packages. Using it to scope an electrical-building vendor document set is directional rather than literal; electrical-building-specific items (switchgear factory acceptance test records, breaker calibration records, relay settings, arc-flash labels, building envelope/HVAC commissioning, UPS battery sizing/test records) are not enumerated by the accessible source. (Source: `_Sources/DBM-Comp_and_Liquids/3-25_Comp_and_Liquids_DBM.md` line 617.)
- **Building identity discrepancy (830-1).** The workbook names the package `6.9kV SWITCHGEAR ELECTRICAL BUILDING (830-1)`, while the DBM building list (`_Sources/DBM-Deepcut/4-25_Deepcut_DBM.md` lines 2811-2813) names 830-1 as `4.16kV Acid Gas / Overheads Compressor Electrical Building` and lists the 6.9 kV electrical building as 820-1. This bears on which DBM electrical-system content actually applies and is carried as a Conflict Table item.
- **Twelve declared interfaces.** PKG-036 carries twelve declared interface types (Utility Piping; Drain / Containment; Electrical Power; Grounding / Bonding; Area / Exterior Lighting; I&C / Control Cabling; Communications / Network; Building HVAC / Services; Fire & Gas / Safety Systems; Maintenance Access; Grading / Site Drainage / Spill Containment; Structural / Foundations / Supports). The vendor document register must provide an explicit row or TBD for each. (Source: `PACKAGE_REGISTER.csv` row `PKG-036`; `INTERFACE_REGISTER.csv` rows.)
- **No declared dependencies.** `_DEPENDENCIES.md` carries no declared upstream or downstream edges. The substantive coupling to `DEL-036-04` (vendor-engineered equipment package) and `DEL-036-06` (EPC review and acceptance) is real and should be declared if/when `TASK + dependency-extract` is run. (Source: `_DEPENDENCIES.md`; `DELIVERABLE_REGISTER.csv`.)
- **No package-specific RFQ row found.** `PACKAGE_REGISTER.csv` for PKG-036 does not point at a discoverable `26020-..._RFQ_...docx` row. Vendor documentation requirements that would normally appear in an RFQ/Bid Doc are therefore not available for grounding. (Source: `PACKAGE_REGISTER.csv` row `PKG-036`.)
- **Objective association is PACKAGE_HEURISTIC.** Objectives `OBJ-001`, `OBJ-004`, `OBJ-005`, `OBJ-006`, `OBJ-007`, `OBJ-008`, `OBJ-009`, `OBJ-010` are carried from the package row and should be treated as directional context, not as binding requirements at the deliverable level, until human-confirmed. (Source: `_CONTEXT.md`; `OBJECTIVE_DELIVERABLE_MAP.csv`.)

## Trade-offs

- **Drafting now vs. waiting for source closure.** Drafting the register and submittal list before vendor scope is firm risks rework; waiting risks holding up EPC review readiness. Bias is to draft the structure now (register fields, interface coverage map, turnover checklist skeleton) and mark content TBD where source-grounded detail is unavailable.
- **Generic vs. MV-switchgear-specific document list.** A generic list satisfies the structural requirement but misses MV-switchgear-specific evidence (FAT, breaker timing, relay coordination/settings, ground-bus continuity, arc-flash study inputs). Accept generic coverage with explicit MV-switchgear-specific TBDs rather than inventing a list without source.
- **Carrying source rows as artifacts vs. promoting them.** Promoting source rows to deliverables would inflate the WBS and break the convention captured in the deliverable register; keep them as artifacts within this deliverable.
