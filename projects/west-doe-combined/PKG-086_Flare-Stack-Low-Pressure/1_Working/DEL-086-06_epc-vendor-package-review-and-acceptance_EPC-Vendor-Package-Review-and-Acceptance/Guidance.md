# Guidance: DEL-086-06 — EPC Vendor Package Review and Acceptance

## Purpose

This deliverable is the EPC Integrator's evidence that the Flare Stack (Low Pressure) vendor package has been reviewed against the EPC basis (Scope of Work, Package Datasheet, Construction Work Package), that integration concerns are resolved, and that the package is ready for handoff. It exists so that downstream construction and turnover can proceed with documented confidence rather than implicit trust in the vendor.

Source: DELIVERABLE_REGISTER.csv row DEL-086-06 (Description and Notes).

## Principles

- **EPC Integrator is the acceptance authority.** Vendor input is consulted, but acceptance disposition is owned by the EPC Integrator (per `_CONTEXT.md` ResponsibleParty).
- **Acceptance is basis-anchored.** Every acceptance judgement traces to an EPC basis document item (DEL-086-01, DEL-086-02, or DEL-086-03). Acceptance not anchored to a basis item is not acceptance.
- **Evidence beats assertion.** Review log, checklist, and test/inspection records are the deliverable. Verbal acceptance or unsourced sign-off does not satisfy this deliverable.
- **Integration is the differentiator.** This deliverable is not a vendor self-review; it specifically asks whether the package works with the rest of the facility (interfaces, tie-ins, handoff to DEL-086-03 construction).

## Considerations

- The deliverable depends on DEL-086-04 and DEL-086-05 being available and at sufficient maturity. If they are not, review can begin but acceptance cannot conclude.
- The Package Datasheet (DEL-086-02) defines the technical envelope used to judge acceptance. Drift between actual vendor package and the datasheet should be raised as either a datasheet change request or a non-conformance — not silently absorbed.
- Construction Work Package (DEL-086-03) defines installation, tie-in, turnover expectations. Acceptance should confirm the vendor package supports those expectations (e.g., turnover document set, tagging, witness points).

## Trade-offs

- **Review depth vs. schedule.** Deeper review reduces field risk but extends acceptance cycles. The review-depth profile should be calibrated to risk class of the flare stack package (high-consequence safety system).
- **Conditional acceptance vs. blocking.** Some non-conformances may permit conditional acceptance with tracked closure; others block. Establishing the threshold in advance prevents ad-hoc disposition.
- **Vendor self-attestation vs. EPC re-verification.** Reliance on vendor QA records is faster; independent EPC re-verification is more defensible. Mix by risk.
