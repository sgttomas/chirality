# Guidance: DEL-074-06_epc-vendor-package-review-and-acceptance

## Purpose

Explain how the EPC Integrator should perform vendor package review and acceptance for `PKG-074` (Caustic Treating — NGL Mercaptan Removal) without overstating what the accessible source set actually authorizes, and how to record acceptance evidence that downstream activities (construction handover, commissioning, turnover to operations) can rely upon.

## Principles

- **Authority hierarchy is upstream-fixed.** The accepted EPC Scope of Work (`DEL-074-01`), the `DEL-074-02` Package Datasheet, and the `DEL-074-03` Construction Work Package are the acceptance basis. The vendor package is the subject of review, not its own authority.
- **Responsibility split is non-negotiable.** Per `PACKAGE_REGISTER.csv` row `PKG-074`, the Package Vendor owns package engineering, package design, vendor documentation, and the physical equipment package; the EPC Integrator owns integration into the functional process facility (interfaces, tie-ins, constructability, procurement/construction coordination, facility-level integration). Review comments shall not redesign the vendor package or accept vendor scope drift into EPC scope.
- **Source gaps are not silently filled.** Where the EPC Scope of Work, Construction Work Package, or vendor data is not accessible at acceptance-criteria fidelity, the acceptance criteria are recorded as `TBD` with the missing reference noted — not invented.
- **Interface evidence is the minimum acceptance unit.** Each of the thirteen declared package interfaces (Process Piping; Utility Piping; Relief / Flare / Vent; Drain / Containment; Electrical Power; EHT; Grounding / Bonding; Area / Exterior Lighting; I&C / Control Cabling; Building HVAC / Services; Fire & Gas / Safety Systems; Maintenance Access; Structural / Foundations / Supports) must have an explicit disposition before acceptance is asserted.
- **Status discipline.** This deliverable updates only its own `_STATUS.md` (safe rule). It does not change the Package Datasheet's status or any other deliverable's metadata.

## Considerations

- The accessible source set in `_REFERENCES.md` is a decomposition basis, not a vendor data package. Reviewers should expect the bulk of acceptance criteria to depend on the EPC SoW and the accepted Package Datasheet (`DEL-074-02`) rather than the DBM or budgetary go-by.
- Caustic-treating package vendors typically offer process variants (e.g., extraction-only, fixed-bed, or regenerative configurations including Merox-type schemes with disulfide oxidation and separation). The choice of variant materially changes equipment list, utility demands, relief disposition, and acceptance test scope. Reviewers should record which variant the vendor proposed and confirm it is consistent with the EPC SoW; do not presume a variant in the acceptance criteria.
- Caustic service introduces specific materials and fabrication considerations (caustic-stress-corrosion-cracking risk, post-weld heat treatment thresholds for caustic-contacting components, materials selection for valves, gaskets, and instrumentation wetted parts). Reviewers should confirm vendor materials selection evidence rather than presuming compliance.
- The package is sited immediately downstream of the deethanizer, which constrains feed composition, pressure/temperature envelope, and the interface points to upstream and downstream NGL handling. Reviewers should confirm vendor design conditions match the EPC SoW battery-limit data sheet rather than presuming envelope.
- Vendor documentation is typically delivered in revisions. The review log should record vendor revision and reviewer disposition for each cycle, not just the latest.
- Relief device sizing and disposition (to the facility relief/flare or local atmospheric vent per the project relief philosophy) are commonly contested across the vendor/EPC boundary. Reviewers should confirm the EPC SoW relief philosophy and check vendor relief calculations against it.
- Hazardous-area classification depends on facility-level zoning that may extend across the package boundary. Reviewers should confirm consistency between vendor classification drawings and the facility hazardous-area drawings rather than accepting the vendor classification in isolation.
- Test/inspection categories (FAT, SAT, pressure/leak test, NDE, instrument loop check, PSV verification, hazardous-area equipment certification verification, caustic-service materials compatibility evidence, treating-performance test when required) are reasonable expectations for a vendor-supplied caustic-treating package, but the specific acceptance criteria belong to the EPC SoW and the Package Datasheet; reviewers should not assert acceptance criteria that are not source-supported.
- Turnover categories (mechanical-complete, pre-commissioning, commissioning-readiness, handover-to-operations) align with typical EPC construction workflow, but the authoritative gates belong to the Construction Work Package (`DEL-074-03`); until that document is accessible at acceptance-criteria fidelity the categories serve as placeholders.

## Trade-offs

- **Accept partial vs. hold for completeness.** Where vendor documentation is partial, EPC Integrator may accept-with-comments and carry an explicit punch list rather than rejecting wholesale; the trade-off is schedule continuity vs. acceptance-evidence completeness. Either choice must be recorded in the review log.
- **Re-test vs. accept by analysis.** Where FAT/SAT cannot be re-performed on site, acceptance by certified vendor records and on-site inspection is acceptable when the EPC SoW permits; otherwise the item remains `TBD` and is surfaced for human ruling.
- **Strict interface verification vs. construction sequencing.** Strict verification of all thirteen package interfaces before commissioning protects integration integrity; deferring some verification (typically EHT energization, fire & gas integration, and final loop checks) to commissioning may be necessary for sequencing reasons but must be explicit, not implicit.
- **Vendor performance guarantee scope.** Where the EPC SoW assigns a treating-performance guarantee to the vendor, acceptance depends on a performance test using feed within the contractual envelope. Reviewers should confirm the envelope rather than allowing a performance test under non-representative conditions; deferring the performance test to start-up is acceptable only if explicit in the EPC SoW.
