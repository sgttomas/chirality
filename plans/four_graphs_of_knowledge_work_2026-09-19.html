Four graphs, one node

The stable structures under knowledge work, as they appear in the Chirality repository.

The owner's sketch draws one node, marked 1, four ways. Each drawing answers a different question about the same piece of work, and each has its own home.

  • Tree: what is it made of?
  • Directed acyclic graph: what must come before what?
  • Network: what bears on what?
  • Many-to-one crossing: how does it all become one thing?

The claim is that these are invariants of knowledge work as such: composition, precedence, relevance and synthesis. None reduces to another.

The next four pages take them one at a time: the question, where it lives in this repository, and what happens when it is missing. The last page puts them back together.

Basis: the owner's hand sketch and one working session (the SWBPIPE interface implementation, 2026-09-19). Observations are one agent's experience of one project, not a survey of the repository.

Structure and working memory

What is this made of?

A tree. The undertaking decomposes into packages, deliverables and final nodes. Every final node carries the same kit, so an agent that arrives there becomes focused on that node and nothing else.

In the repository

  • execution/PKG-*/1_Working/DEL-*/ with _STATUS.md, _CONTEXT.md, _REFERENCES.md, ScopeOfWork.md, _SEMANTIC_LENSING.md, _REVIEW.md, _DEPENDENCIES.md, MEMORY.md.
  • The decomposition itself: _Decomposition/SOFTWARE_DECOMP.md.
  • Home: git. The tree is the folder tree.

When it is violated

Leaves get used as a log. In this session, run records and status lines were appended to two deliverables chosen by precedent and folder name, without reading their scope. Evidence filed by guess has to be found and re-filed later.

Production and dependencies

What must come before what?

A directed acyclic graph. Work starts in waves and converges on a final node. It is read two ways, by two roles.

  • The blocker subset is sequencing truth. Whoever acts next needs only what blocks.
  • Full closure is audit truth. Whoever is accountable needs every node, edge and hash to close.

In the repository

  • The session work graph: AgentRuns/<RUN_ID>/WORK_GRAPH.json, with dependsOn and blockedBy for the first reading, commits and hashes for the second.
  • The project DAG: the snapshot named by execution/_DAG/_LATEST.md, rebuilt per phase at the owner's direction.
  • Home: git worktrees, one per concurrent line of work, converging on main.

When it is violated

State drifts into prose. The run's graph went stale for a day while handoffs carried the state; the owner had to ask for it to be rebuilt.

Topic query and long-term memory

What bears on what?

A network. Hubs of cross-cutting knowledge link to each other and to many final nodes at once. A decision touches six deliverables; a constraint touches every slice. A tree or a DAG can only hold that by duplication.

The edges that matter most are provenance: who decided this, when, and what it supersedes.

In the repository

  • Decision rows and rulings (DEC-102, D-72), gaps (G-11), the handoff's constraints, owner-direction records with verbatim words and hashes.
  • Home today: files and search. Intended: a graph or relational store.

When it is violated

An agent's inference is recorded as the owner's direction and the next agent obeys it. This happened three times in two handoffs and survived audits that verified every hash. Facts were checkable; provenance was not queryable. This is the only quadrant still emulated by hand, and it is where the compounding errors occurred.

Attention and decomposition

How does all of this become one thing?

A many-to-one crossing. Every input is read against every other until a root and its levels emerge. This is synthesis, not lookup, and it is the step a model does natively.

In the repository

  • The design program: a 313-row operations map became 34 classed gaps and three tranches.
  • A lane manager read a 4,000-line component and cut one slice into two stages with named tests.
  • Seven loose open items became eight decisions the owner could take in one line.
  • Home: LLM + files + tools + instructions. Workflows such as software-decomp and project-decomp package it.

When it is violated

It was the one structure that did not fail in this session. Its risk is quieter: a decomposition made without querying long-term memory first repeats old decisions or contradicts them.

How the four work together

One cycle, with one edge cut on purpose.

Decomposition produces the tree. The tree's dependencies seed the production graph. Production generates evidence and decisions, which belong in memory. Memory is what the next decomposition should query first.

On 2026-09-19 the owner cut one edge deliberately: production runs ahead of the structure tree, driven by the code. A later reconciliation re-runs decomposition to rebuild the tree from what production made. The work graph's provisional deliverable bindings are the dangling edges that pass will resolve.

Why this reads as invariant and not as a filing scheme

Each failure traced back to exactly one quadrant, with a distinctive symptom. When the owner loosened the prescribed process, the structures still held, because they belong to the work and not to the procedure.

What follows

  • Show agents this picture at entry. One agent followed a one-graph mental model for most of a day.
  • Give long-term memory a native home, starting with provenance: decisions, directions, who said them, what supersedes what.
  • Test the claim outside software: the same four shapes, and the same failure signatures, in a proposal, an investigation or a calculation package.

The measure

The quality of the system is how much warranted confidence it produces per unit of the owner's attention, and the toggle sets how much of that confidence a given piece of work needs.

Agreed with the owner in session, 2026-09-19. It evaluates as well as summarizes: every rule, record and gate can be asked what confidence it produces and whose attention it costs. Machine-checkable validation (closure, hashes, protected tests) is nearly free and stays on; what speed actually trades against is the owner's understanding, so the design goal is more understanding per minute, not a higher level of abstraction.

  • The level is set per node, by consequence and reversibility. It is never lowered by the agent doing the work; that is the owner's decision or a rule the owner wrote.
  • The acceptance records the level at which the work was validated, so a stamp carries its own warrant.
  • A floor does not toggle: protected criteria, provenance and the claims fence.
