ACCEPT WITH REQUIRED CHANGES

Revision 3 can be the first implementation candidate. No fourth revision is needed — a bounded erratum is. All three reviewers reached this independently. The architecture (launchd-owned supervisor, root-bound workers, hard outer envelope), the gate structure (G0.25/G0.5 plus the feasibility and authority proofs), and the owner rulings are sound and honestly stated as intent rather than authority. Fifteen of twenty round-2 findings are applied faithfully; the five owner amendments are each defensible against the repository, and one (keeping F-APP-2 untouched through preparation) is better grounded than the round-2 recommendation it answers. There is no P0 in the governance or contract review, and no unsupported repository claim in §4–§8 or the appendices.

What remains are contradictions inside text that the gates would later test — so they cannot be carried as gate conditions, because a brief sealed against them would have ambiguous acceptance checks — plus a handful of upstream facts the plan did not have. They amount to a few paragraphs across §4.2, §6.2, §6.4, §8.2, §8.5, Appendix A, B.1, and three gate rows. That is the erratum below, to land before SCA-004 and SCA-APP-008 are drafted.

3Does G-ROLE preserve untyped/Agent 0/Agent 1 latitude while mechanically preventing Agent 2/TASK delegation without an invented App Server control?

The intent is right; the mechanism needs two corrections. Upstream has no per-thread or per-turn way to disable spawning (per-turn overrides are a closed list); it is a config-layer control only, so the isolated role-specific worker with its own CODEX_HOME is the right shape. But features.multi_agent_v2 — present in the 0.149.0 schema, absent from public docs — takes precedence over [agents] enabled, so the Agent 2 profile must set features.multi_agent = false as well as [agents] enabled = false. And Appendix A's acquire() already takes rolePosture unconditionally while §4.2 defers role-keyed workers to G-ROLE. Add the owner pre-decision for G-ROLE failure at G0, since §5.3 forbids both weakening Agent 2 and globally disabling native delegation and pre-decides no fallback (R3-04, R3-08).

4Can the second LaunchAgent supervisor, root-bound workers, daemon re-attachment, and active-turn continuity be implemented and packaged safely?

Supervisor and workers: yes, with the host and installer named. Re-attach with continuity: not as written. The non-Chromium host already exists in the repository — Electron under ELECTRON_RUN_AS_NODE=1 (electron/cli-launcher.ts:57) — and no packaged Node binary does; the LaunchAgent renderer hard-codes [exe, --runtime-daemon] (runtime/packages/cli/src/launch-agent.ts:250–254) and needs amending; the install actor for a second job is unnamed. "Peer-UID verification" has no Node API and no addon in the repo; the daemon's own pattern (0700 dir, 0600 socket, owner record with uid, rotated bearer token — runtime-daemon.ts:113–120,171, auth-registry.ts:57–74) is the implementable equivalent. Continuity: turn state is in-memory only (turn-coordinator.ts:71); the daemon's force path returns the SSE iterator, skipping the generator's catch, so no terminal is persisted; there is no attach route; and AT-036 ("fresh threads after restart") contradicts §4.2/AT-048 (R3-01, R3-05, R3-06).

5Do Root API v2, event schema v2, approval fallback, consent, protected paths, environment, and exact-pin assumptions fail closed at every boundary?

Mostly, with one upstream fact that breaks a stated boundary. includePlatformDefaults is not read-only: the Seatbelt profile it appends grants file-write* to /tmp, /private/tmp, /var/tmp, /private/var/tmp after the write policy, so B.1's exclude_slash_tmp = true is cancelled by the includePlatformDefaults: true sent every turn (R3-02). The sibling terminal fan-out that G-SIG tests has no mechanism: the coordinator throws on any event from another session (turn-coordinator.ts:181–191) and interrupt() writes no terminal (R3-03). Consent's per-turn enforcement point has no seat in the coordinator or bootSession today and is missing from §8.5's breaking list; the cwd-rejection limb is cheap and real (session-store.ts:108–110) but a per-turn cwd override upstream is sticky, so client-side rejection is the only control (R3-09). Sentinels run via command/exec, which carries its own policy — proving that call's containment, not turn/start's (R3-10). Everything else — restricted read envelopes, sourceKinds, thread.sessionId, config/read, configRequirements/read, managed-requirements sources being admin/MDM only, email: null, destination-grouped network prompts, thread/shellCommand and process/* running outside the sandbox — is confirmed.

The erratum: what revision 3.1 must change

In priority order. Items 1–7 change what the SCA-004 / SCA-APP-008 assessments must cover and should land before those are drafted; 8–9 may ride along.

  1. Reconcile includePlatformDefaults with the temporary-root exclusion (§6.2, §6.3, B.1, B.2, G-SENT). Either drop includePlatformDefaults and inventory the platform reads Chirality actually needs, or state that /tmp family writes are granted by the platform profile and make G-SENT's /tmp canary the proof that they are not. The two cannot both stand as written.
  2. Choose one restart semantic (§4.2, §6.4, AT-036, AT-048): terminal-on-retirement (today's behaviour, with a persisted terminal on the force path) or persisted turn state plus a new attach route. Write the AT for the chosen one and delete the other.
  3. Name the coordinator change for sibling terminalization (§6.4, §8.5, G-SIG): a coordinator-level API that can write a terminal for a session whose generator is not being pulled, and the failure mode when it cannot.
  4. Fix the G-ROLE mechanism (§5.2, §5.3, B.1, B.2, Appendix A): config-layer only; features.multi_agent = false in the Agent 2 profile in addition to [agents] enabled = false, with multi_agent_v2 precedence recorded; make rolePosture optional in acquire() or delete "by default" in §4.2; define closeProject(projectId) against root keying; state how N CODEX_HOMEs share one signed-in account; add the G0 owner pre-decision for G-ROLE failure.
  5. Name the supervisor host, installer, and socket authentication (§4.2, §4.3, WP-03, G-HELPER): Electron under ELECTRON_RUN_AS_NODE with a new supervisor entry in the CLI bundle; the @chirality/runtime-cli LaunchAgent-renderer amendment and proof-script re-authoring as WP-03 outputs; the first-run install actor for two jobs; replace "peer-UID verification" with the daemon's 0700/0600 + owner-record + rotated-token pattern (or make a native addon a deliverable with its signing consequence).
  6. G-KEY must name safeStorage (§7.2, B.2, G-KEY, AT-051) with a distinguishable typed decrypt-failure state, and add a preparation-lane self-signed A→B dry run so a G-KEY failure is not first discovered on notarized bytes.
  7. Close the instrument gaps (§5.3, §8.2, §9): add K-CONTROL-1 (a second control socket) and K-ROLE-2 (role-keyed workers) rows; name subagent-governance.ts:205–213 as a WP-06 change and the DEL-02-03 text change for untyped; seat release-procedure authoring on a carrier; consent port in §8.5.
  8. Upstream corrections (§5.4, §5.5, §7.1, Appendix B, B.1): account/read discriminates on type, not authMode (that field belongs to account/updated); a per-turn cwd override becomes the thread default for later turns; thread/shellCommand has no capability gate (client filtering only) while process/* is closed by not enabling experimentalApi; do not assert per-thread scope for network-prompt grouping, and note port is absent from networkApprovalContext though it participates in grouping; network_access = false is already the default; configRequirements/read returns null on unmanaged machines.
  9. Minor: port isAuthorizedSender to the six credential IPC channels before any second view exists and wire the per-window egress policy to it (G-CSP); add G-KEY to the §10.0 map and G-ENV/G-CSP/G-KEY to Figure 2; dispose turn.cancelled in schema v2; map RQG §13 Shared Runtime Gate; cite PRD_ROOT D-1 beside D-8; rename "supervisor" or note the existing RuntimeBindingSupervisor; restate DEL-02-06's limit as REQ-027 and its exclusion block rather than "an M-sized envelope"; name D-APP-103 as an interacting open item on DEL-08-04.
